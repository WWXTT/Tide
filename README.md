# Tide 设计文稿

## 设计核心：三条核心规则（效果与配卡的制作总纲）

### 规则一：平衡（卡牌层）—— 费用与效果一致
一切效果由原子效果组装，费用由原子基准自动推导，正向和负向费用一致，全部效果锚定基准原子费用


### 规则二：变化（对局层）—— 时间与收益
地牌上限  [1-9]线性增加  效果需要的费用线性降低 理论依据是造成1点伤害，在第一回合和第十回合有非常大的差别，卡组完全展开后组合效果会让线性费用贬值


## 优势维度：六轴细化
非对称优势细分为**信息、生存、规则、节奏、场面、资源**六轴，指导卡牌设计——每个卡组有自己的优势来源。

### 一、生存轴
生命值的特殊性：**单向消耗**（通常只减不增，除非有恢复效果）、**直接关联败北**（归零即输，直接对抗对手的胜利推进）、**非线性价值**（30→20 与 10→0 的紧迫感完全不同——生存轴的价值在于把对手拖入自己擅长的长盘）。
治愈卡组的玩法循环：承受伤害 → 恢复/抵消 → 等待对手资源耗尽或自己达成胜利条件

### 二、资源轴
生命剥离后，资源轴专注**手牌、元素、卡组、墓地**等可循环/可再生资源。资源轴卡组不关心自己有多少血，只关心有多少牌和费

### 三、节奏轴
决定**游戏进程的主动权在谁手里**（而非手牌或生物数量优势），如冻结沉默等针对生物的阻拦，摧毁反制等打断对手关键key牌。

### 四、规则轴
双方受益，但是自己能凭借对卡组的特化获得优势，如双方都不再执行准备阶段
（规则轴载体曾以"仪式（竞速任务卡）"实现，2026-09-30 已整体移除，新载体重新设计中——引擎侧通用扩展点 RuleHooks/ReplacementEngine/ITurnStartInterceptor 保留可用）

### 五、信息轴
通过观察揭示对方隐藏信息获得决策优势，但是为了让这种优势更明显，将加入一些预言类的效果。
- **展示（2026-10-02 定案）**：展示原子（RevealCard，域=己/对方手牌·牌库）为目标挂「展示」指示物（Exposed）——
  持续暴露、双方可点击对应区域查看；**换区即失效**（UntilLeaveBattlefield）。网络侧：快照 `RevealedZoneCards`
  恒全量下发 + 事件流隐藏集豁免。展示指示物可作筛选条件（TargetFilter `Exposed`），是后续
  「被展示的卡本回合不可使用 / 送入墓地 / 以被展示为限制条件换费用减免」类设计的挂点。
- **诅咒（2026-10-02 定案；2026-10-05 有限分支定案改载荷）**：诅咒原子（AddCurse）为对手的卡附加「诅咒」指示物
  （Permanent——活过牌库→手牌的换区清除）；**对手抽到该卡时自动执行诅咒载荷的分支效果并消层（一次性）**，
  由 CurseSystem 在 CardDrawEvent 时点驱动。载荷两形态：①**inline**——槽级 Branch 载荷（有限分支 Gate 特例
  `CurseOnDraw`，时机固定"抽到该卡时"、施放时恒假不结算；Then=专属载荷原子，≤2 费预算，converter 折入 AddCurse
  主干原子）；②str=Effects.json 条目 id（手写数据兼容）。以施诅方为控制者结算（载荷内相对域的「敌方」=被诅玩家）。

### 六、场面轴
通过赋予生物和结界各种抗性效果和增益效果，达到场面优势，通过战斗消减生命。

## 游戏规则

### 区域分布
- 游戏以正六变形铺满场地，每个玩家分别具有 角色*1 技能*1 卡组*1 墓地*1 除外区*1 发动区*1  场上单位放置区域*2*9 地牌*9
 卡的使用 先进发动区 → 发动 → 代价/费用通过 → 未被反制 → 进入战场。

### 发动时机（定案）
- 已在战场的卡，其被动效果的发动时机在描述中自带，主动效果双方的主要阶段都能释放（基于速度）。
- 回合开始的**准备阶段**与**结束阶段**为系统自动结算阶段，包含场上卡的结算：逐一按入场顺序结算标记在准备/结束阶段的效果。

### 费用体系 （代价系统）
- 红蓝绿灰四色元素是最基本的代价，卡牌的使用，效果的发动都需要支付代价；黑白为扩展。
- **颜色定位（2026-09-21 钉死）：红=快攻，蓝=控制，绿=慢速**——三原色各对应一种套牌节奏（伤害→红、抽牌/反制→蓝、回复→绿），灰为通用/难分类，黑白为万用扩展色。六轴优势（信息/生存/规则/节奏/场面/资源）与颜色共同指导卡组设计。
- 地牌放置是**主阶段**行为：玩家在主阶段将手牌以未横置状态作为地牌放入元素池，不限张数/次数，张数由地牌槽上限约束（min(全局回合数, 9)），
放入当回合即可横置产出。基于该卡的费用构成放置对应数量的元素指示物，横置去除一个指示物，玩家获得对应元素，指示物消耗完毕后会直接进入墓地
- **上限语义（钉死）**：地牌槽上限管的是**场上同时存在的地牌张数**；地牌横置产出的元素进 bank，跨回合**无上限**积累。
- **浓度上限（2026-09-14 统一混付）**：每种**货币**（红/蓝/绿/黑/白/灰）单次支付总贡献 ≤ 当场地牌槽上限；纯色**需求量** > 上限时不论货币直接不可付。例：攒了 3 个火元素但地牌上限才 2，就不能支付"3 纯火"费用的卡（灰/黑白垫 3 也一样拒）。执行件：**统一账单规划器 `ElementPaymentValidator.GetBillPaymentPlan`**——出牌（`ElementPool.CanPayCost/PayCost`）与效果费（`ElementCostPayment`）共用同一算法，支付序 **同色 → 灰 → 黑 → 白**（黑白=万用色垫四色缺口）；支付事件 `ElementPoolPayEvent.PaidCost` 携带**实际货币组合**（Trinity 光环/台账按真实货币计数）。
- 准备阶段为纯自动阶段（横置恢复、抽牌等由 `TurnStartEvent` 消费者完成），无玩家操作。**回合推进口径（2026-09-24 定案）：准备阶段完成即自动进入主阶段（`TurnEngine.StartNewTurn` 内 `AdvanceFromStandby`——原"停等玩家 `IntentSkipStandby`"口径废除，跳过准备阶段改走 `ITurnStartInterceptor` 声明）；主阶段 → 结束阶段仅由玩家手动结束回合（`IntentEndTurn`；操作超时属 M4 健壮性）驱动，任何驱动器不得自由滑相位**。
- 红蓝绿划分效果集中功能倾向明确的部分，灰色是难以分类的，或通用的效果。黑白是**万用色（2026-09-14 定案）**：可**替代红蓝绿灰**支付（消耗序垫底：同色→灰→黑→白；黑先于白，确定性）；**单向**——红蓝绿灰不可付黑白费，黑不可付白费（反之亦然）。
黑白的**获取**仍不由地牌产出——通道唯一 = 卡结算产生（错边原子转化 / 代价补偿），含黑白费用的卡作地牌时黑白份额不产指示物；**产出不封（2026-10-04 定案）**——全量入账，约束在**使用侧**：支付时每种货币单次贡献 ≤ 地牌槽上限（`GainedThisTurn` 转纯台账观测）；囤积无限、单次使用受限。

#### 费用自动推导（原子表为唯一权威）
基准锚点：造成 1 伤害 / 抽 0.5 张 / 回收 1 张 / 回复 2 命 = 1 费 = 1 个对应颜色元素。
- **效果层计价口径（2026-09-23 定案；2026-10-02 口径修正）**：效果组合阶段=**全部按表累加、无减免抵消**——合成界面实时推导（ConvertOne+DeriveElementCosts 同链），推导费**随效果落盘** Effects.json `cost` 列（`ElementCostRef` 锚价缓存，派生数据**不入内容哈希**——原子表调价重算不换效果 id）；装载期逐效果还原为 `CardEffectData.AnchorCost`——**参考快照，运行时无消费者**：启动式/动态效果（构筑期不占卡费、运行时现付）的显示/预检/扣款一律实时重推导（同链），不读落盘列也不靠整卡缓存（`card.Cost`/`ModeCostCache` 只覆盖非启动式效果）；减免/抵消全部在卡组合层（L2 底盘预算/退费、L3 延迟折——见下）。
- 单个原子效果元素费 = `round(BaseCost × CostMultiplier × max(1, 效果值) × 持续折扣)` 个元素，颜色取 `ElementAffinities.GetAffinityForEffect(type).PrimaryColor`（伤害→红、抽牌→蓝、回复→绿、难分类→灰）。
- `BaseCost`/`EffectColor`/`CostMultiplier` 全部来自 `AttributeValueConfig.json`，调平衡只改配置不改代码。
- **持续时间计价（时间换费用，2026-09-21 与代码对齐；2026-10-05 编辑面收缩——仅赋予类三档可编辑：回合结束/换区清除/永久，非赋予恒一次性，档值本身不变）**：折扣为**相对折扣** `D(实际持续)/D(表内默认)`，分母锚定 Once（伤害锚 1伤=1元素不漂移）。当前档值：Once 0.5 / 回合结束 0.6（**自己与对手回合结束已统一为一档**，限时指示物按持有者回合结束=1回合档）/ 条件持续 0.75 / 离场清除 0.8 / 永久 1.0。属性价梯单独走 `StatTierPrice`（±1 攻/血同锚 0.5）：1 回合 0.5 / 离场·条件 1.5 / 永久 2.0 / Set* 直改恒 3.0；指示物族统一计价=**表行锚 × max(1, 层数)**（2026-10-08 定案，旧指示物档/永久点包价梯退役，判定走 Tags 三型）。

- **数值随机（2026-09-13 定案）**：原子 Value 可配随机幅度 0..100%（构筑期选择，卡组原子条目 `RandomAmplitude`）——结算时名义值 ±span 均匀随机（span=round(|名义值|×幅度)；
- **触发式每回合上限（2026-09-13 定案；2026-09-21 范围钉死；2026-10-05 档位化计价）**：**只有触发式（"xx时"）效果计触发上限价**——默认一回合一次，组合期可改（`TriggerLimitPerTurn`：N=每回合 N 次、-1=显式无限、未声明回落默认 1）；**计价联动（档位化，表 PricingTier 统一）**：次数 2 → ×1.5、3+ → ×2、显式无限 → ×4（同批数量档位：目标 2 → ×1.5、3+ → ×2、全取 → ×3，取代旧 1.2 连乘与期望 4 曲线）。**其余能力各有天然限流、不走此系统也不乘价**：**关键词与启动式通过横置自限**（横置=发动代价，每回合每卡只横置一次——已横置不可再发动）；**光环按箭头数量计费**（受益面线性）。**少数不可修改**原子（表 MountKinds 含 TriggerCapImmutable 位，2026-10-05 重排值 5）恒无限、声明上限被覆写+构筑告警。闸门在触发入栈口（达上限静默丢弃），记账走每回合用量台账（回合开始清零）。
- **全域=组合期表达（2026-09-21 定案；2026-10-05 墓碑连枚举实删）**：类型伤害/全体治疗等固有全域原子（SweepDamage/SweepHeal）已删除（表行 2026-09-21 退役、枚举 2026-10-05 借格式破弃窗口实删）——**全域语义由组合期表达**：TargetKinds 定目标域 + SelectionMode 选全取档（Whole/WholeUnion，对域内全部对象结算、不弹选择窗口）。计价：全取档按档位化数量乘数（见触发上限条）；显式 TargetCount>1 用之；动态数量（-1）计 0 费。
- **检索按筛选维度计费**：`SearchDeck` 原子费用 = 筛选维度档系数（确切单卡/按名称=3、类型+种族=2、单一维度=1）。
- **错边转化（2026-09-11 定案，取代错边折价）**：有益原子(p>0)锁对方域 / 有害原子(p<0)锁己方域 → **全额出计价**，转为黑/白元素获得（对自己负面→黑、对对手正面→白），数量与原折价一致（×|p|，当前表 |p|=1 即全额）。构筑期显示"获得黑X/白Y"（`DeriveElementGrants`）；结算时按实际命中错误侧目标发放（双域卡实际打错边照发；产出不封·2026-10-04 定案，使用侧受支付浓度上限约束）。动态数量原子构筑期不记，运行时实判。
- **内容契约（2026-09-11 定案）**：主动/被动**效果栏只能挂对自己有益或中性的原子**——错边锁定（对自己有害/对对手有益）被转换器剔除，只能进**代价栏**；代价（Payload）只接受错边（p≠0 错侧）或 p=0 单侧域锁定。中性=极性 0 或无目标；"单个原子同时作用双方"不支持——需要时制作专用原子（先不管），双域原子照旧全价。
- **主动效果计价口径（2026-10-02 定案收口）**：启动式（Activate_* 时机）**元素锚价构筑期全免、发动时现付**（2026-09-08 定案——发动=横置+实时推导锚价扣款+选目标；余额不足=宣言期拒绝/结算期空转不回滚）；**效果槽照常占用**（"不占费用，占技能挂载"维持——效果槽是 AI 侧每卡最大原子数限制的可见性锚，免槽会让 AI 看不见超限堆叠）。**关键词型原子不得作启动式**：Grant 行目标域恰为 {Self}（纯自指，21 行——冰晶/毒刺/潜行授予等）= 关键词的挂载形态，作启动式（横置换静态身份）无意义——装载期 `CardEffectConverter` 剔除告警（AtomicEffects/Steps 全树）；**赋予型 Grant（域含他人，如反疗/重放）不受限**。判定收口 `ComposerCatalog.IsKeywordStyleGrant`（与合成器 UI 同源）。同日口径修正：Effects.json `cost` 锚价列为参考快照（运行时无消费者——显示/预检/扣款一律实时重推导，表调价即陈旧不换 id）。
- **发动方式三值钉死（2026-10-02 定案）：主动=启动式、自动=可选触发式、强制=无条件触发**——`ActivationType` 与 `TriggerTiming` 双向绑定：主动声明带触发时机（合成器旧 bug 只写发动方式不写 Activate 时机/手写 JSON）→ converter 告警并钉 `Activate_Active`；反向（启动式声明强制/自动）由既有对称校验覆写回主动。合成器已修：选"主动"即写 `Activate_Active`、离开主动档回落 `OnPlay`。攻击/守卫与该口径天然对齐：**攻击=启动式语义**（主阶段回合方宣言、结算支付横置、速度0——专属 intent 路径非效果条目）；**守卫=可选触发式语义**（触发条件=攻击宣言在栈、响应窗口内自选、速度1响应、结算支付横置）。
- **效果/指示物分离原则（2026-09-11 定案）**：同名的效果与指示物**不是同一个东西**——效果只负责**赋予**某人指示物，指示物本身才是真正承载持续规则的（如：紊乱效果=赋予目标紊乱；紊乱指示物=持有者不能以对手角色作为攻击与效果目标）。效果是投放器，指示物是规则体。
- **关键词赋予权限三分（2026-09-14 定案）**：角色来源（魔法/英雄）→ Setting 文本轨（照旧按声明持续）；**目标=自己 → Setting 文本轨（自赋予视同印制文本，永久——「赋予」给别人才是增益）**；生物→**别人** → Temp 固定 1 回合（回合末清）。关键词本体不走触发上限系统——焊在战斗管线里，由战斗次数/伤害次数天然限流。
- **效果级 schema 收缩（2026-09-14 定案）**：`DurationValue` 删除——持续档收缩后 ForTurns(1/2)≡专档同义词、3+ 构筑拦截，回合数走指示物自减（ForTurns 枚举仅存于指示物时钟）；`DynamicTargetCount` 并入 `TargetCount=-1`（任意=玩家自选数量：原子计 0 费；**不关联地牌资格**——2026-09-21 定案，地牌资格只看生物身份）。`-1` 旧"任意"文档语义从未实现（原与 0 同落全取），重定义无行为回退。
- **整卡计价三层（卡层，2026-10-10 可支配底盘定案与代码对齐）**：L1 原子锚价（上文）→ L2 卡层组合（**可支配底盘**：每卡 3 点万能色额度（经济依据=入组 1+抽牌 2），结构项 攻(1)+守(1)+效果槽(1/个) 各占 1 点——**剩余 N=3−结构项不作废，按卡型支配**：法术抵价 N−k 或提速 k 档（卡级 `SpeedBonus`，运行时与效果 BaseSpeed 加和、计价侧不收钱）、生物/地牌全额抵价（抵价=d(C) 取整后总价逐点扣，先灰后最高费用色——RefundColor 自标已删，自动规则）、结界二选一=启动式发动费每次 −N（结算期落点）或入场耐久 +N（`SurplusToDurability`，免费）；**结构项>3 差额入灰加价（不吃 d(C)），与剩余互斥**；**攻/守=默认存在可去除的主动效果**（`NoAttack/NoGuard` opt-out）；**抉择分支计槽**：一个效果含 N 分支 Choice=N 槽；抉择价差溢价已废；**衍生物无底盘**：召唤单价=模板内容全价（S含耐久+K+E 不乘 d(C)）+结构费全额，见 `CardCostService.ContentPriceOf`）→ L3 整卡组装（身材费 S=(攻+血)/StatUnit 入灰桶、关键词费 K=Grant 原子表行固定费、连接光环费 A=条目按单回合档折算（源行锚×折算系数，2026-10-08 起不再称"指示物档"）；整卡 (S+E+K)×f 一次取整最大余数法分色，f=d(声明档位) 延迟折——**分段曲线 2026-10-10 定案：C1-3 不折、C4-9 线性 1→0.8、C≥10 恒 0.75**；三类卡型统一（2026-10-02 定案：法术不再豁免））。**D≤C 超模校验已移除（2026-09-24 定案）**——效果层纯表累加、卡层只算各种减费，D/C 直判无意义：合成器保存/卡组装载/卡组保存三处超模警告全部删除，费用推导仅产建议档位与明细、不做合规判断；声明费优先，缺省写建议档位 Ĉ（差额补灰自洽）。**抉择卡**：构筑期推导全部模式费缓存（ModeCostCache），支付与**地牌产元素**均按玩家所选模式（与出牌同口径）；声明 costList 缺省写最大模式费，仅作 UI/排序口径。

#### 代价栏（单卡单条·强制·2026-10-04 本轮全套口径）
- 一张卡**只有一个代价栏、只能填一个代价**，无法像效果那样组合（装载期违约警告）。
- **代价栏在卡组合层（2026-09-23 定案：数据/UI 上移）**：数据落 `CardData.PayloadCost`（单条 Payload），填装在卡编辑界面；效果级 `CardEffectData.Costs` 为 legacy 兜底（旧数据仍读取，卡层已填时跳过防双收）。效果合成界面不再有代价槽——**效果阶段不存在费用减免抵消**。
- **代价也是效果栏，不是特殊判（2026-10-04 本轮定案）**：代价栏**占 1 个效果槽**（`CountEffectSlots` 计入）——底盘 3 灰预算同口径扣槽（攻1+守1+效果槽1/个），超出加价；即「使用它要单独为效果栏付 1 费」。锚价仍不并入卡费（只作门槛与补偿基准）。
- **代价全价过地牌门槛、装载不受减免（2026-10-04 本轮定案）**：全价（`PayloadUnitGrant`——与补偿同锚）使用时单独过门槛——**全价 > 地牌槽上限 → 整卡不可使用**（走不到代价发动；例：上限 3、全价 4 → 卡死）。
- **代价无有效目标 → 发动失败回退（2026-10-04 本轮定案）**：声明期无候选 → 拒发卡留原区；响应窗口内预选目标全部失效（死亡/离场/不再满足过滤）→ 结算期发动失败，卡**回退声明来源区**（手牌路径回手牌），不付费、不执行、**走不到黑白生成**。存活校验按支付者视角域内重解析（`GameActions.PayloadTargetsAllLost`——手牌域 {5} 等非战场域同口径）。
- **代价强制（2026-09-14 撤销「代价可选」）**：使用时必付——付费步**先扣卡费、再强制执行 Payload 原子**，无选择窗口、无减费通道；**生效后立即按执行前快照全价获得黑（己方侧）/白（对方侧）**（快照在执行前取：执行会膨胀模板身价；产出不封·全量入账，使用侧受支付浓度上限约束）。**元素池不足以支付卡的费用时，将生成的黑白不提前计入**（声明期 `CanAfford` 与结算期支付点同口径——新生成黑白不能垫本卡；响应窗口后支付失败入墓不回卷维持）。cast 付费步与启动式/动态效果统一走 `PayWithCompensationAsync`。

#### 元素池生命周期（地牌→指示物→横置→入池→墓地）
两层结构：地牌上的元素指示物 + 可花费的池（bank）。
- **地牌资格（2026-09-21 钉死）：只有卡组正式生物（CardWrapper + Creature 超类）可作地牌**——魔法等非生物超类、效果生成的衍生物/临时复制卡一律不可；与效果内容（如动态数量）无关。
- 地牌放入时按费用构成生成对应颜色指示物（黑白份额不产指示物，纯黑白费卡不可入池）。**抉择卡按玩家所选模式产指示物（2026-09-21 定案，与出牌同口径）**；所选模式 0 费 → 无指示物 → 不可入池。每张地牌有 `IsTapped` 横置态。
- 取元素：选一张 `!IsTapped` 且有该颜色指示物的地牌 → 移 1 指示物入 bank → 该地牌 `IsTapped=true`（每地牌每回合横置一次）。
- **跨回合可取**：支付时无论轮到谁都可横置己方地牌取元素。
- **自动横置补足（2026-09-30 定案）**：支付时（出牌付费步 / 英雄技能 / 效果费）bank 不足以覆盖账单、但未横置地牌可产出所需元素时，**自动横置地牌补足**（跨回合支付同样适用）；声明期门禁（`GameActions.CanAfford` / `CanPayCostWithAutoTap`）按同一潜力口径放行（纯预检不动状态，实际横置在付费步）。产色优先级：缺口本色 → 为挤占灰的先序需求产本色释放灰 → 灰（`ElementPool.PlanAutoTaps` 与账单规划器同序同链）；黑白本色费缺口不可补（地牌不产黑白）；横置耗尽的地牌照常送墓。手动横置入口保留（玩家自选产色优先于自动）。AI 驱动器（SimpleAI/无头）回合初已全横置，行为不变。
- 回合开始把该玩家所有地牌恢复直立。
- 指示物耗尽的地牌直接进墓地。
- bank 无上限跨回合积累，但支付受**浓度上限**约束（每种货币含灰的单次贡献 ≤ 地牌上限；黑白可作万用填充——见费用体系）。
- 地牌位置无关，仍走元素池区域，**不**绑定 HexCell（见待办）。


### 结界耐久（2026-09-24 定案；2026-10-02 战斗侧实装）
结界（Enchantment）为耐久体：耐久类似生物的生命，**每次受击仅损失 1 点耐久**（不同于生物承受全额战斗伤害——战斗与法术/效果伤害同管线 `KeywordRules.ApplyDamage`，有效伤害钳 1：DamageEvent/吸血/返回值同源），归零销毁入墓（**Smashed 直毁**，与装备共用 `CounterRules.LoseDurability` 公共路径，不经死亡决策表 DeathRules）。实现口径（2026-10-02 三类卡型定案配套）：
- **入场初始化**：`CardPutToBattlefieldEvent` 驱动挂 `DurabilityCounter`（Permanent 层）初始值=`CardData.Durability`（卡表 `durability` 列，0=无；卡牌合成界面结界表单采集）——一切**无生命单位**（战场非生物卡）同走此初始化，装备/结界一套耐久语义。
- **SBA 不扫无生命单位**：`ZeroToughnessChecker` gate 收紧为活体单位（生物）——结界不再被当 0 防御单位误杀（旧 bug：CardWrapper 恒实现 IHasLife，无生命数据时带 1 点幻影生命，1 伤即死绕过耐久）。
- **域数据**：伤害族（DealDamage/PierceDamage/DrainLife）TargetKinds 开放无生命域 3,4——法术伤害可消耐久；**冻结域收紧 1,2**（原 1,2,3,4 靠 NoRole 过滤副作用排除结界，现为域层显式排除——冻结横置对结界无效）。
- **攻击目标显式化**：结界=合法攻击目标（防守方战场卡；反击力=0 天然单向）；非战场卡（FieldZone 英雄技能卡等）不可被攻击。
- **回归锚**：TideServer verify **V9 段**（`Verify/SectionRules.cs`）+ Unity `CardPipelineVerifier.TestThreeCardTypes`（同口径）。
- 光环可挂结界（生物/结界同规——箭头/光环声明仍走效果合成器，挂卡并集）。
- 遗留：耐久计价未做（当前免费，底盘预算只收攻/守/效果槽）；战斗改写关键词（毒刺/冰晶/梦魇）已限活体目标，拦截式改写门（DmgRewriteFreeze 等）对结界的语义待实战观察。

### 疲劳（空卡组抽牌）
- 牌库为空时抽牌：不抽牌，改为**疲劳**——第 N 次疲劳对该玩家造成 N 点递增伤害（炉石式）。

### 死亡与移除术语（定案）

**世界观定案**：角色（玩家化身）就是**普通生物单位**——对生物有效的效果对他也有效。使其免疫各种效果的是默认持有的**神佑（DivineProtection）状态**（`Player` 构造时写入 `_keywords`，可被效果移除的真实状态，非硬编码）：只接受"生命值归零"的死亡。关键词存储已上移到 `Entity` 基类（Player/Card 同构）。

**标死与死透（2026-09-15 SBA 定案）**：死亡分两级——**标死**（伤害落血同步置 `IsAlive=false` + 死因/来源留档，卡仍在战场＝"战场尸体"）与**死透**（SBA 栈对象到点重查仍满足死条件，经 `DeathRules.TryKill` 真正送墓、发 `CardDestroyEvent`、亡语入队）。一切"击杀时/击杀门"（`DmgKillsTarget` 等）的判定口径＝**标死瞬间**——先结算击杀奖励、后目标被救回，是合法终态。窗口期间的尸体：仍占战场容量（满场预检把它算进去）；**不可被手动指定**为目标（`EffectTargetValidator` 的 IsAlive 校验拦）；范围波及（全域/随机）照常命中——伤害打尸体＝浪费，治疗打尸体＝救活。配套：观察者死亡时点 `OnOtherCreatureDeath` 已入枚举（镜像 OnOtherCreatureEnter，死的不是自己）；终局原子**宣告胜利**（DeclareVictory，表行已加）＝效果控制者的对手获胜（`GameOverReason.EffectVictory`），亡语「对手获得胜利」的载体。

**角色亡语（2026-09-15 定案，判负效果化）**：角色（Player）获得亡语能力——引擎为每个角色**内置一条强制亡语 OnRoleDeath → 宣告对手获得胜利**（宣判即终局：宣告无条件，亡语轮不可靠加血翻盘，救点只有 SBA 窗口一次）。时序：判负 SBA 到点重查仍死 → 发角色死亡事件（RoleDeathEvent；宣判标记防重入——此后不再开窗/发事件）→ 角色亡语入队 → 亡语轮双 Pass 后结算宣告，终局原因＝EffectVictory；亡语被全拦/未挂时 CheckLifeGameOver 兜底判负 LifeZero（两种终局原因可区分"宣告的败北"与"系统兜底"）。硬判负从"角色死亡动作本身"退化为兜底——**胜利条件全面效果化**，未来拓展胜利方式（集齐组件即胜、倒计时取胜、任意卡挂宣告胜利等）零引擎改动。OnRoleDeath 时点对效果开放：可给角色**追加/改写**亡语。边界口径：**战斗致死**无 SBA 窗口但同样走宣判（亡语照常宣告）；**疲劳致死**保持直判 LifeZero（不经宣判、不可救）。

### 原子效果
所有卡牌效果均遵循单一数据流管道：
触发 ➔ 条件过滤 ➔ 支付代价 ➔ 锁定目标 ➔ 执行动作

0. 来源归因与三轨制（2026-09-09 定案）
- **来源归因**：生物（场上卡）发动的效果，来源=该生物；所有魔法卡的效果来源=角色。
- **赋予族一律设置轨直写（2026-10-08 来源分轨退役：「魔法=永久 / 生物=指示物」旧分轨已删）**：
  - Modify* 族（改攻/改血/改费）永久直改字段——跨区保留、净化不清（视同本体）；临时层（换区清）由指示物原子族（AddPlusOne/AddPowerUp 等）显式表达，与来源无关；
  - 魔法卡来源=设置类（同上直写，跨区保留、净化不清，视同本体）；
  - 连接箭头=光环（箭头指向格的当前占据者享受卡面 linkAuras 声明；来源须持续在场，断链/离场即失效；计价按单回合档折算）。**坚韧（2026-10-08 指示物化）**：坚韧=指示物（ToughnessCounter，表行 GrantToughness）——每层使每次受到的伤害 −1、不随受伤消耗、可叠加；角色可持有；换区清、净化可清。旧「坚韧光环」（受伤-1 只以光环形态存在、绿1×箭头）与 GrantArmor 命名一并退役（GrantArmor→GrantToughness 同日更名）；构筑校验：声明 linkAuras 必须配箭头（生物/结界同规）仍然有效。**守护（2026-10-08 配对制改版）**：守护=关键词（GrantGuardian 表行）——登场/授予时弹选一个己方目标（单位或角色），其受到的伤害改写为守护者承受（GuardianRules 配对表；活性实时校验，无限次直到守护者死亡/离场、离场断链、复活重选）；位 8 拉黑退出连接光环族。旧守护箭头光环与守护计数体系退役。
- **关键词口径更新（2026-09-13）**：**吞噬**=消灭目标 + 吞噬者按被消灭单位**最大生命值**恢复生命（关键词吸收与按当前生命回复已删；不灭/复生拦下即无回复不变）；**再生**=回合开始恢复**全部**生命（原固定+2）。
- **净化语义**：变回生物原有状态——卡面本体与设置类保留；清全部指示物+临时赋予+可移除状态；神佑对净化有抗性（剥神佑+剧毒组合无法计价平衡，移除留给未来专用效果）。
- **沉默/无效**（均为指示物，2026-09-13 与表表述对齐）：沉默（白1）——目标不可发动主动效果；无响应（白2）——目标的非启动式能力无法响应（全部触发式+光环静态；伤害管线被动与回合维护不是能力发动不拦）。净化/沉默/无效打在光环受益者身上无效，只有「无效」作用于光环来源能压制光环。
- **入场刷新**：真实入场（打出/效果召唤/复活/token——统一换区出口）时，卡面被消耗的消耗项补回：关键词（法术护盾）按 Printed 轨差集补回；指示物化项（圣盾/复生/潜行——2026-10-08）层数=0 时补 1 层（生效自减档换区不清，未消耗层跨区保留）。复生（死亡替代原地留场）与控制权变更（场内迁移）不经入场口，不触发刷新。

2.作用目标与范围 —— 筛选与策略分离
目标选择 = 筛选器 + 决策权。
筛选器定义合法对象（如：敌方、野兽、攻击力>5），生成弹出展示筛选出的对象，玩家自行选择最终目标。
- **可选范围 + 数量两态**（无 AOE 概念）：`TargetFilter` 给可选范围，玩家在范围内指定具体目标；数量分**固定 N**（运行时须正好选 N 个）与**动态**（运行时玩家自选 0..候选数，费用计 0——不关联地牌资格）。多目标对**每个目标各适用一次**效果及其后续分支（per-target）。
- **全域（2026-09-21 定案：固有全域原子已退役）**：不再有 SweepDamage/SweepHeal 专用原子——**全域=组合期表达**：TargetKinds 定目标域（可双侧 {1,2} 或单侧）+ SelectionMode 选全取档（Whole/WholeUnion，对域内全部对象结算、不弹选择窗口、不可随机）。计价统一走档位化全取乘数（见费用自动推导小节）——单一价格路径。
- **随机选目标（2026-09-13 定案）**：`SelectionMode=Random`——范围存在且目标数 > 0 时**不弹弹窗**，随机种子自动抽取（TargetCount 管抽取个数；全部档随机无意义 ≡ 全域全取）。随机从**完整范围**抽取、绕过选择：**扰魔/潜行的语义 = 存在此范围但弹窗不显示**——手动选择（含 AI/无头代替选取）不可选，随机与全域照常命中（范围波及）。指名路径硬校验（攻击/直接指向不可指扰魔）不变。
- **目标硬限制（2026-09-13 修复定案；同日更名）**：**帷幕（原"嘲讽"）= 只吸引效果目标、不拦攻击**——与守卫的攻击拦截职责冲突后收窄：对手有存活帷幕卡时，效果**指定**（手动/随机抽取池）的对方侧目标收窄为帷幕卡（角色与非帷幕随从均不可选）；全域/范围波及不受限；**攻击不受帷幕限制**（攻击侧目标强制由守卫拦截承担）。运行时关键词 id 仍为 Taunt（更名只改中文文案，同辟邪→扰魔先例）。**紊乱 = 持有者不能以角色作为攻击和效果目标**——候选域层剔除 + 声明期外给目标收口（UI/AI 直给目标同样过滤）。**碾压（2026-09-13 重定义，红3）= 攻击结算时，对目标以及目标相邻 1 格的同侧随从造成战斗伤害**（相邻受击不反击；攻击角色无相邻概念、不溅射）——不再与帷幕交互。
- **edict 原子：牺牲（黑2）/摒弃（黑2）——2026-09-13 定案**：作用对象=**双方角色**（filter "Player" 仅角色）；效果=**持有者自行选择**——牺牲=选一个己方生物效果死亡（来源=持有者、无视不灭），摒弃=选一个己方场上**无生命单位**（结界等）直送墓地。**豁免帷幕**：帷幕只约束对手的选择，不管持有者自选。
- **分区候选**：筛选器按分区 token（Battlefield/Hand/Graveyard/Deck/Exile）从对应区取候选；候选 > 需求数时弹选择（AI/无头/超时自动取前 N）。
- **效果层只有并列·相同目标（2026-10-04 定案；2026-10-05 两槽定案：并列缩为两槽）**：效果层面并列原子**共享同一份选中目标**（组合域一次选择、全体原子共用——不再每原子各自解析）；**主序列主干原子 ≤2**（Then 奖励/光环条目不计入，超限构筑 Error——两槽即组合形态上限，抉择/条件奖励并入槽内）；组合域=**效果级作用范围** `CardEffectData.TargetKinds`（Effects.json `kinds` 列）优先，未声明回落原子域交集（存量兼容，两代同链）。作用范围=并列原子作用域**交集内**的选择：无域原子（额外回合/跳过回合/宣判/衍生物生成）与交集空原子在合成器库筛选时直接过滤；**两槽主干域交集须非空**（引擎载荷槽零域豁免——其"主干"=条件本身，纯引擎效果无主序列无效果级目标）。None 档（未声明选择模式）在**解析期**（无预选目标的触发式）按选一共享解析一次；域全隐藏区（对方手牌/双方牌库=6/7/8）维持自结算——每原子兜底自动取首候选、不弹选（防"从牌库选目标"交互）；施放路径声明期目标照旧，不走组合解析、域校验口径不变。**发动类两槽统一**（主动=无触发上限/无触发时机/同速；自动=同单回合生效次数/同触发时机/无速度——效果级字段天然共享，强制档维持系统自用不开放）。
- **效果通用可编辑属性=七项+两顶栏（2026-10-05 定案）**：原子级=效果数值、数值随机幅度；效果级=作用范围、发动速度、目标数、作用次数（触发上限）、随机目标；顶栏=发动方式（自动/主动）、触发时机。**选择模式下拉取消——由 作用范围域宽×目标数 推导**（converter：作用范围已声明时推导覆盖存储值——单域→单范围档 0/1/2、多域→union 档 3/4/5；数量 1=选一、N>1/任意(-1)=选多、0=全取；随机=正交标志不入推导；未声明沿用存量存储值）。**持续档收缩**：仅「赋予xxx」类保留三档——回合结束/换区清除（原"离场清除"文案）/永久，非赋予=一次性（计价折扣档值不变，Duration=Once 恒 1；运行时六枚举保留存量兼容）。**落区写死（按原子）**：衍生物（SummonToken）恒落**战场**（handler 与计价同口径）；回响的临时卡落**手牌**（回合结束移除，TempCopyRules；微缩/放大已删 2026-10-10）；毁灭/除外/弹回/洗回去向原生固定——组合层落区三档退役（`SummonDropZone` 字段保留保指纹稳定，UI 停写）。

3. 原子效果组装 —— 两槽并列 + 槽级分支载荷（2026-10-05 两槽定案；承接 2026-09-13 分支体系正规化）
原子效果与关键词的静态数据全部由配置表驱动。**效果 = 至多 2 个并列槽**，每槽 = **主干原子 + 槽级 Branch 载荷（三条件族选一，可无）+ Then 奖励列表**。存储=平铺原子（`AtomicEffectEntry.branch` 载荷随原子走，Effects.json 引擎头字段已退役）；`Steps` 仅存光环形态的规则光环原子步与存量抉择——遗留 kind=1 门步骤 converter 自动折叠为载荷（产出族→Outcome、其余→Gate；elseSteps 丢弃）。**Then 奖励**：无发动时机、条件达成**强制结算**；有目标域的奖励结算前**依次弹选**（AI/无头自动选首，verify 确定性口径）；计价 0——预算制（Gate/Outcome=条件 premium 放置上限；Engine=机制费/引擎预算），奖励原子须可挂载为分支奖励（MountKinds 含 BranchReward 位）。

### 栈/连锁系统
- 卡的效果发动分两种：**条件发动**（"xx时"时点的事件/响应触发）与**速度发动**（玩家自主决定时机的主动发动）。**条件发动不走速度**——触发式效果满足时点即入栈，不参与速度比较。
- **速度是效果自身属性，无"基础速度"**（2026-09-13 定案，废除"阶段×回合归属"的默认速度）：原子效果速度**默认 0**，组合期间自行调整（需在对手回合用/瞬间释放的调 1 以上，笨重的保持 0）。
- **记速器不是无条件 +1**，默认值 0，只有发动**高于**当前记速器的卡才把它抬到该值。发动门槛：**回合持有者 速度 ≥ 记速器；非回合持有者 速度 > 记速器（严格大于）**。
- 双方轮询至无人再发动，开始结算；开始结算后不再轮询，直到本次连锁全部结算完成、记速器归 0，才进行下一次双方轮询发动效果。
- 速度值来源：卡在编辑/组合阶段经速度类效果调整自身速度。
- **SBA＝速度 1 栈对象（2026-09-15 定案）**：连锁排干后，死亡/判负类状态动作（防御归零送墓、生命归零判负——"关键两类"）不再无条件自发执行，而是作为**速度 1 的伪栈对象**入栈：记速器抬到 1、回合方先获优先权、开响应窗口——窗口内回合方可连锁（≥1）、非回合方严格 >1（≥2）；LIFO 使窗口内的救场效果（如速度 2 治疗）先于 SBA 结算，SBA **到点重查**：条件已不满足（被救回）则空转——不送墓、亡语不触发（与预言延迟到点验证同哲学）；无人响应则照旧送墓/判负。记帐型 SBA（区域变更事件补发、±1/1 指示物湮灭）**不开窗**、照旧自发执行（否则每次出牌的换区记录都会开假窗口）。
- **死亡多一轮窗口**：每次效果致死＝标死 → SBA 窗口（双 Pass）→ 到点送墓 → 亡语入队又开新一轮（触发式不走速度、记速器归 0）。无头/AI 驱动下窗口被自动双 Pass 排掉，结果与无窗口时一致。
- **救场是速度特权**：0 速卡（普通法术档）没有救场资格；触发式不走速度恒可入栈——但当前没有"将要死亡时"触发时点（OnTakeDamage 在伤害时点，早于窗口），"被动救场"卡暂不可表达。
- **两种死法、两种救法**：伤害致死＝标死，只有治疗能救——治疗对战场标死卡回到有效生命 >0 时**解标死**（恢复 IsAlive、清死因归因，溢出转生命上限照算）；减益致死（活着但防御 ≤0）＝任何加防手段（光环/指示物）都能救，SBA 到点按层引擎现值重查。
- **判负同样可救**：生命归 0 的玩家在窗口内回血则不判负。双杀（双方同时归 0）都无人救时，按检查顺序先判 Player1 负（隐式裁决，先手方劣势——设计同归局时注意）。
- **不可救定案（2026-09-15）**：**战斗致死**（战斗结算后直调执行）、**光环重算致死**（结算中直调）、**疲劳致死**（空卡组抽牌伤害直发判负）三类**不经 SBA 窗口、不可响应**——立即送墓/终局。即：只有"效果致死"有死局窗口，这是有意设计而非待办。

#### 链级反制扩展点备案（2026-10-02 讨论，暂不做）

同一条连锁里多条法术可在（各自玩家的）发动区共存——按卡引用独立结算（`ResolveCardCastAsync` 查"自己"在不在发动区）、费用各自在响应窗口后支付、无效位消费即复位（`_isNegated` 只拦一次）。这组定案已是连锁反制的正确地基，无需返工。将来做游戏王式"无效上一环（锁缚龙）/无效整条连锁（时空转生）"时，按以下**两个纯增量扩展点**落笔，不动现有语义：

1. **StackEngine 补只读枚举口**：`_stack` 现 private（公开面仅 `IsEmpty/StackSize/Peek`），handler 侧链内省需 `PendingObjects` 只读枚举。链相对语义无需指向——链顶结算时压在它下面的对象即"上一环"；"整条链"= 结算时刻栈上全部对象（触发式在栈清空后才累积开新连锁，链边界天然清晰）。
2. **无效位上移栈对象层**：`_isNegated` 目前挂 Card 上、仅整卡 cast 结算路径消费——链上混着场上来源的触发式/启动式效果（Source 在战场不在发动区）时无处落笔。届时在 `EffectInstance` 加实例级无效标志，cast 与普通效果两条结算入口统一检查；卡上位可保留为镜像或迁移。（**2026-10-04 已落地**——见下节「两层无效」：`EffectInstance.IsActivationNegated/IsEffectNegated` + 双结算入口消费门；标记入口=按**源卡**指向待结算条目，备案点3 的栈对象域暂不需要。）
3. **栈对象域（TargetKind 尾部追加）**：域 15/16 只覆盖发动区卡，表达不了"指定无效某个栈对象"（如无效场上单位的启动式发动）——需要时新增栈对象域，模型支持尾部追加。（**2026-10-04 缓解**：两层无效现按"指向源卡"落标记（处理器在栈内按 Source 匹配待结算条目），场上发动已可无效；专用栈对象域仍留作后续精化。）
4. 随附规则定案（模型不阻塞）：SBA 伪对象不可无效（通例）；攻击宣言不被"无效"而由守卫改目标承担；结算中途新入栈的触发式属**新连锁**（现架构天然分层，语义比游戏王干净）。

### 反制体系：两层无效（2026-10-04 定案）

无效分两层，两个原子各一行（表行「发动无效」黑3 /「效果无效」黑5，均指向发动区·域 15/16）：

- **发动无效**（NegateActivation，原打落承接）：无效化**发动**本身——净零成本。就当这次发动没发生过。
- **效果无效**（NegateEffect，旧标记实现承接）：发动照常走完（计费/计次/横置照付），**效果**不结算。

| 发动场景 | 发动无效 | 效果无效 |
|---|---|---|
| 发动区施放（卡） | 扣费**返还**（付费前中止）、卡送墓 | 扣费**不返还**、卡送墓、效果不结算 |
| 战场主动发动（启动式） | **不扣费**、横置**不重置**（声明期代价不退） | 扣费照付、横置不重置、效果不结算 |
| 强制效果（光环类强制桶） | **不受管制**（不可标记） | **受管制**（效果跳过） |
| 「xx时」响应（触发式） | 受管制；**不计入发动次数**（上限记账退还，同回合可再触发） | 受管制；**计入发动次数**（记账保留，上限照锁） |

引擎映射：施放两路在 `ResolveCardCastAsync`（步1 发动区缺席=发动无效送墓中止；步3 `_isNegated`=效果无效付费入墓）；场上发动经栈条目旗标 `EffectInstance.IsActivationNegated/IsEffectNegated`——反制处理器按**源卡**在栈内匹配待结算条目落标记（强制桶对发动无效免疫的过滤即在此处），消费门在 `EffectExecutor.ExecuteAsync`（发动无效先于一切支付与潜行移除、触发式退还 EffectUsageTracker 记账；效果无效在扣费后跳过原子、启动式照记次数）。验证锚：TideServer V9.o（施放端到端 + 计数口径 + 强制桶面）、Unity 侧 CardPipelineVerifier 反制窗口段（口径同源）。

### 数据分层与三层引用链（2026-09-21 钉死）

**配置表 vs 用户数据**——两类文件严格分家：
- **配置表（开发者调平衡，不随玩家数据走）**：`Assets/Configs/AttributeValueConfig.json` = **原子效果表**（唯一权威：BaseCost/EffectColor/CostMultiplier/极性/域/挂载位；调平衡只改此表不改代码）。
- **用户数据（玩家构筑产物）**：全部在 `Assets/StreamingAssets/Card/`——`Cards.json`（卡池）、`Effects.json`（效果库）、`<卡组名>.json`（卡组，DeckSerializer 落盘）。读写单源：EffectsLibrary / CardCatalog / CardConfigSerializer / DeckSerializer / EffectLibrarySerializer 全部指向 `Card/`。

**三层 ID 引用链**——上层只存 ID 引用，不内嵌下层实体：
```
卡组（DeckData）      = 卡的 ID 引用数组（cardIds）
  └─ 卡（Cards.json） = 增量数据（名称/类型/攻血/耐久/费用构成/箭头…）+ effectIds → Effects.json / 原子表（双路引用）
       └─ 效果（Effects.json，EffectSlim 瘦格式）= 原子表行 ID 引用（refId）+ 增量（value/str/amp/kinds + **branch 槽级分支载荷**——2026-10-05 两槽定案：条件三族+Then 奖励随原子存储，引擎头字段已退役）+ 效果级作用范围（kinds 列，2026-10-05 相同目标定案——空列=未声明回落原子域交集）+ 光环声明（arrows/linkAuras，2026-09-23）+ 锚价（cost，2026-09-23：合成期纯表累加实时推导落盘——派生列，不入内容哈希）
       └─ 原子（AttributeValueConfig.json，8-hex ID）
```
- **关键词引用化（2026-09-24 定案）**：卡表 `effectIds` 双路引用——Effects.json 命中=组合效果；**直接引用原子表 refId=本体关键词**（引用组合效果中的 Grant 族=赋予关键词，赋予亦可作用于自己）。legacy `keywords` 列退役（编辑器菜单 `Tools/卡表/关键词引用化重写` 一键迁移——HashCard 读运行时物化结果，迁移前后卡 ID 稳定、卡组引用不断链）；装载端双路解析合并去重，反查失败的引擎专用词仍留 legacy 列兼容。
- 卡/效果 ID 均为**内容哈希**（内容变 → ID 变；同内容跨文件同 ID，天然去重对齐）；原子表 ID 稳定不漂移（重推工具收口）。
- 保存链路：合成卡即入池——卡写 `Card/Cards.json`（effectIds 引用），效果定义按 ID upsert 进 `Card/Effects.json`。
- 内嵌效果/内嵌卡的旧格式仅存于验证夹具兼容路径（`CardLoader.LoadCardsFromText`），正式链路一律引用化。
- **网络线格式同口径（2026-09-22 定案）**：线上只传 ID 与运行态，效果文本一律客户端本地重渲染——执行摘要事件传 EffectId/来源/控制者（拼好的战报文本不上网，`[NetProjectionIgnore]` 投影排除）、快照栈条目不带效果显示名（按 EffectId 查表）、`MsgGameStateSync.Stack` 全量效果定义字段与 DTO 已删、实体反问不传卡名 Labels（按 CardId 查表）；真实数值（随机实掷等）由细粒度事件承载。
- **开局握手（2026-09-22 定案，同日收缩口径）**：只核对**卡组引用闭包**，不做全池对比（不比对整个 Cards.json/Effects.json）——卡/效果 ID 即内容哈希（命中即一致），唯一内容核对是闭包引用到的**原子表行**（`NetDeckDigest` 摘要，双方按同一卡组各算一次比对）。对局开始 `DeckSubmit`(111) 携卡组 cardIds+摘要，服务器校验卡表命中/不重复/效果-原子引用闭环/摘要比对，拒绝走 Error 帧；通过后 `MatchManifest`(125) 下发（己方卡组回显+摘要、对手仅数量——卡组构成隐藏），客户端双向校验。缺卡开局拒绝，不再静默打成"缺卡对局"；对手侧与未来扩展**用到再核对**（`NetMatchHandshake`，网络协议.md §11）。

### 总结
这是一个基于颜色效果分类的，将原子效果组装成效果，将效果组装成卡，用卡组装成卡组，最后像普通卡牌对战游戏一样游玩的联机卡牌游戏。每个玩家用各自构筑的卡组风格与对手作战。
