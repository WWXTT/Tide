# 训练奖励修复方案（全套 + 短验证）

## 诊断回顾（已确认的三个根因）
1. **塑形淹没终局**：λ=0.05 固定在 Unity 侧，双方各自整局塑形累计 ≈ +3.1，远超终局 ±1；且 Φ 把手牌按 0.6 倍计入（每回合摸牌=白拿正奖励），进攻收益（λ×伤害×0.15）比发展动作低一个数量级 → 学会拖局：局长 90→267，对脚本胜率 0.35→0.1。
2. **自对弈 GAE 视角混流**：双方决策在同一条轨迹交替，critic 回溯把对手视角价值当同号混入。
3. Python `reward_lambda` 是死参数（Unity 硬编码）；评估 20 局噪声 ±0.11。

关键约束（探索确认）：
- 桥接是 TCP batchmode（非 stdio），`info.toPlay` **每步已带行动方座次**（0/1/-1）——GAE 修正纯 Python。
- `HandWeight` 被观测特征 g[28]/g[29]（TideObservation.cs:196-197）共用，**不能归零**，需加"不含手牌"的势能变体，观测保持不变。
- 主工程与 Tide_train 的 C#/Python 文件目前字节级一致；`make_train_copy.ps1 -Refresh` 是 /MIR 镜像 → **所有改动落在主工程 E:\UnityProject\Tide**，再刷新同步。

## B. 主工程 Python 改动（tide_rl/）

**B1. `tide_env_tcp.py`**
- reset 发送 `{"op":"reset","opponent":..., "shapingLambda": reward_lambda}`（reward_lambda 从死参数变真参数）；step 注释同步（λ 不再固定 0.05）。

**B2. `rollout_common.py` — 座次记录 + 带符号 GAE（核心修正）**
- `rollout_single_env` 新增 `seat` 入参（当前 obs 行动方）并返回 `next_seat`；每步响应的 `info["toPlay"]` 推进 actor 座次，data 增加 `"seats"`；episode 结束 reset 后从响应 info 取新座次。toPlay 缺失时 seats=None（回退旧行为）。
- `compute_advantages_simple` 增加可选 `seats`/`next_seat`：构造符号序列 sign₀=+1，换手处翻号；对 r̂=sign·r、V̂=sign·V 跑标准 GAE，bootstrap 按下一座次是否换手定号；返回 A=sign·Â、R=sign·R̂。数学依据（零和势能 Φ_opp≡−Φ_me，对手视角价值反号；终局 ±1 actor-centric 与该约定自洽）写进注释。seats=None 走原逻辑，`quick_train_tcp.py` 不受影响。
- simpleai 模式下所有决策点都是模型 → toPlay 恒同座次 → 符号不翻，自动退化为单代理 GAE ✓。

**B3. `train_tide_complete.py`**
- carries 从 `[obs, rstate, ret, len]` 扩为 `[obs, rstate, ret, len, seat]`（初始 reset、episode 内 reset、评估打断后强制 reset 三处都要取 `info["toPlay"]`）；GAE 调用传 `seats`/`next_seat`。
- `reward_lambda: 0.02 → 0.005`；`eval_episodes: 20 → 50`。
- `__main__` 增加 `TIDE_TRAIN_OVERRIDE` 环境变量（JSON dict 合并进 Args）——verify_small 此前靠临时手改数据类，这次机制化。
- 文档注释更新定案日期。

2. 后台发起验证训练（预计 30~40 分钟）：
   `TIDE_TRAIN_OVERRIDE='{"exp_name":"verify_reward_fix","total_timesteps":300000,"eval_episodes":20}'`（验证期评估仍用 20 局省时）→ `python train_tide_complete.py`（工作目录 Tide_train/tide_rl）。
3. 监控 stats.jsonl，判定标准：
   - **ep_ret 从 +6 平台回落到 0 附近波动**（终局主导；每方塑形累计 ≤ ~0.3）；

   - entropy 不塌零（≥0.3）；
   - vs 脚本主题胜率不出现"局长暴涨 + 胜率下滑"组合（30 万步内主要看前两条，胜率趋势作参考）。
