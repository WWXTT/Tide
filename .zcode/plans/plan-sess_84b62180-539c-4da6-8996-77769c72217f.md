# TideServer verify：服务器端到端验证套件 + 一键门禁

## 目标

给服务器一套对标 Unity 回环验证器深度的端到端验证手段：`TideServer verify`（纯 .NET 快档，含网关/子进程真实进程拓扑），配 `verify.ps1 --with-unity` 可选慢档（串行拉起 Unity 三验证器）——"每次修改完、实际运行前"的例行门禁。

探索结论（已解剖 `NetProtocolLoopbackVerifier.cs` 1293 行）：除 `[MenuItem]`/`Debug.Log`/Editor 程序集的 `AiBattleDriver` 外**全部断言逻辑可平移**——投影器/快照/握手/反问/确定性三件套全在 TideServer 编译集；唯一缺口 = 第②段需要的 `LegalActionEnumerator.cs`（纯 C#，确认无 Unity 依赖）。

## 交付物

### 1. `TideServer verify` 子命令（新目录 `TideServer/Verify/`）

**骨架**：`VerifySuite.cs`——平移 Unity 验证器的 Assert/Section 计数模式（失败不中断、一跑收全部失败面），`--quick` / `--sections V5,V6` 过滤，汇总表 + 退出码即门禁结果。

**测试客户端**：`VerifySocketClient.cs`——平移 SocketTestClient：真 TcpClient + FrameDecoder + 下行分派到公开字段（LastRoomState/Manifest/LastSnapshot/Events/PendingSelects/Errors/SnapshotsReceived），实现 IBrainChannel、可挂 NetClientBrain；另带大厅入口模式（Hello→建房/匹配/AI 填位）供网关段使用。

**分段（编号与 Unity 验证器对齐，便于交叉引用）**：

| 段 | 内容 | 手法（探索报告固化的 API） |
|---|---|---|

## 模式与预期时长

- `verify` 全量（~7 局整局+网关流程）：约 5-10 分钟
- `verify --quick`（跳 V7 与 V8 长用例，保留单局全链路+握手+反问+网关基础）：约 2 分钟
- `verify --sections …`：段过滤，调试迭代用

1. 编译集变更 + VerifySuite 骨架 + VerifySocketClient

- `TideServer verify` 全量本机跑通、0 失败、退出码 0
- `verify.ps1 --quick` 全绿；`--with-unity` 三验证器汇总解析正确（基线 941/54/262）
- 注入人为失败（临时断言）→ 退出码非零（门禁语义自证）
- 双 Unity csproj 编译保持 0 错误
