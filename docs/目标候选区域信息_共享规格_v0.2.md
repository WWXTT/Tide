## 2. 单一分组源（新增文件）

`Assets/Scripts/HotUpdate/CardCore/Effects/TargetZoneGroups.cs`：

```csharp
namespace CardCore
{
    /// <summary>候选分组：归属×区域（Indices=候选下标，引擎候选序不重排）。</summary>
    public sealed class TargetZoneGroup
    {
        public int SideRank;        // 0=己方（Chooser 视角） 1=对方
        public int ZoneRank;        // 角色0→战场1→元素池2→手牌3→墓地4→牌库5→除外6→技能栏7→发动区8→其他9
        public string Label;        // 「己方战场」等
        public List<int> Indices;   // 候选下标（升序；组内保持引擎原序）
    }

    public static class TargetZoneGrouping
    {
        public static List<TargetZoneGroup> Build(IReadOnlyList<Entity> candidates, Player chooser);
        public static List<TargetZoneGroup> Build(TargetSelectionRequest req);

        // 公开判定单源（UI/AI/脚本/LAE 共用，不得各写一份）
        public static int ZoneRankOf(Zone zone);            // 敌人没有 zone 的实体用 9=其他
        public static string ZoneWord(Zone zone);           // 复用 MatchLogRenderer.ZoneZh；角色单独
        public static int SideRankOf(Entity e, Player chooser); // Player=自身；Card=GetController()??GetOwner()
    }
}
```

规则（**唯一权威**，与 UI 规格 v0.1 一致）：

1. 归属：`chooser` 己方；`Card` 用 `GetController() ?? GetOwner()` 比较；`Player` 用自身；
   `chooser==null` 按 P1 为己方（旧 UI 口径）。
2. 区域：`Player`→角色（0）；`Card`→`GetZone()`：战场1/元素池2/手牌3/墓地4/牌库5/除外6/技能栏7/发动区8/其他9。
3. 组序：`(SideRank, ZoneRank, 组内首个候选下标)` 升序；**组内不重排**。
4. 标签：`(SideRank==0 ? "己方" : "对方") + ZoneWord(zone)`；角色=`"角色"`。
5. **不重排 `req.Candidates`**：`Indices` 指原下标，回传仍按原下标，`MapIndices` 语义不变。

## 5. 脚本消费口（ScriptedAi）

`targets` 令牌扩展（旧「卡 ID / hero / auto」不变）：

```
targets: "己方元素池×2"     // 该组取前 2 张（组内引擎序）
targets: "己方战场"          // 该组全部
targets: "对方墓地×1"
targets: "己方元素池×2,hero" // 可混用，按令牌顺序拼接、去重保序
```

- 令牌：`<归属><区域>[×N]`，归属∈{己方,对方}，区域∈{角色,战场,元素池,手牌,墓地,牌库,除外}（与标签同字串）。
- 解析：先按目标效果的 spec 计划取候选（`CollectSpecPlan` 每原子 `Candidates`，与人类窗口同源），
  再 `TargetZoneGrouping.Build(candidates, me)` 取该组下标 → 实体；**不得自己写 `GetZone()` 过滤**。
- `skill`/`activate`/`play` 三个动作的 `targets` 均支持；组不存在=该令牌失败并记日志（不得静默换成别的区域）；
  数量不足按实有收口。
- 动态数量（-3）仍按「目标张数=本次选的 N」自动计（上一阶段已接）。

## 6. 训练：动作特征 12→14 维（本阶段做）

### 6.1 特征定义

`LegalActionEnumerator.BuildFeatures` 追加两维（现有 [0..11] 不变）：

| 维 | 名称 | 取值 | 说明 |
|---|---|---|---|
| [12] | `targetZoneRank` | -1 / 0..9 | 首个目标的区域序（角色0→其他9）；无目标=-1 |
| [13] | `targetSideRank` | -1 / 0 / 1 | 首个目标的归属（0=己方/1=对方，枚举者视角）；无目标=-1 |

- 首个目标：`a.Targets` 非空取 `[0]`；否则 `a.Target`（Attack/Guard）；否则 null。
- 区域/归属判定复用 §2 的 `TargetZoneGrouping.ZoneRankOf` / `SideRankOf`（LAE 内不另写规则）。
- 多目标行（任意数量/动态数量子集）仍只编码首个目标的区域；其余目标经 `target2/target3` 槽位 + 观测
  `zoneKind` 可分辨（与现有「只编码前 3 个目标」同口径）。

### 6.2 常量与同步

| 位置 | 改动 |
|---|---|
| `TideObservation.NAction` | 12 → **14**（现行=14 ✓） |
| `TideObservation.LayoutVersion` | 13 → **14**（**2026-11-18 审计注：其后已被场地特殊化再升 v15/卡槽 191，现行=15**） |
| `tide_rl/tide_features.py` | `LAYOUT_VERSION = 14`、`N_ACTION_FEATURES = 14`；文件头注释同步 |
| `tide_rl/export_onnx.py` | 合成 fixture 补两列（区域/归属），type 值域注释/采样同步 |
| `docs/AI训练说明.md` | 「冻结面」布局行改为 `v14 / 动作 14 维`；历史沿革加一行（2026-11-15 目标区域特征；旧模型作废，训练未开始） |

## 7. 联机：`MsgSelectRequest` 下发分组（本阶段做）

### 7.1 协议

- 新增 DTO（`Network/IntentMessages.cs`）：

```csharp
[MemoryPackable]
public partial class MsgSelectZoneGroup
{
    [MemoryPackOrder(TagTable.MSG_Label)] public string Label; // 「己方战场」
    [MemoryPackOrder(TagTable.MSG_Start)] public int Start;   // Candidates 起始下标
    [MemoryPackOrder(TagTable.MSG_Count)] public int Count;   // 张数
}
```

- `MsgSelectRequest` 追加：

```csharp
[MemoryPackOrder(TagTable.MSelR_ZoneGroups)]
public MsgSelectZoneGroup[] ZoneGroups; // null/空=不分组（旧行为）
```

- `TagTable`：**不手改**——把 4 个新字段加进
  `Assets/Editor/配置/RefreshMemoryPackOrder.cs` 的 `GetTagDefinitions()`，运行
  `Tools/刷新属性排序（新增序列化字段时使用）` 重新生成。Unity 被占用无法跑菜单时，可按表头同款
  `Murmur32("类.属性", 0x53796E67) & 0x7FFFFFFF` 计算后按生成格式插入，并在交付说明里注明。
- `NetworkProtocol.Version` 19 → **20**（`IsCompatible` 严格相等，旧端互拒，无兼容层）。
- `docs/网络协议.md`：标题版本、`ProtocolVersion` 行、新增 v20 条目（`MsgSelectRequest.ZoneGroups`）。

### 7.2 服务端下发

`NetworkTargetSelector.SelectAsync`：`MsgSelectRequest.ZoneGroups = request.ZoneGroups?.Select(...)`；
`request.ZoneGroups` 由 §3 的 `RequestAsync` 已算好；为空则不下发（旧行为）。

### 7.3 客户端渲染

- `BattleScreen.NetSelectAsync`：`req.Max > 1` 分支把 `req.ZoneGroups` 传给
  `RegionTargetSelector.SelectIndicesAsync(...)` 的新重载。
- `RegionTargetSelector` 新增可选参数：

```csharp
SelectIndicesAsync(labels, min, max, title, hint, allowCancel, timeout,
    IReadOnlyList<(string label, int start, int count)> zoneGroups = null)
```

  有 groups 时按统一规则插 `Isolation` 隔断（与本地同款：首端只右列/组间双列/尾端只左列），
  条目仍是最小卡面（网络路径无实体）；`(x/N)`/确定键/回传下标口径不变。
- 单目标（`max <= 1`）不分组，保持现状。

### 7.4 验证器

`NetProtocolLoopbackVerifier` 增加一条：带 `ZoneGroups` 的请求往返后，客户端收到的
`Label/Start/Count` 与服务端一致，且 `SelectResponse.Indices` 仍指向原候选下标。
