## 0. 决策摘要

1. **移除三教师路线**：不再训练"红/绿/蓝专精教师 → 过 teacher gate → 蒸馏学生"。四次绿专精（最远 102,656 步）+ 一次带交棒实验全部 0 过门；红 75k 六格 49.3%（低于脚本基线 ~58%）；该路线不再产出。

4. **不再有"教师门"**：门改为"BC 达到脚本水平 → DAgger/PPO 超过脚本 → 学生 18 格认证"。

## 3. 新路线：脚本示范 → BC → 防遗忘 → DAgger → 混合对手

### 3.1 数据（脚本示范）

- **口径澄清**：采集就是**脚本对脚本**（`opponent="script"` → `ResetScriptGame`，双方 `SimpleAI(AutoMatch(各自卡组))` 整局自动打完）。`modelTheme` 只是给「学习者侧」贴标签（判胜负/分组/座位），**没有神经模型参与**；`ScriptBcRecorder` 九个拦截点双方都命中，所以一局实际录了**两侧**的决策步（bin 带 `seat`）。
- 覆盖矩阵（按格采样，固定种子族）：`deck`（学习者侧卡组）× `opp`（对手主题）× `seat`（0/1）× N 局；先绿只跑 `deck=green`，即 `green × {red,green,blue} × {P1,P2}` = **6 格**。
- 命令：`distill collect --decks green --games-per-deck 900 --seed 20261128 --project-path C:\UnityProject\tide_s3_probe`（≈900 局、每格 150 局；实测单局 bin ~7~13MB / ~6s，先 900 局做首轮 BC，G2 通过再扩到 2,100）。
- 先绿的理由：BC 标签只对采过的卡组有效；三套一起采会稀释绿的样本，且 shard 闸的归根覆盖率会被红/蓝摊薄。
- 产物：`bc_<gid>.bin/.meta.json` → npz shard（`chosen_card_id` 直比卡 ID）。
- 闸（G1，2026-11-28 实测）：`verify-shard` **PASS**（归根施放 **3,368 步**）；**未匹配率 10.05%**（9,754/97,059，未达 <5% 目标，红格 15.9%/19.1% 最高——疑似响应窗动作未录，v1 限制）；**线内局 82.9%**（746/900；绿镜 150/150，红 117/101，蓝 116/112）。处理：未匹配步按 `chosen=-1` 零权重剔除，先按 90% 标签开训；若 G2 不达标再补录制 v2。
- **信息不对称检查**：逐项核对脚本决策依赖的信息是否都在模型观测里（牌库顺序、隐藏手牌、费用来源）；缺一项就先补观测，否则 BC 会学成"猜"。

### 3.2 纯 BC（先不接 PPO）

- 训练：`distill train --loss ce`（macro 选中行交叉熵），按局切 5% 验证集。
- **方案 A 加权（2026-11-28 用户定）**：按「线是否真的打出来」给步权重，不做局级过滤——命中 `--line-cards`（绿默认 `C_D1A00009` 归根）的局=1.0，其余脚本兜底步=`--fallback-weight`（默认 0.2）。保留坏手牌覆盖，只降低兜底对梯度的占比。线判据用 `chosen_card_id`（施放出来），不是「入手」。
- 指标：held-out 选中行准确率、逐格动作分布（尤其 `cast_genel` 步）。
- 评估：直接 6 格（**不启用任何脚本拐杖**；交棒代码已在 §2 C 删除），48 局/对、种子 20261122。
- 闸（G2）：
  - 绿镜 P1 ≥ 脚本基线的 90%（≥87%）；
  - 对红 P1 ≥ 55%；
  - 绿六格总胜率 ≥45%；
  - `cast_genel` 局占比 ≥ 脚本的 60%。
- 到不了 G2 ⇒ 先修观测/动作映射，不进 PPO。

### 3.3 防遗忘（这是本次必须新建的部分）

现状：`train_tide_complete.py` **无 KL 锚、无示范回放**；`distill_student.py` 头注明确"不含 PPO 微调与教师 KL 锚"。直接接现有 PPO，克隆行为会被磨掉（机制见 §6）。

要加的三件：

1. **KL 锚**：`loss += β · KL(π ‖ π_BC)`，β 0.5 → 0.05 线性退火；`π_BC` 为 BC checkpoint 冻结副本（新增 `--bc-anchor <msgpack>`、`--kl-coef`）。
2. **示范回放**：每个 PPO 批混 5~20% 脚本 `(obs, chosen_row)` 做 CE 辅助损失，权重随训练退火到 0（新增 `--demo-shard <npz>`、`--demo-frac`）。
3. **起步期约束**：前 20k 步 `ent_coef` 0.05 → 0.01、LR 减半；确认行为不掉再放开。

闸（G3，50k 处判）：
- `cast_genel`/T5 率 ≥ BC 初始的 **80%**；
- 六格不得连续两次低于 BC 初始 **−10pp**；
- 触发即回滚上一 ckpt 并加 KL β。

### 3.4 DAgger（2 轮，**需要新建脚本标注口**）

现状：`distill collect --actor student` 的标签源是**教师 checkpoint**（`sorted(teachers)`），教师路线删除后不可用。
要新建：student 跑局时，让 SimpleAI 在同一状态只**决策、不 Apply**，取动作行写入 shard（复用 `ScriptBcRecorder` 的行匹配逻辑，新增 `--actor dagger-script`）。

- 用当前 student 跑局，脚本在同一状态标动作，补齐 BC 没见过的状态。
- 每轮：采 1k 局 → 混 50% 旧 shard 重训 CE → 6 格评估。
- 闸（G4，T1）：六格每格 Δ≥0、`Δ_agg ≥ +5`（对 `script_baseline_20261122`）。

### 3.5 从绿 BC 直接续训三套（**B 路线优先**，2026-11-28 用户定）

- **合并方式定案**：不做独立教师蒸馏，直接从**绿 BC 的权重**出发，混合三套（绿/红/蓝）继续 PPO；绿用 KL 锚（锚到 BC 权重）+ 示范回放保住行为，红/蓝靠 PPO 学各自的执行。
- 对手池：`current`（脚本）/`themes`/`checkpoints` 混合，而非纯自对弈；自对弈只做精炼。
- PPO 继续带 KL 锚 + 示范回放（衰减）；每 25k 跑 6 格 + 行为门。
- 闸（G5，T2）：每格 Δ≥+5、`Δ_agg ≥ +10`，连续 2 次评估稳定。
- **回退条件（A 路线）**：若 KL 锚加到 β≥0.5 仍出现「绿行为保持率 <80%」或「六格连续两次低于 BC 初始 −10pp」，判 B 不稳，转 A——三个独立产物（绿 BC / 红 PPO / 蓝 PPO）→ `distill_student.py` 的教师标签蒸馏（需从 git 恢复 teacher 路径）。
- 红线：A 路线的教师**不再有 T1/T2 门**，只要“比脚本强或够用”即可当标签源。

## 4. 读法：允许牺牲当前最优

- **不以单点胜率早停**。每个阶段固定读三样：六格逐格胜率、`cast_genel`/T5 率、链局占比。
- **定义基线 S0** = BC 完成时的六格读数。训练期间允许掉到 S0−10pp；连续 2 次评估低于 S0−10pp，或行为门 <80% ⇒ 回滚 + 加 KL。
- 胜率上升但行为门崩 = **不算通过**（这正是现行配方的问题）。
- 所有对照必须同 init / 同种子 / 同 6 格协议；跨执行器的数不比较。

## 6. 风险与对策

| 风险 | 表现 | 对策 |
|---|---|---|
| **灾难性遗忘** | BC 后 50k 内 T5 归零、胜率先跌后不回升 | KL 锚 + 示范回放 + 起步低熵/低 LR；行为门回滚 |
| BC 天花板 = 脚本 | 六格停在 Δ≈0，过不了 T2 | 明确 BC 只是 init；DAgger/PPO 负责超越 |
| 脚本 P2 弱 | 绿 P2 基线仅 28.3%，克隆后同样弱 | P2 单独看，DAgger 时对 P2 状态加权 |
| 信息不对称 | BC 准确率上不去、评估远低于脚本 | P1 先做观测核对，缺信息先补观测 |
| 未匹配动作 | 10.9% 步丢标签 | 采集端修匹配（响应窗外/引擎拒绝），目标 <5% |
| 对手漂移 | 自对弈后对脚本胜率下降 | 混合对手池 + 定期脚本评测 |
| 基线失效 | 任何卡/费用改动都会让 Δ 不可比 | 本轮**冻结卡表**；改卡即重测基线并换 era |
