# 协议 v19 · 落格坐标权威化 修改计划

> 2026-11-12 · 联机实测缺陷「双方生物显示位置不一致」的完整修复方案
> 目标仓库：Tide（Unity 客户端 + TideServer 共享 CardCore 源）
> 结论：**这不是渲染层问题，是网络位置权威分裂**。必须让「落格坐标」成为服务端权威数据，随 intent 上行、随快照下行。

---

## 1. 背景与根因

### 1.1 现象

联机对战中，同一只生物在两名玩家的屏幕上落在不同格；重连后位置还会变。实测日志（[logF.txt:L22186](../.ztmp/logF.txt#L22186)）：

```text
17:36:33.833 [HandPlay] 网络永久物选格：余烬 → (4,2)（钉随快照生效）
```

### 1.2 当前数据流

```text
玩家选格（观察者坐标）
  → NetCellPins.Pin(RuntimeId, x, z)        // 只写本地，不下发
  → MsgIntentPlayCard（无 CellX/CellZ）     // 服务端不知道玩家选哪格
  → 服务端 GameActions.PlayCard
  → BoardState.AssignCells → first-free     // 服务端按列表序找第一个空格
  → MsgGameStateSync（ZoneCards 列表序，无坐标）
  → 房主端 BuildNet：己方优先读 NetCellPins（选格）
  → 对手端 BuildNet：无钉子，只能按 first-free 重建
```

### 1.3 代码证据

| 位置 | 现状 |
|---|---|
| [IntentMessages.cs:L15-L17](../Assets/Scripts/HotUpdate/CardCore/Network/IntentMessages.cs#L15-L17) | 注释明确「快照不承载棋盘坐标（位置权威=客户端表现层）……无需协议带格」 |
| [RuntimeCardStateDTO.cs:L77-L106](../Assets/Scripts/HotUpdate/CardCore/Serialization/RuntimeCardStateDTO.cs#L77-L106) | `SerializableRuntimeCardState` 没有 X/Z 字段 |
| [BattleViewData.cs:L505-L563](../Assets/Scripts/HotUpdate/UI/Screens/BattleViewData.cs#L505-L563) | 己方单位优先 `NetCellPins`；对手单位按 `UnitCells(1)` first-free |
| [BoardState.cs:L80-L103](../Assets/Scripts/HotUpdate/CardCore/Board/BoardState.cs#L80-L103)、[L176-L190](../Assets/Scripts/HotUpdate/CardCore/Board/BoardState.cs#L176-L190) | 服务端只按 first-free 分配，没有收到客户端选格 |
| [BattleScreen.Net.cs:L607-L611](../Assets/Scripts/HotUpdate/UI/Screens/BattleScreen.Net.cs#L607-L611) | 选格后只写 `NetCellPins`，`MsgIntentPlayCard` 不带格 |

### 1.4 具体错位

本局第一个生物 `余烬` 玩家选 `(4,2)`；服务端 `BoardLayout.UnitCells(0)` 的 first-free 首格是 `(2,2)`：

- 房主屏：`余烬` 在 `(4,2)`（本地钉格）
- 服务端：`余烬` 在 `(2,2)`（first-free，规则权威）
- 对手屏：按 `(2,2)` 的镜像格 `(5,4)` 重建

第二只 `火苗 (3,2)` 恰好与 first-free 重合；第三只 `火苗 (2,2)` 又与 first-free `(4,2)` 错开——最终两张生物的位置在两边“互换”。

### 1.5 严重性

这不只是画面不同步：

- 服务端的攻击距离、邻接、光环、碾压、目标合法域都按 `(2,2)` 计算；
- 房主屏却按 `(4,2)` 理解，会出现“我看着能打到/相邻，服务端说不能”；
- 重连/晚加入只靠快照，选格钉全部丢失，位置回 first-free；
- 后续 `MoveUnit` 联机、观战逐事件演出都会被同一个缺口卡住。

## 2. 目标与非目标

### 2.1 目标

1. 落格坐标成为**服务端权威**：玩家选格随 intent 上行，服务端校验并钉格。
2. 快照携带每张盘面卡的**绝对棋盘坐标**，双方客户端都按快照渲染。
3. 保留 2026-10-28 的「网络选格」交互，不退回自动 first-free。
4. 观战、重连、AI 填位、衍生物生成、回放剧本使用同一套坐标。
5. 协议升 v19，旧端显式互拒（与项目既有「无兼容层」策略一致）。

### 2.2 非目标

- 不实现联机 `MoveUnit`（本次只把坐标通道打通，移动后续再接）。
- 不改变棋盘布局 `BoardLayout` / `MirrorSeat` 的几何定义。
- 不改变本地单机对局的 `BoardState` 行为。
- 不改变战报行流、演出指令（`BattleFxOp`）的数据面。

---

## 3. 方案总览

### 3.1 坐标语言

| 层 | 坐标 | 说明 |
|---|---|---|
| 服务端 `BoardState` | **绝对坐标** | `BoardLayout` 的 0..6；P1 下半场 z0..z2，P2 上半场 z4..z6 |
| 协议（intent / snapshot） | **绝对坐标** | 新增字段全部用绝对坐标，避免“谁看谁”的歧义 |
| 客户端 `BattleViewData` | **观察者坐标** | 己方恒在下半场（P1 布局）；`ViewerSeat==1` 时用 `BoardLayout.MirrorSeat` 把绝对坐标翻到观察者视角 |

### 3.2 数据流（修后）

```text
玩家选格（观察者坐标）
  → 本地换算绝对坐标（ViewerSeat==1 ? MirrorSeat : 原值）
  → MsgIntentPlayCard{ CellX, CellZ }         // v19 新增
  → 服务端校验：己方单位格 + 空格
  → GameActions.PlayCard
  → BoardState.PinCard(card, CellX, CellZ)    // 服务端权威钉格
  → NetSnapshotBuilder 填 CellX/CellZ（绝对）
  → MsgGameStateSync
  → 客户端 BuildNet：绝对坐标 → 观察者坐标（ViewerSeat==1 ? MirrorSeat : 原值）
  → BattleViewData.X/Z → 3D 摆位
```

### 3.3 不变式

1. 服务端 `BoardState.TryGetCell(card)` 与快照 `CellX/CellZ` 恒一致。
2. 任一客户端看到的卡位 = `ViewerSeat==1 ? MirrorSeat(服务端格) : 服务端格`。
3. 同一张卡在两台客户端上的**相对格位**一致（各自下半场为“己方”）。
4. `NetCellPins` 只作为“快照无坐标”的兜底，不再覆盖服务端坐标。

## 5. 服务端改动

### 5.1 `NetworkIntentApplier` 增加棋盘参数与校验

`Assets/Scripts/HotUpdate/CardCore/Network/NetworkIntentApplier.cs`

1. `using GameBoard;`
2. 方法签名：

```csharp
public static bool Apply(GameCore core, int seat, NetworkMessage msg,
    out string error, BoardState board = null)
```

3. `IntentPlayCard` 分支，在 `PlayCard/PlayCardInResponse` 之前校验选格：

```csharp
// v19：玩家选格（绝对坐标）——仅永久物携带；服务端权威校验
if (board != null && intent.CellX >= 0)
{
    if (BoardLayout.RoleOf(intent.CellX, intent.CellZ) != CellRole.Unit
        || BoardLayout.OwnerOf(intent.CellX, intent.CellZ) != seat
        || board.CardAt(intent.CellX, intent.CellZ) != null)
    {
        error = $"非法落格：({intent.CellX},{intent.CellZ}) 非己方空格";
        return false;
    }
}
```

4. 出牌成功后钉格（只对战场永久物，场地卡/法术跳过）：

```csharp
bool ok = GameActions.PlayCard(...);
if (ok && board != null && intent.CellX >= 0
    && card.GetZone() == Zone.Battlefield && !card.IsFieldCard())
{
    board.PinCard(card, intent.CellX, intent.CellZ);
}
return Ok(ok, reason, out error);
```

> **响应出牌分支同样收口**：现有代码在 `PlayCardInResponse` 分支直接 `return Ok(...)`。实施时把两个分支都改成先求 `ok`，再走同一个“成功后 PinCard”收口（响应出牌通常为法术、`CellX=-1`，但不要依赖这个假设）。
> `PinCard` 只在 `card.GetZone()==Battlefield && !IsFieldCard()` 时调用，避免场地卡被钉到单位格。

> 说明：`PinCard` 内部会 `Resync`，占用/邻接/光环/攻击距离立即按新格派生。校验在出牌前完成，失败无副作用。
> 场地卡由 `BoardState` 固定落 `FieldCell`，客户端不送格（-1）；法术不落格。

## 6. 客户端改动

### 6.1 发送选格：`BattleScreen.Net.cs`

`Assets/Scripts/HotUpdate/UI/Screens/BattleScreen.Net.cs`

1. **不要**把 `NetPickUnitCellAsync` 改成返回 `(int,int)?`：那是 `UniTask<Nullable<ValueTuple<int,int>>>`，
   会引入新的 AOT 值类型泛型组合（本项目明确「异步口不用元组返回」）。用两个 int 字段带出结果，
   返回值仍为 `UniTask<bool>`（现有 AOT 锚已覆盖）。

```csharp
private int _netPickX = -1, _netPickZ = -1;

private async UniTask<bool> NetPickUnitCellAsync(BattleCardView card)
{
    var options = NetEmptyUnitCells();
    if (options.Count == 0) { _toast.Show("单位区已满——无法打出"); return false; }

    _choreo?.CancelTargeting();
    _selfFan?.SetVisible(false);
    var origin = BoardLayout.CharacterCell(0);
    var picked = await PickCellAsync(BattleBoardGrid.WorldPositionOf(origin.x, origin.z), options);
    if (picked == null)
    {
        RestoreFanNet();
        return false;
    }
    _netPickX = picked.Opt.X;
    _netPickZ = picked.Opt.Z;
    NetCellPins.Pin(card.RuntimeId, _netPickX, _netPickZ); // 兜底：快照无坐标时用
    RestoreFanNet();
    Debug.Log($"[HandPlay] 网络永久物选格：{card.Name} → ({_netPickX},{_netPickZ})");
    return true;
}
```

2. `NetUseCardAsync` 收集选格并写进 intent：


### 6.2 渲染：`BattleViewData.cs`

`Assets/Scripts/HotUpdate/UI/Screens/BattleViewData.cs` → `FillUnitsNet` / `FillLandsNet`

**原则**：有快照坐标就一律用快照坐标；没有才走旧 first-free/钉格 fallback。

`FillUnitsNet` 增加 `viewerSeat` 参数；核心逻辑：

```csharp
private static void FillUnitsNet(List<BattleCardView> list, MsgGameStateSync snap,
    int seat, bool ownerIsOpponent, int viewerSeat)
{
    var units = ZoneCardsNet(snap, seat, Zone.Battlefield);
    bool hasCells = units.Any(u => u != null && u.CellX >= 0);

    if (hasCells)
    {
        foreach (var s in units)
        {
            var view = FromRuntime(s, null, ownerIsOpponent);
            if (s.CellX >= 0)
            {
                int x = s.CellX, z = s.CellZ;
                if (viewerSeat == 1) (x, z) = BoardLayout.MirrorSeat(x, z); // 绝对→观察者
                view.X = x; view.Z = z;
            }
            list.Add(view);
        }
        return;
    }

    // ---- 以下为旧快照 fallback（无 CellX/CellZ）----
    // 保留现有钉格/UnitCells first-free 逻辑；NetCellPins 只在此分支消费
}
```

`FillLandsNet` 同理：

```csharp
foreach (var s in lands)
{
    var view = FromRuntime(s, null, ownerIsOpponent);
    if (s.CellX >= 0)
    {
        int x = s.CellX, z = s.CellZ;
        if (viewerSeat == 1) (x, z) = BoardLayout.MirrorSeat(x, z);
        view.X = x; view.Z = z;
    }
    else if (s.LockedColor >= 0)
    {
        var cell = BoardLayout.LandCellOfElement(ownerIsOpponent ? 1 : 0, (ManaType)s.LockedColor);
        if (cell.x >= 0) { view.X = cell.x; view.Z = cell.z; }
    }
    list.Add(view);
}
```

调用处：

```csharp
FillUnitsNet(d.SelfUnits, snap, me, ownerIsOpponent: false, viewerSeat: me);
FillUnitsNet(d.OppUnits, snap, them, ownerIsOpponent: true, viewerSeat: me);
FillLandsNet(d.SelfLands, snap, me, ownerIsOpponent: false, viewerSeat: me);
FillLandsNet(d.OppLands, snap, them, ownerIsOpponent: true, viewerSeat: me);
```

> `NetCellPins` 保留：仅在 `hasCells == false` 的旧快照路径生效；v19 正常路径不再读取，避免房主端钉子覆盖服务端格。

### 6.3 选格候选与视图一致性

`NetEmptyUnitCells` 继续按观察者坐标 `BoardLayout.UnitCells(0)` 生成候选；因为 `BuildNet` 已把快照坐标翻到观察者坐标，`SelfUnits` 的 X/Z 与候选同一语言，占格判断无需改。

### 6.4 观战/回放

- 观战 `ViewerSeat == -1`：`FillUnitsNet` 不做镜像，按绝对坐标渲染；与现有观战/全量快照口径一致。
- `BattleFilm`：`BattleViewData` 的 X/Z 已是观察者坐标；`LocalFilmSource`/`NetFilmSource`/`ReplayFilmSource` 无需改格式，回放自动拿到正确格位。
- 终局 `MatchLogFull` 不受影响。

## 7. 测试与验证

### 7.1 服务端单元/回环测试（新增 V13）

建议新增 `TideServer/Verify/SectionCells.cs`，注册到 `VerifySuite` 的 `V13`（`InQuick = true`），覆盖：

2. **快照绝对坐标**：`NetSnapshotBuilder.Build(core, 0, false, board)` 中该卡 `CellX==4 && CellZ==2`。
3. **观察者镜像**：
   - viewer 0：`BuildNet` 该卡 `X==4 && Z==2`；
   - viewer 1：`BuildNet` 同一卡在 `OppUnits` 中 `X==3 && Z==4`（`MirrorSeat(4,2)`）。
4. **intent 校验**：
   - `MsgIntentPlayCard{CellX=4,CellZ=2}` 被接受并落 `(4,2)`；
   - 对手单位格/已占格/越界格被拒，返回 Error 文案；
   - `CellX=-1` 保持旧 first-free 行为（AI/兼容路径）。
5. **非法客户端**：P2 发送观察者坐标未镜像（例如 P2 发 `(4,2)` 但那是 P1 格）被拒，防回归。

### 7.2 协议/线格式

- `TideServer verify` 全量（含 V1/V6/V7/V11/V12）。
- 版本闸：旧 v18 客户端/服务器互连应回显式「协议不兼容」Error，不得半开。
- `MsgGameStateSync` 帧往返：新增字段可空/默认 -1，序列化字节稳定。

### 7.3 双模拟器实测

设备：`127.0.0.1:16384` / `127.0.0.1:16416`（MuMu）。

1. 建房/排位进入对局。
2. P1 第一只生物选**非 first-free** 格 `(4,2)`（本局 first-free 为 `(2,2)`）。
3. 断言：
   - 服务端日志/测试：`TryGetCell == (4,2)`；
   - P1 屏：该生物在 `(4,2)`（下方）；
   - P2 屏：同一生物在 `(3,4)`（上方，`MirrorSeat(4,2)`）；
   - 两边是同一个相对格，不再互换。
4. 再打两只：`(5,2)`、`(2,2)`，逐只核对。
5. 衍生物/token 生成：两边同格。
6. 重连：P2 杀进程重进，位置仍为服务端钉格。
7. 观战：第三客户端/双 AI 观战，位置一致。
8. AOT 门禁：`dotnet run --project tools/AotAudit ...` exit 0。

### 7.4 验收日志（建议临时加，验收后可降级）

- 服务端钉格：

```text

```

- 客户端渲染：


## 9. 风险与回滚

| 风险 | 处理 |
|---|---|
| 忘记跑 TagTable 生成器，编译缺常量 | 按 §4.4 执行菜单；生成器会守门（碰撞/删常量/解析不全直接报错） |
| P2 客户端把观察者坐标直接上行，服务端拒/落错 | §6.1 明确 `ViewerSeat==1` 时 `MirrorSeat`；V13 加 P2 用例 |
| 房主端仍读 `NetCellPins`，覆盖服务端格 | §6.2 规定有快照坐标时不读钉子；只在 fallback 路径读 |
| `PinCard` 在 `PlayCard` 后多一次 Resync | Resync 是纯函数 + 幂等；无事件副作用，可接受 |
| 旧存档/旧剧本 JSON 缺字段 | 新字段默认 -1；`TideJson`/MemoryPack 反序列化缺省安全 |
| 协议升级导致旧端无法联机 | 项目既定「无兼容层」；同版本发布，版本闸给明确报错 |
| 观战 `ViewerSeat=-1` 镜像错误 | 只在 `viewerSeat==1` 时镜像；-1/0 保持绝对坐标 |
| 回放剧本位置漂移 | 快照坐标进入 `BattleViewData`，三种 FilmSource 同源；V13 加回放断言 |

**回滚**：整体 revert 本提交（协议 v19→v18、字段/标签/客户端改动一起回退），服务器与 APK 同步回旧版。不要只回滚一端。
