## 2. 三相仪典：改触发 + 降价

### 2.1 现状

- 卡：[训练·三相仪典台](../Assets/Data/TrainingData/TrainingCards.json)（`C_84D035FE`，Enchantment·场地卡，`tags: 训练池`，
  **费 9 灰**，效果 `8367F795` → 原子 `301a29ba`，`str="ElementConversion"`）。
- 光环：`ElementConversion`（光环表里叫**三相仪典**，`AtomicEffectType.AuraTriPhase`，[RuleAuraSystem.cs:214/315](../Assets/Scripts/HotUpdate/CardCore/Effects/RuleAuraSystem.cs#L214)）。
- 现机制（[RuleAuraSystem.cs:540-590](../Assets/Scripts/HotUpdate/CardCore/Effects/RuleAuraSystem.cs#L540)）：
  按**支付账单**逐色累计，**某一颜色累计满 3 点** → `GrantTrinity` 给红/蓝/绿**各 +1** 临时钱包。

### 2.2 目标机制（用户口径）

> **同一笔支付**里付了**红、蓝、绿各 1 点** → 获得 **1 点彩元素（Any）**；该光环的**费用降到 3**。

- 触发记账：在**单笔支付**内按色记账，三种颜色都 ≥1 时各扣 1（本轮清零），发 `Any +1`（`CreditTempWallet(Any)`）；
  **不跨笔累计**（现机制是逐色跨笔累计，这次改掉）。
- 一笔里付了两轮 1/1/1（如 6 点）→ 触发两次。
- 事件沿用现口径（`ElementPoolGainEvent` / `AddManaEvent` 按现有路由）；
- 光环 id / 名称 / 原子（`AuraTriPhase`）不变，**只改触发条件与产出**；原子计价随之调整。
- **描述文本同批改明**：卡面/效果描述、`原子表_光环` 的 `DisplayName`（现文案是"某色累计 3 点 → 三色各 +1"口径，必须一起改）。

### 2.3 费用 9 → 3 怎么落

**不能手填 `costList`**（工程铁律：新卡/改动的费用必须由 `CardCostService` / `CostDerivationService` 从内容推导）。
所以"降到 3"只有两条路：

1. **改推导让结果=3**（推荐）：修 `AuraTriPhase` 的计价档（`AtomTier`/时机系数/光环单价）使其推导值 = 3，
   `costList` 由导出/`EnsureCost` 写回；
2. 若推导口径无法适配（原子价是全局的，会连带影响其它带该原子的卡）→ 需要单列一条计价规则（"三色各1→1彩" 的定价），
   走 `ValueSystemConfig` + 推导代码，仍不许手填。

> 落地后必须跑 `dotnet run --project TideSim -- --cost-audit`（会读三池并现推对账），并给出"改前/改后 costList"证据。
