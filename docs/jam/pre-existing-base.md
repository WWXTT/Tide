# 赛前自研基础清单（tag `jam-baseline-20261001` 及之前）

**定位声明**：以下为赛前已开发完成的自研引擎/框架/研究管线，本次比赛期间作为基础设施使用（类比"使用 Unity 作为引擎"），不计入 21 天工作量。参赛游戏本体（玩法设计落地、卡牌内容、主题表现）为比赛期内新建。

| 模块 | 说明 | 性质 |
|---|---|---|
| Tide 规则引擎层 | LayerEngine / 事件单点分发 / 效果系统框架（配置驱动，见根目录设计文稿.md） | 自研卡牌游戏框架（中间件） |
| 框架原型验证 | 赛期前在框架上做过的卡牌配置、效果实现与自动化测试（git 历史可见，如实申报为原型验证） | 原型，非参赛本体 |
| HexMap.ECS | 六角战场 ECS 层 | 自研引擎模块 |
| dbdrp | 基于 Unity URP 17.5 的渲染管线 fork（自维护层，上游为 Unity） | 自研 fork（上游第三方） |
| TideServer | 独立权威服务器（网关 + 每局一进程） | 自研基础设施 |
| tide_rl 训练管线 | RL 训练环境与动作空间设计（源自赛前 Yu-Gi-Oh 相关研究） | 自研研究管线 |

## RL 模型特别注意

- **可复用**：研究方法、训练管线、网络/动作空间设计。
- **不可直接分发**：在 Yu-Gi-Oh（Konami IP）数据上训练出的模型权重不得随参赛作品分发；参赛 AI 对手必须在本游戏环境上重新训练（tide_rl v2c 已于 2026-09-30 启动重训）。
- 台账登记：模型用途、训练数据来源（本游戏对局）、训练起止日期，记入 [ai-usage.md](ai-usage.md)。

## 与官方规则的对应

规则允许"预先制作的引擎、框架和模板"（需署名/申报）。本清单即该项申报内容；第三方部分另见 [third-party.md](third-party.md)。
