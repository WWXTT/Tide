# 动态数量规格（v0.1 · 2026-11-14）

> 用户口径：效果组合界面 `placeholder` 的 `dd-num` 下拉，在 1/2/3/全部 之外增加「动态」。
> 开启后作用目标在**发动时**由玩家选数量，效果费用按该数量计算；**动态数量不享受
> PricingTier 数量档减免，费用 = 原子基础费 × 实际目标数**（1:1）。

## 1. 数据哨兵

| 值 | 语义 | 费用 |
|---|---|---|
| `1/2/3` | 固定 N 个目标 | 吃 PricingTier：1× / 1.5× / 2× |
| `0` | 域内全取 | 吃 PricingTier 全部档 3× |
| `-1` | 旧「任意数量」（原子计 0 费，历史数据） | 0（不动） |
| **`-3`** | **动态数量**（`AtomicEffectInstance.DynamicTargetCount`） | **基础 × 实际 N（不进档位）** |
| `-2` | 未声明 | 回落效果级 |

落盘：`AtomicEffectEntry.count = -3`（效果级 `CardEffectData.TargetCount = -3` 不成立，
装载归一为 -2）。逐原子专用。

运行时解析值存 `AtomicEffectInstance.ResolvedDynamicCount`（>0=本次发动已选 N；
0=未解析，计价/执行都按 1 兜底）。该字段是运行时状态，不入网络 DTO。

## 2. 开放面（只在主动效果的主干原子）

- 仅 `EffectActivationType.Voluntary`（法术/主动技能）——触发式/自动效果的元素费在构筑期
  已计入卡价，没有发动时二次收费时点。转换器装载时对非主动效果把 `-3` 收为 1（告警）。
- 仅效果组合界面主干预选行（奖励/代价原子不收）。
- 召唤衍生物（SummonToken）不收：召唤数量由自身 `num` 数量档承载。
- `NoWhole` 行不收（动态同样能选到全取，等价整体档）。
- 与「目标随机」「结算期选择（defer=1）」互斥：动态必须在**扣费前**选定目标数，
  合成器选中动态会强制关闭随机与 defer，转换器再兜底归一。

## 3. 交互

`dd-num` 选项：1 / 2 / 3 / 全部 / **动态**。选动态后：
- 随机 Toggle 与「目标选择=预选/结算期」下拉禁用（强制预选）。
- 若效果当前是「自动」，选中动态时自动切为「主动」并提示（动态必须发动时计费）；
  结界宿主 / 光环形态 / 引擎钉档无法切主动 → 提示并保持 1 个目标。
- 发动时目标窗允许选 1..候选数（MinCount=1，MaxCount=候选数），标题注明
  「动态数量：选几个收几份费用」。
- 单候选/Self 域自动取 1（不弹窗）。

## 4. 收费/执行链

```
声明期收集（CollectDeclarationTargetsAsync）
  → DeclarationTargets { Targets, DynamicCounts[原子下标]=N }
  → 计价：GetCardCost / SpellCastAnchor / DeriveElementCosts 应用 DynamicCounts
         QuantityFactor(动态) = N（不吃 TargetCountFactor 档位）
  → 扣费：法术 cast 账单；主动效果/技能经 CanActivate/ExecuteAsync 现付
  → 执行：EffectExecutor 先 ApplyDynamicCounts，再按 N 消费预选队列（选几个打几个）
```

- 未解析（AI/兜底/构筑预览）：`QuantityFactor = 1`，选择按 1 个目标——**precheck 与实付同价**。
- 费用预览：效果组合界面按 base×1 显示，并标注「发动时按实际目标数×基础计费」。

## 5. 各路径

| 路径 | 行为 |
|---|---|
| 本地法术 | 既有声明期目标预选链（`CollectSpellDeclarationTargetsAsync`）返回计数，`PlayCard`/`PlayCardInResponse` → cast → 结算 |
| 本地主动效果 | 发动键点击后先收集目标/数量 → `ActivateEffect(targets, counts)` → 入栈；结算按 N |
| 本地英雄技能 | 同上，`ActivateHeroSkill(targets, counts)`；`TryActivate` 预检与结算同价 |
| 联机法术 | **服务器声明期预选**：收到 `IntentPlayCard` 且该模式含动态原子 → 服务器经 SelectRequest 问客户端选目标/数量 → 再走完整 PlayCard 门禁；客户端直送 targets 无计数表会被拒 |
| 联机英雄技能 | 同法术（`IntentActivateHeroSkill` 前置预选） |
| 联机单位主动效果 | 暂未接（客户端 UI 不发该 intent）；服务端显式拒绝动态效果，避免按 base×1 少收 |
| AI | 不解动态（LAE 单行 targets=null）；结算按 1 个目标、费用 base×1，与动作估值同价 |

## 6. 验证

- 无头计价用例：`.ztmp/DynCountHarness`（`dotnet run --project .ztmp/DynCountHarness`）——
  覆盖 base×N、不进 1.5/2/3 档、未解析 base、自动/随机/召唤/效果级归一、文本量词。
- 编译：`dotnet build Tide.HotUpdate.csproj`、`dotnet build Assembly-CSharp.csproj`。
- 手测：效果组合器建主动效果 → 原子 dd-num 选「动态」→ 保存；本地法术施放选 2 个目标，
  观察扣费 = 基础×2、目标实际受击 2 个。
