# 残局求解器 → 精确搜索 + 世界采样（计划 v0.1）

> 状态：**未来拓展方向**，不改变当前训练主线（PPO 自对弈 + 三脚本对手池）。
> 本文只定「方向与阶段」：定型决策、阶段划分、验收口径、负清单。
> **计划稿，不是实现状态**：阶段 1 只有探针（待验收），其余未实现。
> 最后更新：2026-11-19
>
> 定位：给训练侧补一个「可验证的最优解来源」，与策略网络互补，不替代网络。
> 求解器只回答「这个局面下有没有更优动作」，不回答「对手在想什么」（后者属对手建模，见 §6）。
>
> 标记约定：**定案** = 已拍板；**建议** = 有明确推荐但未拍板；**未决** = 需用户决策。

---

## 0. 一句话

**斩杀回合用精确搜索，斩杀之前的回合用「世界采样 + 精确搜索」；两者共用同一份合法动作定义与同一套规则代码。**

蒙特卡洛的位置在**不确定性存在的地方**（对手手牌未知、牌库未知），不在斩杀搜索内部（那里没有不确定性，采样只会加噪声）。

## 2. 定型决策

### D1 规则单源 —— 定案

合法动作一律走 `LegalActionEnumerator`，执行一律走 `LegalActionEnumerator.Apply`。
求解器**禁止**自建枚举、禁止复制规则判断。理由：两套「什么算合法」是同一类 bug 的温床，且会让求解器与训练分布悄悄错位。

### D2 回溯：先重建，后快照，且两者必须对拍 —— 定案

- 阶段 2 引入 `TurnStartSnapshot.Restore`，把「重建+重放」换成「快照恢复」。
- **重建+重放保留为黄金基准**：每个新用例必须跑一次「快照恢复 vs 重建重放」逐字段对拍（生命/区域/卡态/池/回合方/阶段）。
- 理由：快照漏掉一张注册表就会产出**假斩杀**，而这种错误在训练里不可见。对拍是唯一能抓住它的手段。

### D3 对抗用 minimax，不确定性用期望 —— 定案

- 对手的响应分支 = **对抗性**，用 `min`（他能挡必挡），不用概率平均。
- 隐藏信息（手牌/牌库）= **不确定性**，用 `E_w[·]`（对世界取期望）。
- 合成式子固定为：

```
值(首步 a) = E_{w ~ P(世界 | 公开信息)} [ min_{对手响应 r} 结果(a, r, w) ]
```

禁止把对手响应写成「按历史频率加权」——那会把「对手会针对你」错算成「对手随机出牌」。

### D4 斩杀回合不采样 —— 定案

斩杀回合里我方牌与场面全公开，没有可采样的不确定性。该回合只做精确搜索（现有 DFS）。
采样只在**斩杀之前的回合**启用：那时你不知道对手能不能挡、下回合抽什么。

### D5 先出保守下界，再出概率 —— 定案

概率需要信念模型，信念模型需要数据与对拍，链长且易错。
因此顺序固定：**先算「最小可斩杀血量」**（假设对手手里每一张可能的挡牌都会打出来），再算「斩杀成功率」。
下界不依赖任何概率假设，可以立刻给训练与决策使用。

### D6 求解器只当「辅助标签 / 评估基准」，不改奖励 —— 定案

- 不改终局 ±1，不改塑形项；
- 求解器产出两类东西：① 某局面的「最优首步」标签；② 「是否可斩」判定。
- 用途：辅助损失 / 数据筛选 / 评估对照。理由：把求解器结论直接当奖励会引入「求解器算不准时训歪」且不可回滚。

### D7 每个阶段必须能独立验收 —— 定案

每阶段交付时给出一条命令 + 一组断言，跑完即可判定成立/不成立。不许「等全套做完再验」。

## 3. 阶段

| 阶段 | 内容 | 产出 | 状态 |
|---|---|---|---|
| 1 | 本回合斩杀判定 | `--lethal-probe` | 已实现，**待验收** |
| 2 | 状态快照/回滚 | `--lethal-probe` 提速 + 对拍口 | 未实现 |
| 3a | 对手响应入搜索 | 斩杀结论从「上界」变「保证」 | 未实现 |
| 3b | 保守下界（最小可斩杀血量） | 不依赖概率的安全边界 | 未实现 |
| 4 | 世界采样（隐藏信息） | 斩杀成功率 | 未实现 |
| 5 | 训练接入 | 标签产出 + 评估对照 | 未实现 |
| 6 | 多回合延伸 | 斩杀窗口（3~5 回合） | 仅方向（§6） |

> 1–5 是本期计划；6 及以后只记方向，不进本期范围。

### 阶段 2 —— 状态快照/回滚

- 目标：把单节点开销从「重建 + k 次重放」降到「一次恢复」。
- 依据：`TurnStartSnapshot` 的恢复方案已写在源码注释里（RNG 双流检查点 / 卡态回灌 / 区域重排 / 注册表按战场重建）。
- 验收：
  1. 同局面 1000 次「采集→恢复」循环后，状态哈希与重建基准一致；
  2. 同一搜索的节点数与路线与阶段 1 完全一致（只允许变快，不允许变答案）；
  3. 单节点耗时下降（记录改造前后数字）。

### 阶段 3a —— 对手响应

- 目标：搜索里对手在响应窗不再自动让过，而是取「能挡则挡、能杀则杀」的最优响应。
- 关键：响应分支用 `EnumerateResponses`，按 `min` 剪枝；我方 `max`。
- 验收：
  1. 构造「对面对着一张守卫/响应牌」的用例，阶段 1 说能斩、阶段 3a 说不能——两者都对，只是口径不同，必须把这组差写在用例里；
  2. 求解器给出的线路，在「对手按求解器自身响应策略对抗」下依然成立。

### 阶段 3b —— 保守下界

- 目标：不采样，先给「对手必挡时还能不能斩」。
- 做法：把对手未公开手牌视为「每一张都可能是一张有效响应」，取最坏组合。
- 验收：下界结论必须是 3a 结论的子集（下界说能斩 ⇒ 3a 也说能斩），用例覆盖等号与不等号两种。

### 阶段 4 —— 世界采样

- 目标：给定公开信息，采样对手手牌与牌库序，输出斩杀成功率。
- 信念来源：**优先用对手模型自身采样**（对手池里的策略），历史频率只作冷启动先验。
- 验收：
  1. 采样数 N 从 64→256→1024，成功率估计收敛（给收敛曲线数字）；
  2. 与「对手真实手牌已知」的精确解对比，偏差在可解释范围内；
  3. 明确记录 strategy fusion 的表现：同一线路在不同世界的「事后最优」不一致时如何报告。

### 阶段 5 —— 训练接入

- 产出：`局面 → 最优首步 / 可否斩杀 / 成功率` 的标签集（离线落盘，可追溯）。
- 接入方式（建议，未决）：辅助损失 or 数据筛选 or 仅评估。
- 验收：加标签前后各跑固定局数，胜率与「斩杀浪费率」两个指标同口径对比。

## 4. 接口契约（不随阶段变化）

1. 合法动作：`LegalActionEnumerator`（唯一来源，含 512 行上限与兜底行规则）。
2. 执行：`LegalActionEnumerator.Apply` + `DrainStack`。
3. 胜负：对手生命 ≤ 0 / `IsGameOver`。
4. 随机：`InitGame(rngSeed:)` 钉种子；两条随机流（GameRng + 洗牌流）都要可重播。
5. 求解器不读写 `GameCore` 之外的状态，不依赖 Unity 运行时（TideSim 可跑）。

## 5. 负清单（明确不做）

| 不做 | 原因 |
|---|---|
| 把规则翻译成 SAT/CP 子句 | 规则已是可执行代码，翻译=复制第二份真相，必漂移 |
| 在斩杀回合用蒙特卡洛 | 无不确定性，只加噪声 |
| 用历史频率直接给动作加权 | 目标是期望胜率，不是动作频率；且频率未按公开状态条件化时是噪声 |
| 把对手响应当概率平均 | 对手是对抗的，不是随机的 |
| 求解器结论直接当奖励 | 求解器算错时不可回滚；先做标签与评估 |
| 未对拍就上快照 | 假斩杀在训练里不可见 |

## 6. 未来拓展（暂不定型）

- **多回合斩杀窗口**：把「本回合必杀」放宽到「3~5 回合内可杀」，配合牌库采样。
- **求解器当 teacher**：DAgger 式蒸馏——网络在求解器高置信局面上的偏差拿出来做校正样本。
- **反事实标注**：对同一局面枚举「首步不同」的差值，给策略梯度一个更低方差的基线。
- **与对手池联动**：世界先验直接取自 `opponent_pool` 的当前对手，而不是历史日志。
- **人类对局日志**：与 `docs/AI训练说明.md` §10（模仿学习）合流——人类线也可以被求解器打分。

## 7. 风险

| 风险 | 触发条件 | 缓解 |
|---|---|---|
| 假斩杀 | 快照恢复漏状态 | D2 对拍；重建重放保留为基准 |
| PIMC strategy fusion | 每个世界都假装知道对手手牌 | 阶段 4 显式记录；必要时收缩到「下界」口径 |
| 搜索爆炸 | 分支大、深度高 | 节点/时间预算 + 剪枝；报告节点数而非只报结论 |
| 对手模型偏差 | 世界先验与真实对手分布不符 | 用对手池在线采样，不用历史频率当长期先验 |
| 训练过拟合求解器 | 标签当唯一监督 | D6：标签只做辅助 |
