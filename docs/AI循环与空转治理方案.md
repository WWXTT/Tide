## 2. 根因

### 2.1 深潭碑链路（缺陷型循环）

1. **卡**：`深潭碑` `C_2BD6EDE2`，结界，**费用 0**，耐久 4，效果 `3442A01E`：
   「元素充盈：剩余元素差 ≥ 门槛时，回响 1：选择双方战场的一张卡，把 1 张带遗忘的临时复制加入手牌」。
2. **复制**：`EchoCopyHandler` → [TempCopyRules.CreateTemporaryCopy](<C:/UnityProject/Tide_train/Assets/Scripts/HotUpdate/CardCore/Attribute/TempCopyRules.cs>)
   做 **CardData 全量深克隆**（效果栏/引擎全保留），挂 1 层临时指示物后入手。
3. **引擎**：[BranchEngines.EvaluateManaSurplusEngines](<C:/UnityProject/Tide_train/Assets/Scripts/HotUpdate/CardCore/Effects/BranchEngines.cs>)
   每次「卡牌结算」遍历己方战场**每一个**充盈引擎各触发一次；代码注释明说
   **2026-11-13 起「无每回合次数上限」，刹车只靠「结界每次触发扣 1 点耐久」**。
4. **漏洞**：复制体是**新实例**（满耐久 + 新引擎），0 费打出去不消耗法力 → 充盈差值照样达标 →
   再触发 → 再复制。场上有 k 个碑，一次施放产 k 份复制 → **指数增长**。
   耐久这个刹车对"新实例"完全无效。
5. **根治（2026-11-18 已实施，用户拍板；同日 07:34 定稿第三版）**：充盈触发= **「己方释放法术后·仅法术」**
   （`FlushCardCastSettled` 只评估施放者本人且仅 `Cardtype.Spell`——结界/生物施放不触发；曾短暂实行「仅对手回合」第二版后即被取代）——
   自己回合的施放不再触发己方引擎，回响链在自己回合断掉；复制量上界 = 对手回合的施放次数。见 §5.1。

### 2.2 现有三道防线为什么没挡住

| 机制 | 位置 | 设计意图 | 为什么没挡住 |
|---|---|---|---|
| `MaxActionsPerTurn = 256` | TideHeadlessDriver.cs:68 | 防死循环 | 只在**第 256 步**强收，代价是每回合烧 256 步；一局 8 个回合 = 2000 步超时判负 |
| `_bannedThisTurn` + `RemoveAll` | LegalActionEnumerator.cs:349、Driver:269 | 摘除**被引擎拒绝**的动作 | 深潭碑每次 `Apply` 都**成功**，不属于"拒绝" |
| `StallDrawThreshold = 64` | Driver:76 | 只剩兜底行 64 次判和 | 深潭碑局面里 PlayCard 行有 175 个，永远不是"只剩兜底行" |
| `EnforceActionCap`（512） | LegalActionEnumerator.cs:248-266 | 截断超限动作表 | 177 行没到上限，且截断语义是"保前 511 + 末位兜底"，反而把 EndTurn 稀释到 1/177 |

### 2.3 问题分类（决定用哪一层治）

| 类型 | 例子 | 状态特征 | 该谁治 |
|---|---|---|---|
| **缺陷型（自繁殖）** | 深潭碑复制深潭碑；未来任何"复制/重放引擎"的卡 | 每一步都**有变化**（手牌 +1），永不重复 | **L0 规则/引擎**（必须修规则） |
| **合法净零循环** | 绿：牺牲地→回收墓地→铺地→再牺牲（用户 2026-11-18 指出） | 若干步后**回到同一状态**（张数净变化 0） | **L1 指纹回环** |
| **合法增长循环** | 以后的刷资源/刷计数类 | 一直增长，不重复 | **L2 回合预算** |
| **策略性重复** | 模型在某个状态反复选同一动作 | 无进展但动作表正常 | L1 + L3 |

> 关键认知：**真人靠墙钟收手，AI 没有墙钟**。所以 AI 侧需要的是「预算 + 进度」双判据，
> 而不是更小的步数上限——上限只是防炸底线。

## 3. 不变量（改动红线）

1. **不动奖励**：终局 ±1 + λ=0.005 塑形不变；不引入"循环惩罚"奖励项。
2. **不动观测/动作契约**：布局 v14 / 卡特征 116 / 动作 14 维不动 → 旧 checkpoint 可热启动（**2026-11-18 17:49 后此前提失效**：场地特殊化升 v15/卡槽 191，旧 checkpoint/ONNX/fixture 全部作废须重训，见 [AI训练说明.md](AI训练说明.md) §4）。
3. **不动卡身份**：L0 必须在**引擎侧**实现；改卡面数据会让 `深潭碑` 换内容哈希 → 在 append-only
   身份池里变成"新卡"，旧权重对该卡 embedding 作废。
4. **不动真人规则**：L1/L2 只进 headless driver（AI 对局），不影响本地对局/联机；真人侧保留墙钟。
5. **不判和**：循环触发只"收口本回合"（损失节奏），不判和——判和会催生"劣势方拖和"的 reward hack。

## 4. 方案总览

```
                        ┌─────────────────────────────┐
  一次决策（Main 相） → │ L1 指纹：回环 / 停滞？        │─是→ 收口本回合 + 本回合禁选该动作 + 标记 pruned
                        └──────────────┬──────────────┘
                                       │否
                        ┌──────────────▼──────────────┐
                        │ L2 预算：本回合动作 ≥ 60？    │─是→ 收口本回合 + 标记 pruned
                        └──────────────┬──────────────┘
                                       │否
                                    正常 Apply → 推进
  L0（规则）：充盈改「己方释放法术后触发」（结界/生物施放不触发）→ 掐死自繁殖
  L3（训练）：pruned 步走 learner 掩码剔除 + 动作表折叠 + stats 指标
```

## 5. 详细规格

### 5.1 L0：充盈触发时机 =「己方释放法术后」（已实施，定稿）

- **状态**：✅ 2026-11-18 由 DSH 直接改（不进 ZCode 计划）。当日迭代三次：
  ①「仅对手回合」（复归 11-06 前口径）→ 机制有效但蓝套崩（跨组 67.3%→10%）；
  ② 用户否决 → ③ 定稿 **「己方释放法术后」**（不限回合，只看施放者与卡型）。
- **位置**：`BranchEngines.FlushCardCastSettled`（调用点）+ `EvaluateManaSurplusEngines`（评估）。
- **实现**：连锁终点对每条施放结算记录，只评估**施放者本人**的引擎，且仅当该卡是**法术**（`Cardtype.Spell`）；
  结界/生物施放不再触发。
- **为什么能根治**：深潭碑（结界）的复制体也是结界，打出不触发 →「复制→打→再复制」断链；
  蓝套的法术（潮汐/回潮等）仍能触发自己的引擎 → 自触发节奏保留。
- **副作用**：对手的施放不再触发己方引擎（旧「双方施放·双方评估」口径），蓝套的伤害来源变少。
- **日志**：`KeywordAppliedEvent`（"元素充盈…执行奖励"）；临时调试 `[DBG-SURPLUS]` 已移除。

### 5.2 L1：无进展检测（指纹）

**指纹定义**（每次 Main 相决策后计算，忽略实例 ID；2026-11-18 实施修正为"名字+状态摘要"，原文只取名字导致正常战斗被判循环 53 次/6 局）：

```
F = hash(
  回合号,
  双方生命 + 双方角色指示物摘要（护甲/攻击弹药…）,
  双方战场/技能区永久物状态多重集（名字 + 攻/血/横置/指示物摘要，排序后）,
  双方手牌/牌库/墓地/除外 张数,
  双方元素池张数 + 横置数
)
```

- **R1 回环**：本回合内 F 与之前出现过的 F 相同（环形缓冲最近 32 个）→ 判定循环。
- **R2 停滞**：F 连续 8 次决策不变 → 判定停滞。（2026-11-18 实施说明：该分支**理论不可达**——连续重复 ⊂ 本回合内重现，R1 已先判出 cycle；保留为防御分支，`LoopStallThreshold=8`，并留了自检开关 `LoopGuardSelfTest` 可把阈值降到 1 验证检测器。）
- **触发动作**：
  1. 排干栈 → `EndTurn`（收口本回合，不判和、不改奖励）；
  2. 把触发动作的 `Signature` 加入 `_bannedThisTurn`（本回合不再出现该选项）；
  3. 打 `loop_pruned` 标记（供 L3 剪枝），并按类型计数 `loopCycle` / `loopStall`。
- **作用域**：仅 Main 相决策；响应窗口沿用现有 `StallDrawThreshold`（vs 脚本口径下响应窗本就自动让过）。
- **扫描成本**：全部是 `List.Count` + 战场排序（≤20 张），单步 < 0.1ms。

> 为什么指纹不含手牌内容：成本高且易误判（同名不同编号的卡互换不算进展）。指纹抓"净零"，
> "增长型"交给 L2。

### 5.3 L2：回合预算 60

- **位置**：`TideHeadlessDriver`，与 `MaxActionsPerTurn` 并列。
- **计数口径**（2026-11-18 实施修正）：本回合该座次的**全部动作数**——实现取**保守超集**，响应动作也计入（不是原文的"仅 Main 相决策"）；理由：响应大战同样是空转形态，漏计会让 L2 兜不住；代价是极少见的长响应链可能提前触发预算收口，属于可接受误伤。
- **触发**：≥60 → 排干栈、强制 `EndTurn`、打 `pruned` 标记、`loopBudget` 计数 +1。
- **`MaxActionsPerTurn = 256` 保留**为硬保险（防实现 bug 导致完全无法收口）。
- **取值依据**：真人典型回合 ~10 步；绿固定序 T1~T7、蓝碑阵铺场属于多步但远低于 60。
  上线后看 `max_turn_actions` 分布再收（若 99 分位 < 30，可降到 40）。

### 5.4 L3-A：训练剪枝（空转步不进 PPO）

- **协议**：driver 的 `info` 增 `loopPruned`（bool，触发那一步为 true）与 `turnActions`（本回合已用步数）。
- **rollout**：`rollout_common.py` 记录每个回合的起点下标；回合结束（或对局结束）时若该回合触发过
  `loopPruned`，把 `learner[start:end] = 0`。
- **消费**：PPO 批次本来就按 `data["learner"]` 掩码过滤（`train_tide_complete.py:716-743`），
  与"对手步剔除"同一条通道，无需新机制。
- **效果**：空转步既不产生梯度，也不污染熵/KL 统计。

### 5.5 L3-B：动作表折叠（重复行去重）

- **位置**：`LegalActionEnumerator.Enumerate` 末尾（`EnforceActionCap` **之前**）。
- **键**：动作特征行去掉 `sourceIndex`（即 type/target/mode/cost/effectId/targetKind/target2/3/nTargets/reference…）；
  同键只保留第一行。
- **为什么安全**：对模型而言这些行完全不可区分（唯一差异是"手牌第几格"），折叠不改变可选性。
- **效果**：深潭碑局面 177 行 → 约 8 行，EndTurn 概率回到 1/8；同时省算力。
- **注意**：费用指示物/临时标记不同的同名牌，`cost` 特征不同 → 不会被误折叠。

### 5.6 指标（`stats.jsonl` 新增）

|---|---|---|
| `loop_events` | 本 update 触发的 L1 收口次数 | 0（偶尔 1） |

## 8. 风险与回滚

| 风险 | 说明 | 缓解 |
|---|---|---|
| L1 误判 | 合法长回合被指纹误伤 | 指纹只含"净变化"项；K=8 且回环需同回合内重复；上线后看 `loop_events` 是否异常 |
| L2 截断合法回合 | 蓝铺场 + 碑阵可能接近 60 | 先跑一轮看 `max_turn_actions` 分布再调；配置项可改 |
| 折叠改变评估可比性 | 动作表形态变了，旧 eval 数字不能直接逐格对比 | 只比 ALL 胜率与格趋势；文档记录口径变更 |
| L0 规则复归 | 充盈触发时机变化（定稿=己方释放法术后·仅法术）→ 蓝套强度、脚本基线都变 | 这正是修复目标；§6.3 基线需重测，蓝格门槛可能随之调整 |
| 热启动不兼容 | 只有在改了维度/卡身份时才会发生 | 本方案不改，风险为零；若后续要改卡面，另立"换卡身份"决策 |

回滚：L0 用常量开关（`SurplusTriggersPerTurn=0` = 不限，回旧行为）；L1/L2 用 CLI/env 开关
（`--loop-guard off`）；L3 可由 `--no-prune` 关闭。

## 9. 后续（不在本版范围）

1. **真人侧的循环规则**：若未来出现真人也能无限循环的卡组，参照 MTG 的"循环声明/短路"：
   同一状态重复 N 次 → 要求玩家声明迭代次数或判和。这条要进正式规则，与 AI 闸分离。
2. **循环监控告警**：`loop_events` 连续为 0 → 正常；突然飙高 → 大概率新卡引入了新循环，停训检查。
3. **对局回放**：把 `loopCycle` 触发点写进对局日志，便于复现具体卡组。
