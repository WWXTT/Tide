## 2. 目标与非目标

**目标**

1. 单网络、无硬路由、不吃卡组 key，在**任意 30 张卡组**的观测/动作空间下可训。
2. 一期绿链（3 地 → 首献 → **施放归根** → 重铺 → 大哥）逐段到达率抬到脚本同量级（**G5 口径，已验收 2026-11-26**）。
3. 二期改造后**第一轮仍只跑三预组对脚本**：回归面（18 格不退步）+ 过程面（G5 漏斗/决策步数/macro 使用）双读；不建 held-out（**S4 不做**，见 §6）。
4. 部署面不破：ONNX 单文件、C# `OnnxTidePolicy` 只按 dims 校验、无运行时路由。

**非目标**

- 不按卡组/卡名写掩码或专用奖励（**唯一例外**：S3-3 的链进度势能奖励按卡组定义目标态，属契约变更，**需用户签字**后才进）；不做三网络 + 硬路由；不改教学表；不重算历史 best、不改判据。
- 不做 set-prediction（一次前向选 k 目标）；不做 dry-run 全量后果（**已测不可行**：有免费状态副本也要 27.7~48.3ms/决策点，现状 220~657ms，见 C9）。
- 不做「三份工程并行」的二期版；二期仍是单网络 + 课程。

## 2.5 卡组分布：原型化极端构筑（2026-11-26 用户给定）

> 用户原话：玩家卡组**必然是主题化构筑，但不是颜色主题，而是必然构建成一种获胜方式**；玩家会围绕一个目标构建非常极端的卡组（红打脸、绿成长）。
> 这条约束改掉两件东西：**训练卡组分布**，以及（等评估方式想定后的）**held-out 判据**。它不改模型接口。

| # | 推论 | 落地在哪 |
|---|---|---|
| D1 | 「随机 30 张」不是目标分布，是噪声分布 | 卡组生成器按**原型**生成：先定获胜方式（致胜回合带 / 资源轴 / 节奏键），再按极端度（满编重复张数、单例数、曲线尖峰）拉满 |
| D2 | 「拿到什么都会玩」= 「拿到任一**原型**都会打」，可测 | held-out 按原型留出（**不做，见 §6**） |
| D3 | 网络必须看见「我的牌库想干什么」 | `g[88..95]` 8 维统计不够 → **S1-3b** 把 30 槽牌库块当集合编码 |
| D4 | 极端卡组 = 一条近乎确定的 plan + 执行细节 | 正是 S2 选项层 + S3 BC 先验的靶心：先验教「形状」，RL 学「执行」 |
| D5 | 局长时间两极化（打脸 T4-6 收，成长 T8+） | 评估按原型分层；aux 头的「剩余步数」目标天然按原型分化，不分层会训成平均 |
| D6 | 单一原型会被「上分/退化」激进化 | 原型之间要做**克制成对**评估（不只镜像），否则学成「只会打自己」 |

> **不写「原型 key 表」**：原型不进观测、不进路由、不进掩码——它只是**训练分布与评估分层**的概念。这是 §2 非目标的直接推论，也是二期「任意卡组」的技术前提（原型无穷，不能枚举）。

## 3. S1 · 表示层（不换环境）

> 为什么先做：纯 `tide_rl/` 改动，不碰 C#、不升版本、不动冻结面；且 S2 换环境后本来就要全量重训，把网络先做完**不会多付一次重训**。

### S1-1 原子集合编码（替换三路 sum）

- 新增 `AtomSetEncoder`（`tide_encoder.py`）：
  - token = `[identity_emb(id) + type_emb(t) + Dense(param[t]) + slot_pos(s)]`，`t=0..N_TYPE_SLOTS-1`，mask = `(type>0) | (id>0)`；
  - 1 层单头 self-attention（**手工 matmul→scale→mask→softmax→matmul**，不用 `nn.MultiHeadDotProductAttention`，为 jax2onnx 稳定）+ 残差 + LayerNorm；
  - 池化 = `masked_mean ‖ masked_max` → `Dense` → 卡向量；
  - `[27]` 结构哈希、`[28]` 关键词哈希仍走 `Embed`，**加到卡向量**（不进 token）。
- 槽位上限、参数维、表大小全部走现有常量（`N_ID_SLOTS` / `N_TYPE_SLOTS` / `ATOM_PARAM_DIM` / `N_CARD_POOL` / `N_EFFECT_TYPES`），不新增魔数。
- 顺带修掉 `tide_encoder.py` 里已过期的 docstring（「(80,65)」「6 槽」「[15..22]」等，实际 191/158/12 槽/14 身份槽）。

### S1-2 三路权重 + 身份 dropout

- 三路可学习标量权重 `α_id / α_type / α_param`（初值 1/1/1，`softmax(α)*3` 归一），替换裸相加 → 训练后可直接读出「模型多信身份 vs 类型 vs 参数」。
- 身份通路训练期 dropout `p=0.1`（eval 关闭），逼网络依赖类型/参数通路 → 对「新原子实例」鲁棒。

### S1-3 context 与动作打分

- `TideActor` / `TideCritic` 的卡槽池化，改为 **query-attention 池化**：`query = global_feat (+ Dense(rnn_out))`，对 191 槽做单头 attention（mask 空槽）→ `pooled`。
- logits：`logit_i = dot(action_i, context)/√c + dot(action_i, attn(action_i → cards))/√c`（第二项=动作行对卡槽的一次 attention，取代「只 gather 源/目标两张卡」）。**实施口径（2026-11-26）**：这一项是追加，动作编码器仍 gather 源/目标卡——见下方实施记录。
- **输出形状不变**（`(batch, 512)`），`a_mask` 语义不变。

### S1-3b 牌库集合编码（让「原型」可见）

- v21 已经有 30 槽牌库块（`TideObservation.cs:137-138`，`DeckBase=154`，每槽一种唯一卡 + `[157]` 张数）——**槽位本来就在观测里，只是现在被均值池化吃掉了**。
- 做法：把 `cards[154..183]` 这 30 槽单独过同一卡编码器 → set-attention（query = global）→ `deck_vec` → `Dense` 并入 context；`g[88..95]` 保留为残差。

### S3-3 链进度：**reward 与 aux 同做**（用户点 3；**已签 2026-11-26**）

- 现实：只做 aux 头（旧口径"不进 reward"）等于**主动放弃**唯一能给「现在别烧归根」正向信号的通道——aux 只改表示与信用分配，**不改策略梯度**。
- 两件同做：
  1. **aux 头**（保留）：标签=「本局是否到达目标态」，权重 0.1，不进 reward；
  2. **链进度势能奖励**（新增）：`Φ_chain(s)` = 已达成的里程碑数/4，`r += λ_chain · (Φ_chain(s') − Φ_chain(s))`，`λ_chain` 初值 **0.02**（量级须 ≪1，与 §2 的塑形历史坑同口径）。**必须按 4 段里程碑分段（不是可选）**：3 地 / 施放归根 / 重铺 / 大哥落地，段间折叠后跨度 ≤30。**不能只做 0/1 终态**——「归根→大哥」折叠后 **56~64 步** > λ=0.98 的 50 步窗口（78/86 减 22，n=2 仅量级），0/1 会让最后一段仍落在窗口外。
- **为什么用势能形式**：势能塑形理论上不改变最优策略、只改梯度路径，比"打一张归根 +0.5"这类事件奖励安全一个量级。γ=1 下它 telescoping ⇒ **轨迹总回报不变、只改入账位置**（这正是要的），所以验收读**入账步距/位置**，不读总量。
- **契约冲突登记（明写）**：§2 非目标原有「不按卡组写专用奖励」。`Φ_chain` 的目标态本质是**按卡组定义的目标**（一期=三预组各自的 T3/大哥态）→ **属契约变更，需用户签字**（**已签 2026-11-26，范围见本条下方「签字范围」**）；**二期不能用**（无手工目标态），二期改为"由牌库集合自学的进度/赢面头"另立项。
- 验收：判据不是胜率，而是**按费分层后的比值反转**——`P(施放 | 含归根 且 green+any≥动态费)` vs `P(当地 | 同条件)`；不分层会被 475 局「付不起」钉死。
- **落地（2026-11-26 ZCode）**：① aux 第三标签——`AUX_DIM 2→3`（第三维 sigmoid=「本局是否到达目标态」，标签源 info.chainDone；rollout_common 按局回填；旧 2 维 checkpoint 热启动时 aux 头经 merge_params_by_shape 落 fresh 零初始化）；② 链进度势能——`TideHeadlessDriver` 事件层按座位闩位（只进不出=单调，γ=1 telescoping）：**绿=0:池地≥3/1:施放归根/2:重铺(归根施放后再放地)/3:阿格洛斯落地；红=0:池地≥3/1:血偿/2:活体炸弹/3:同回合双法术；蓝=0:池地≥2/1:深潭碑/2:潮汐/3:潮痕碑衍生物召唤**（蓝曲线 2 地口径=BlueControlStrategy 头注；卡组不命中三预组（随机 30/掺卡）主题空串→Φ=0 无链奖励——契约例外只覆盖三预组）；`r += chainLambda·ΔΦ/4`（协议 chainLambda/chainSet 显式下发，缺省 0=关；训练 Args chain_reward_lambda 初值 **0.02**）；闩位恒进 info.chainBits（λ=0 时=免费过程仪表）。**读数面（2026-11-26 补批）**：stats.jsonl 每行 model_behavior 聚合 `phi_games/phi_bit0..3（各里程碑达成局数）/phi_done（终点局数）/phi_reward_sum（=λ×bits/4 累计——γ=1 telescoping，局总量=λ×Φ_final，份额=sum/games）`；键前缀 phi_ 避开 B4 的 chain_games（mChain）撞名。费分层比值反转判据仍待正式 run（§5 验收）。**签字登记**：用户 2026-11-26「二期计划 s3全面执行」指令=对 §2 非目标例外（按卡组定义目标态的 Φ_chain）的签字；二期「自学进度头」另立项不变。
- **签字范围（2026-11-26 用户定）**：本签字覆盖三预组各自的四段里程碑（绿=3 地/施放归根/重铺/大哥落地；红=3 地/血偿/活体炸弹/同回合双法术；蓝=2 地/深潭碑/潮汐/潮痕碑衍生物）+ **aux 第三维** + **`chain_reward_lambda` 默认 0.02**。**不覆盖**：随机 30 张/掺卡卡组（Φ=0 无奖励）、二期「自学进度头」。红/蓝里程碑定义须与三预组卡表/策略同源，改动视为契约变更、重新签字。

| jax2onnx 不支持 attention 图 | S1 卡在导出 | 手工 matmul/softmax；再不行降级为 token-wise Dense + mean‖max（S1 仍成立） |
