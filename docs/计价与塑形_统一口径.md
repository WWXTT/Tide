# 计价与塑形 · 统一口径（2026-11-23 定案）

> **一句话**：牌价系统（`CardCostService`）与奖励塑形（`FieldValueReward`）不是两套东西——
> 塑形就是把**同一套标价**用到「双方盘面」上。任何一项在牌价里有价，在塑形里就必须有同一个价；
> 否则 AI 会学到「按塑形而不是按牌理」打。
> 本文是唯一口径来源。改动费率请同批改这里 + `FieldValueReward` 权重表 + `红绿0胜归因_修改计划.md` §3.5。

---

## 0. 为什么必须同源

塑形是 `每条奖励 = λ·(Φ' − Φ)`，`Φ = V(我) − V(对手)`。
如果 `V` 里某项的价格与牌价不一致，模型就会对着**错的价目表**做决策：

| 症状 | 走过的弯路 |
|---|---|
| 绿不铺地、不出大哥 | 地价 0.6 且**横置=0**（用资源就掉分）→ 模型不敢横置、不敢铺 |
| 绿/蓝不叠甲 | **护甲根本不在 Φ 里**（收益 0） |
| 血偿 0 次 | 手牌按 `DerivedTotal`（含代价价）计价 → 代价被收两遍 → 血偿 = −2 永不出手 |
| 模型偏冲脸不解场 | 战斗伤害也按 1.0/点 → 攻击被高估一倍 |

全部已修，见 §2 权重表。

## 1. 标的物与单价（单位统一 = **费**）

| 标的 | 单价 | 牌价侧对应 | 备注 |
|---|---|---|---|
| 卡在手牌 | **卡面费 `DerivedTier`** | `CardCostService.Derive().DerivedTier` | 例：血偿 3。**不含代价价**（代价在结算时按盘面变化另计） |
| 卡进墓地/回手 | 回手 +标价；墓地 0 | — | "从墓地回收"的收益 = 回手后那张牌的标价 |
| 牌库抽牌 | +标价（牌进手） | — | 抽到的牌按手牌计 |
| 地牌（池中） | **1.0 / 块** | 无（地不是卡费） | **横置不打折**：地价恒定 |
| 产出元素（临时彩 / Any） | **1.0 / 个** | 1 费 | 于是"横置一块地"净 **+1**（地不变、元素 +1） |
| 生命 | **1.0 / 点** | 1 伤 = 1 费 | |
| 护甲 | **1.0 / 层** | 1 甲 = 1 费 | 旧版缺失 |
| 场面生物 | **(攻 + 血) × 0.5** | 1/1 = 1 费 | 非生物仍按标价 `DerivedTier` |
| 指示物 | ±0.5 / 层（+1/+1 记双倍） | — | 沿用旧值 |
| **法术/效果伤害** | **1.0 / 点** | 1 伤 = 1 费 | 一次性，按牌收费 |
| **战斗伤害** | **0.5 / 点** | — | 生物自带"复利"：属性值已按永久盘面计，攻击每回合重复兑现，不再按 1.0 重复计 |

**复利口径**：生物的攻击/守卫价值体现在 `(攻+血)×0.5` 这个**永久**盘面值里，每回合重复兑现；
战斗伤害只额外补 0.5/点的一次性收益。所以「砍脸」不如「解场」——解场同时拿走对手的复利资产。

## 2. 落点（代码）

### 2.1 势能（状态函数）

`FieldValueReward.ResourceValue / CardDynamicValue`：

| 权重 | 值 | 说明 |
|---|---|---|
| `LifeWeight` | 1.0 | 旧 0.15 |
| `ArmorWeight` | 1.0 | 2026-11-23 新增（`player.GetCounterCount(ArmorCounter)`） |
| `ManaWeight` / `WildManaWeight` | 1.0 / 1.0 | 旧 0.4 / 0.6 |
| `LandTokenWeight` | 1.0 | 旧 0.6；**横置不减价** |
| `HandWeight` | 1.0（× `DerivedTier`） | 旧 0.6 × `DerivedTotal` 且奖励端剔除手牌 |
| `BioStatWeight` | 0.5（生物按攻+血） | 2026-11-23 新增 |
| 塑形 `includeHand` | **true** | 旧 false（2026-09-22 防摸牌刷分；λ 已 0.05→0.005） |

### 2.2 战斗伤害 0.5 修正（事件层）

Φ 分不出伤害来源，故用引擎事件定向修正（`TideHeadlessDriver`）：

```csharp
EventManager.Instance.Subscribe<CombatDamageEvent>(OnCombatDamage); // 记 打到我 / 打到对手
delta += 0.5f * (打到我方的战斗伤害 − 打到对手的战斗伤害);
reward = λ · delta;
```

- 打到对手：Φ 已 +1.0/点 → −0.5 → 净 **0.5**
- 自己挨打：Φ 已 −1.0/点 → +0.5 → 净 **−0.5**
- `DamageEvent`（法术/效果）不进修正 → 保持 **1.0**

## 3. 自洽性验算（每条都要对得上）

| 动作 | Φ 变化 | 判读 |
|---|---|---|
| 抽一张 3 费卡 | **+3** | 抽牌是加分项 |
| 从墓地回收一张 3 费卡 | **+3** | 同上 |
| 把 3 费卡当土地打出 | **−2**（手牌 3 → 地 1） | 之后每横置 +1：**2 次回本、3 次净赚** |
| 横置一块地 | **+1** | 地价不变 + 元素 +1 |
| 打 1 费「1/1 + 加 1 甲」小精灵 | **+1**（−1 +1 +1） | 低费生物是正收益，鼓励铺场 |
| 血偿（3 费、5 伤、吃己方 1/1） | **+1**（−3 +5 −1） | 代价只收一次（生物消失） |
| 活体炸弹（0 费、参照攻伤害、吃己方生物） | 攻 − 生物属性 | 用便宜生物换大伤害才赚 |
| 攻击 1 点（战斗伤害） | **+0.5** | 复利已在生物属性里 |
| 解场：打死对手 3/3 | **+3**（拿走其盘面值） | 解场 > 砍脸 |

## 4. 已知偏差 / 待办

1. **T5 成长口径**：现有 `land_t1/land_t3` 快照记在"本回合铺地之前"，不判别"是否铺地"。
   待改成「T5 地数 / 累计铺地次数」。
2. **血偿可用性**：v3~v6 诊断里血偿 0~1 次，而同局活体炸弹 4~7 次。需单独查 LAE 可用性
   （3 费 + 有可牺牲生物两条件），不是塑形问题。
3. **风险**：手牌计入势能（true）+ 抽牌 +3，理论上可能诱导囤牌/拖局；λ=0.005 已比 2026-09-22
   事故时小 10 倍。若 `ep_len` 明显抬头，回滚点=`TideHeadlessDriver` 两处 `includeHand`。
4. **风险**：0.5 战斗伤害若仍导致"无脑冲脸"，则需给"己方生物被消灭"加权或再降战斗伤害。

## 5. 变更纪律

- 改任一单价 → 同批改：本文 §1 表、`FieldValueReward` 权重常量注释、§3 验算、`红绿0胜归因_修改计划.md` §3.5.2b。
- 改费率口径（如"代价是否进卡面价"）→ 必须重跑 §3 全部验算，贴数值进提交说明。
- 塑形/牌价不一致 = 缺陷，不是调参。

## 6. 死亡计数口径（2026-11-24 用户定案，单独登记）

> 来源：[观测_卡组分布与策略分界_实施方案](观测_卡组分布与策略分界_实施方案.md) §9.2/§9.3。
> 这是**规则/计价变更**，不属观测维度验收（见《回到一期训练目标》）；按该文档要求在此单独登记、单独验收。

| 项 | 旧口径（退役） | 新口径（2026-11-24） | 落点 |
|---|---|---|---|
| 开启计价 | 旧-旧「引擎零计价」→ 2026-11-10「×4 总费」（`DeathTollAmplificationMultiplier`）；原子属性化（2026-11-20）后判据漏迁=**零加价** | **基价 +2 开启费**（平费，加在系数链末端——不随目标数/时机系数缩放） | `CostDerivation.DeathTollEnableFee=2f`；判据=`atom.DeathToll`（`IsAmplifiedDeathToll`）；`AmplificationFeeOf`=UI/测试口 |
| 手牌累计上限 | 满值 6（普通）/ 9（增幅）两代口径 | **无上限**（`DeathTollCap` 常量已删；增幅收益=原始层数，`min(9)` 移除） | `BranchEngines.EvaluateDeathTollCounters`；`EffectHandlerRegistry.DeathTollBonusOf` |
| 观测显示（同批、属观测侧） | 卡特征 `[152] = 层数 /9` | `[152] =` **原始层数**（与毒素指示物同族） | `TideObservation` 死亡计数维；`tide_rl/tide_features.py CARD_F_DEATHTOLL` |

- **塑形同源性**：手牌势能按 `DerivedTier` 计（§1 第 1 行），开启费进 `DerivedTier` 后塑形自动跟随，
  `FieldValueReward` **无需另改**——本变更不动 §1 单价表，§3 验算不涉及。
- **卡表影响**：当前全库**无**属性形态（`deathToll=true`）的用户卡 ⇒ 推导费表零变化、卡表指纹不变；
  未来新卡开死亡计数即自动吃到 +2（禁止手填绕过）。
- **验收状态**：`CardPipelineVerifier` 死亡计数段全绿、TideSim `FreeBranchScenarioCheck` 放大段属性形态
  （2026-11-24 取证）；**待用户单独验收**。
