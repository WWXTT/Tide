# 人类对局日志 → 模仿学习：最小实现框架（v0.1）

> 状态：**未来拓展方向**，不改变当前训练主线（PPO 自对弈 + 三脚本对手池）。
> 本文只定义「如果要做，最小可验证的一套东西」：数据契约、代码落点、验收口径、红线。
> 最后更新：2026-11-15

---

## 0. 定位与非目标

**定位**：把「顶尖玩家上传的联机对局」变成 `(局面, 合法动作, 选中动作)` 样本，用来**给 PPO 做初始化**（行为克隆预热），目标是缩短到达基线胜率所需步数。

**非目标（这一版明确不做）**：

| 不做 | 原因 |
|---|---|
| 用人类数据做 reward shaping | 会把 AI 塑成「人类风格」；历史上塑形 λ 过大已把自对弈训成拖局（`docs/AI训练说明.md` §2） |
| 从**客户端战报 markdown** 里挖样本 | 遮蔽视角（抽牌只报数量、手牌不可见）+ 无 seed，状态不可复现 |
| 在线/增量从日志学 | 训练仍是离线 batch，日志只产数据集 |
| 改观测/动作空间 | 布局 v15（2026-11-18 场地特殊化起）、动作 14 维；改契约=重训，这条留到以后单独评估 |
| 自动上线/自动换模型 | 部署链（ONNX→manifest→游戏内）目前本身是断的（§8），先不叠加 |

## 1. 现状与差距

| 环节 | 现状 | 差距 |
|---|---|---|
| 对局回放 | 服务器把引擎事件流渲染成 **markdown 战报**，随 `MatchSummary(133)` 下发，客户端落 `EncounterStore`（`Assets/Scripts/HotUpdate/CardCore/BaseSystems/EncounterStore.cs:15`） | 只有「发生了什么」，没有「当时能选什么、选了什么」 |
| 随机性 | `MatchHost` 起局时传 `seed`（`TideServer/MatchHost.cs`） | **没有落盘**，牌序/随机效果无法复现 |
| 卡组 | `DeckSubmit(110)` 带双方 `CardIds + Digest`（`MsgDeckSubmit`） | 战报记录里只留了 `ownDeckName` |
| 决策流 | 服务器逐条接收 Intent 段（100..108/112/113）+ `SelectResponse(109)`，并已用 `NetworkIntentApplier.Apply` 应用（`CardCore/Network/NetworkIntentApplier.cs:25`） | **没有按序记录**（只用于实时推进） |
| 训练桥 | `TideHeadlessDriver`：`Reset(deck1,deck2)` / `Step(actionIndex)`，每步产出 `Obs + Legal`（含动作特征张量）与 `DecisionSeat`（`AI/NeuralEnv/TideHeadlessDriver.cs`） | 已有「状态→合法动作表」的现成实现，可直接复用做导出 |

**结论**：原料都在服务器侧，只差三件事——seed、双方卡组、intent 序列按序落盘。三者补齐后，用同一份 `CardCore` 离线重放即可还原每一步的 `obs / mask / action`。

## 2. 总体架构（最小四段）

```
联机对局（真人）
   │  P0：服务器决策日志（DecisionLog v1，JSONL，默认关）
   ▼
[ match.jsonl ] ──P1：离线重放校验（TideSim --replay-log）──► 对齐报告（对齐率/覆盖率）
   │
   │  P2：数据集导出（--export-dataset → npz 分片，可选按需重放不落盘）
   ▼
[ dataset.npz ] ──P3：train_bc.py（同网络，mask 交叉熵）──► 参数初始化 ──► PPO 微调（现有主线）
```

**关键设计决定**：服务器只记 `intent` 原文，**不记 RL 动作下标**——下标与布局版本绑定，由离线重放器（P1）在对应版本下计算。这样服务器侧代码与训练契约解耦，不会因动作空间演进而返工。

## 3. 数据契约：DecisionLog v1

文件：`<dir>/<matchId>.jsonl`，一行一个 JSON，UTF-8，事件类型用 `type` 区分。

```jsonc
{"type":"match","schema":1,"matchId":"m1751...","cardTableHash":"68fd6d33","layoutVersion":14,
 "engine":"2026-11-15","seed":123456,"roomId":"r-...","startedAtUnix":1763...,
 "players":[
   {"seat":0,"openIdHash":"sha256:...","deckCardIds":["C_...","C_..."],"skillCardId":"C_...",
    "tokenBindings":[],"rating":null},
   {"seat":1,"openIdHash":"sha256:...","deckCardIds":[...],"skillCardId":null,"tokenBindings":[],"rating":null}
 ]}
{"type":"decision","seq":0,"turn":1,"step":1,"seat":0,"kind":"intent",
 "msg":"IntentPlayCard","payload":{...},"msSincePrev":1240}
{"type":"decision","seq":1,"turn":1,"step":2,"seat":0,"kind":"select",
 "requestId":3,"msg":"SelectResponse","payload":{"RequestId":3,"Indices":[1]},"msSincePrev":2100}
{"type":"end","seq":42,"winner":0,"reason":"LifeZero","totalTurns":22,"finishedAtUnix":1763...}
```

字段约束：

| 字段 | 说明 |
|---|---|
| `schema` | 日志格式版本；不兼容变更 +1，旧日志直接跳过 |
| `cardTableHash` / `layoutVersion` | **必须**与训练侧一致，否则该局作废（`AI训练说明.md` §4 冻结面） |
| `seed` | 引擎随机种子；缺省=不可重放，整局作废 |
| `deckCardIds` | 双方完整主列表；自建卡额外带 `cards/effects/atomRows` payload（沿用 `EncounterRecord` 口径） |
| `openIdHash` | 只存哈希，用于「同一玩家/评分分位」聚合；不落原始 OpenId |
| `msSincePrev` | 决策间隔，用于过滤挂机/秒投 |
| `rating` | 可选（排名分；没有就 null，靠胜负+分位替代） |

脱敏与保留：只存哈希 ID；默认保留 30 天或按量上限（与 `EncounterStore.KeepRecords=100` 分离，训练日志是服务端资产）；导出数据集时再按需二次脱敏。

## 4. 实现清单

### P0 服务器决策日志（约 2 人日）

| 项 | 内容 |
|---|---|
| 新增 | `Assets/Scripts/HotUpdate/CardCore/NetSession/DecisionLog.cs`：`DecisionLogWriter`（打开/追加/关闭；写盘异步队列，失败只告警不阻断对局） |
| 接线 | `NetBattleChannel.HandleIntent(core, conn, msg)` 在 `NetworkIntentApplier.Apply` **之前**记一条 `kind=intent`；`HandleSelectResponse` 在应用前记 `kind=select`（`CardCore/NetSession/NetBattleChannel.cs:208,233`） |
| 元数据 | `NetSessionServer` 开局时写 `type=match`（seed 由 `MatchHost` 传入；双方卡组从 `DeckSubmit` 取；`cardTableHash/layoutVersion` 从现有契约常量取） |
| 终局 | 写 `type=end`（winner/reason/totalTurns） |
| 开关 | `TideServer --decision-log <dir>`（默认关；网关透传同款参数）；AI 填位局默认写 `players[].rating=null` 且可选跳过 |
| 验收 | 一局联机对局结束后日志行数 = intents + selects + 2；`jq` 能解析；无写盘异常 |

### P1 离线重放校验（约 3~5 人日，**这一段的通过与否决定整条路是否成立**）

| 项 | 内容 |
|---|---|
| 新增 | `TideSim/ReplayLogCheck.cs` + `--replay-log <file>` |
| 流程 | 读 `match` → `CardCore` 用同版本卡表 + `seed` 起局（双方卡组）→ 循环：在停靠点用 `TideHeadlessDriver` 同款方式构建 `Obs + Legal` → 取日志下一条 intent → 用 `LegalActionEnumerator`/`NetworkIntentApplier` 的映射找到 `Legal.Actions` 下标 → 应用 → 记一条 `(layer, index)` |
| 失败处理 | 找不到合法下标 = 该决策 `unmatched`（计入分母），仍按 intent 原文应用以继续重放；不中断 |
| 校验 | ① `winner/reason/totalTurns` 与日志 `end` 一致；② 终局 `PlayerState` 摘要（生命/手牌数/墓场数/元素池数）一致 |
| 产物 | `<log>.replay.json`：`{decisions, matched, unmatched, alignRate, coveredTurns, endStateOk}` |
| 验收 | 单局 `alignRate ≥ 99%` 且 `endStateOk=true`；批量抽 20 局同结论。**不达标 → 停下，回查缺哪个状态维度（随机/隐藏/时机）** |

### P2 数据集导出（约 2~3 人日）

| 项 | 内容 |
|---|---|
| 新增 | `TideSim/DecisionDatasetExporter.cs` + `--export-dataset <logDir> --out <dir>` |
| 产物 | 每 N 局一个 `.npz` 分片：`obs_cards (uint8, 191×116)`（v15 场地拆槽后 191）、`obs_globals (float16, 58)`、`mask (bool[512])`、`action_features (float16, 512×14)`（可选：只存 mask+index 更省）、`action (int16)`、`seat/turn/step`、`meta`（卡表 hash/layout/来源 matchId） |
| 过滤 | 版本不符 / 缺 seed / 决策间隔异常（<1s 或 >30s）/ 投降局 / 缺卡组 → 丢弃并计入统计 |
| 体积 | 单决策 ≈ 22KB（189×116 卡槽为主）；一局约 40~100 决策 ≈ 0.9~2.2MB；10k 局 ≈ 9~22GB（uint8，zstd 后约 1/3）。**日志为唯一真源**，obs 可随时重导 |
| 验收 | 随机抽 100 条样本，用同一份 `TideHeadlessDriver` 重建 obs 与导出值逐字节一致 |

### P3 BC 预热 + PPO 微调（约 3~5 人日）

| 项 | 内容 |
|---|---|
| 新增 | `tide_rl/imitation_dataset.py`（读 npz → 采样器）、`tide_rl/train_bc.py`（复用现有网络 + GPU/CPU 后端，loss=mask 内交叉熵） |
| 训练 | `train_tide_complete.py` 增加 `--init-params <bc.npz>`（复用 `opponent_pool.CheckpointPool` 的 `flax.serialization.from_bytes` 恢复路径，只是作用到 learner 初始参数）；其余超参不变（γ=1.0、λ=0.005、熵 0.05） |
| 评估 | 与基线同一口径：三主题各 50 局、对脚本胜率；另报 `50k / 200k` 步时的胜率对照 |
| 验收 | 达到「同基线胜率」所需步数 **≤ 1/3**（目标 1/10）；BC 单独对脚本胜率 > 随机策略 |

## 5. 与现有主线的接法

- 当前训练默认路径**完全不变**：代码默认 `--opponent-pool current`（同策略自对弈）；2026-11-17 起一期课程口径=模型侧三预组随机 vs SimpleAI 脚本三预组（`--model-theme all`，`AI训练说明.md` §0.1），mixed 为可选配置而非默认。
- 人类日志只在**初始化**这一处接入：`--init-params bc.npz`；不进入 rollout，不改奖励。
- 脚本与人类数据是两条互不替代的线：脚本 = 对手池 + 评估锚 + 行为先验（当前主力）；人类日志 = **初始化的额外先验**（未来）。
- 若 BC 初始化后出现「只会抄固定开局」，用 **DAgger-lite** 缓解：前 N 步按 `β` 概率用 BC 采样、其余用当前策略，样本仍只来自自对弈（不新增标注成本），逐步降低 `β`。

## 6. 指标与验收

| 指标 | 口径 | 目标 |
|---|---|---|
| `alignRate` | 能匹配到合法动作下标的决策 / 总决策 | ≥ 99% |
| `endStateOk` | 重放终局摘要与日志一致 | 100%（抽检 20 局） |
| 数据量 | 有效局数 × 平均决策数 | 首轮 ≥ 3000 局（≈ 2~3×10^5 决策） |
| BC 质量 | 验证集 mask 内 top-1 命中率 | ≥ 60% |
| 样本效率 | 达到基线胜率所需步数 | ≤ 1/3 基线 |
| 回归 | 对三脚本胜率不降（同评估口径） | 不低 2 个百分点以上 |

## 7. 风险与红线

| 风险 | 处理 |
|---|---|
| **版本漂移**（卡表/原子表/布局） | 日志带 `cardTableHash + layoutVersion`；不匹配直接作废。卡表一改，历史日志全体作废——**这也是「现在只做框架、不急着囤数据」的原因** |
| **隐藏信息** | 只有服务器侧日志有全量状态；客户端战报（遮蔽）不用于训练 |
| **人类噪声** | 投降/挂机/乱打：按决策间隔 + 胜负 + 分位过滤；不做「输局也当正样本」 |
| **行为克隆天花板** | BC 最多到人类水平；必须 PPO 微调，且保留自对弈信号 |
| **分布偏移** | BC 只做初始化；微调学习率减半；必要时 DAgger-lite |
| **合规** | 原始 OpenId 不落盘；训练数据使用需玩家条款覆盖；对手自建卡内容按 `EncounterRecord` 同款「导入才进库」口径，训练侧只读不合并 |
| **服务端开销** | 异步写 + 单局上限（如 500 行）；失败不阻断对局；默认关闭，按需开启 |

## 9. 附：一句话记住

> 现在的回放是「战报」，能看不能学；要学，必须在服务器多记三样（seed、双方卡组、intent 序列），
> 用同一份引擎重放出 `obs/mask/action`，先 BC 预热、再 PPO 微调——**只做初始化，不做奖励、不改契约**。
