# 场地特殊化 + 场地目标域 修改计划（v0.2 · 2026-11-18）

> **需求原文**：场地特殊化——场地结界每次受伤固定 1 耐久、不能赋予指示物效果、结界不算在战场单位中；
> 在 Domain（`AtomicEffectConfig.Domain` / `TargetAxis` 作用范围列）增加 **双方场地 / 己方场地 / 对方场地**。
>
> **口径补充（用户已拍板）**：
> 1. `双方场地 / 己方场地 / 对方场地` 是**区域词元**，对标 `双方角色 / 己方角色 / 对方角色`，
>    **不与 `卡 / 生物 / 结界 / 法术` 做类别笛卡尔积**（`己方场地:结界` 这类写法必须非法）。
> 2. 场地**可被攻击**；战斗伤害与法术/效果伤害**都只扣 1 耐久**（每次受伤结算 −1）。
> 3. **关键词效果对场地无效**；**指示物效果对场地无效**。
> 4. `:卡` 类别**不命中**场地。
> 5. 场地耐久**不加计价系数**（本批不改价）。
> 6. **拆场地**：AI 观测/动作空间里把场地从「战场单位槽」拆出（独立槽 + zoneKind）。
> 7. 「结界不算在战场单位中」**只指场地**（普通结界仍占容量、仍可被攻击）。

本文件只出计划，不改代码。分 8 个可独立验收的阶段；每阶段给出文件 / 函数 / 验收口径。

---

## 0. 一句话方案

把「场地」从**结界类别的一个子集**提升为**与角色同级的区域词元**（`TargetRegion` 尾部追加 3 项），
场地卡只经这 3 个词元被效果指向；同时落三条规则：**每次受伤 −1 耐久（战斗/效果同）**、
**赋加类效果对场地无效（指示物 + 关键词）**、**场地退出 `:生物/:结界/:卡` 类别域**；
最后把场地从 AI 的战场单位槽拆到独立观测槽（布局版本升 15，旧模型作废）。
**不新增 UI 节点、不改预制体、不改网络协议、不改计价规则。**

## 2. 口径定案

1. **场地 = 区域词元，不是类别**
   - 新增 `TargetRegion.OwnField / EnemyField / BothField`（`22 / 23 / 24`，只许尾部追加）。
   - 词法：`己方场地`、`对方场地`、`双方场地`；**无类别段**（带类别=解析失败）。
   - 语法层与角色 selector 同款；取件是**战场区里的场地卡**，不是 `Player` 实体。
2. **场地退出「战场单位」与三类卡类别**
   - `:生物` / `:结界` / `:法术` / **`:卡`** 一律不命中场地（`EntityCategoryRules.Matches` 对场地直接 false）。
   - 容量口径保持现状（已排除）；**可被攻击**（保留战斗入口，伤害按第 3 条 −1）。
   - `:卡` 不命中带来的一致性：`对方战场:卡` 的全选/全取也拿不到场地——场地只能经场地词元到达。
3. **固定 1 耐久**：每次**成功落到场地**的伤害（战斗 / 法术 / 效果同口径）只扣 **1** 点耐久，与伤害量无关；
   防护层/护甲/圣盾/易损/无实体等修正链**先照常算**，在「落耐久」这一口钳 1。
   攻击场地时反击力天然 0（无生命耐久体既有口径），不改。
4. **赋加类效果对场地无效**
   - **指示物**：效果类正量投放一律 0 落账（`CounterGrantKind.Effect`）；引擎初始化（入场耐久）走新增 `CounterGrantKind.Init` 豁免。
   - **关键词**：效果授予（`GrantKeywordHandler`，`KeywordLane.Temp`）对场地空转；箭头连接光环投递的关键词读取为假；
     卡面印刷关键词（`KeywordLane.Printed`）不在此列（不是「效果」）。
   - 场地自身的**场地光环/规则光环**、自身效果文本照常（不是关键词效果）。
5. **文案/交互**：`{target}` 渲染为「对方场地」纯区域词（无类别、无量词、无「的卡」后缀）；
   目标数量档与角色同口径（只 1，不开放「全部 / 动态」）。
6. **AI 拆场地**：场地卡在观测里占独立槽（每方 1 槽），不再占战场单位槽；`zoneKind=10`；
   战场槽 9 只放单位；g[7]/g[8] 计数剔场地；攻击动作仍可打场地（目标槽=场地槽）。
7. **不改**：预制体 / 新 UI 节点 / 网络协议 / 计价规则 / 表现层摆位。

> 命名澄清：本计划的「场地」= **场地卡**（`CardData.IsField`，落场地格）；
> 与既有「场地光环」（`MountKind.RuleAura`，仪典类规则光环）是两回事。

## 4. 分阶段改动

### P1 区域词元（`CardCore/Effects/TargetAxis.cs`）

1. **枚举**（`:13` 尾部追加，禁止重排）：
   ```csharp
   OwnField   = 22,   // 己方场地
   EnemyField = 23,   // 对方场地
   BothField  = 24,   // 双方场地
   ```
2. **真相表**（`:68` 的 `Rows`）追加三行，并把 `Row` 从「`Zone` + `Side`」扩成带**槽位类型**的形态，
   避免 `Zone.None` 同时表示「自己 / 角色 / 场地」三义：
   ```csharp
   enum RegionSlot { Self, Zone, Character, Field }
   ```
   | Region | Zh | Zone | Side | Slot |
   |---|---|---|---|---|
   | `OwnField` | 己方场地 | `None` | Own | `Field` |
   | `EnemyField` | 对方场地 | `None` | Opposing | `Field` |
   | `BothField` | 双方场地 | `None` | Both | `Field` |
   - `IsCharacter(region)` 改为 `Slot==Character`（不再靠 `Zone==None` 推断，防止场地被当成角色域）。
   - 新增 `IsFieldRegion(region) => Slot==Field`（供 P2/P3/P4 共用）。
3. **`TryParseDomain`**（`:287`）：
   - 带类别段（`parts.Length==2`）：`Slot==Field` → **return false**（禁笛卡尔积，错误可见不静默）。
   - 无类别段：`Slot==Field` 放行（与 `Self` / `Character` 同列）。
   - **`Categories` 必须置 `None`（不是默认 `Card`）**：否则混合轴里场地 selector 的 `Card` 位会让
     `TargetAxisResolver` 的类别过滤对**所有**候选白名单化（`:607` 的 `Matches` 见到 `Card` 位恒 true）。
4. **`Zh`**（`:264`）：`Slot==Field` 时只输出区域词，不拼 `":卡"`。
5. **`NarrowByPolarity`**（`:456`）：`BothField` 显式映射 `p>0 → OwnField / p<0 → EnemyField`
   （**不能**走 `OwnOf/EnemyOf`——那两个函数按 `Zone+Side` 扫描，`Zone.None` 会误命中 `Self`）。
6. **`NarrowByKinds`**（`:349`）：场地 selector **按侧别收窄**，不走区域映射：
   - `kind=3`（己方无生命单位）→ 允许 Own，`kind=4` → 允许 Opposing；两者都有 → 保留 Both；
   - 侧别不匹配 → 删 selector；`kinds` 空 / 纯 0（`selfOnly`）→ 不收窄（沿用现有短路）。
   - 场地**不认** 1/2（有生命）——它是无生命持久物，`3/4` 是它的区级视图（见 P2）。
7. **`AllowsAllTarget`**（`:493`）：显式返回 false（`ZoneOf==None` 现状也天然 false，写死防回归）。

**验收**：`TryParseDomain("双方场地") / ("己方场地") / ("对方场地")` 成功且 `Zh` 往返一致；
`"己方场地:结界"`、`"场地"`、`"双方场地:卡"` 解析失败；`TargetRegionRules.Count==25`。

### P2 候选解析 / 收窄 / 数量

1. **`TargetAxisResolver.GetCandidates`**（`TargetAxis.cs:561`）：
   - 在 selector 循环里**先判** `IsFieldRegion`：对 `SidesOf(region, controller)` 逐侧扫描
     `ZoneManager.GetCards(side, Zone.Battlefield)`，取 `c.IsFieldCard() && c.IsAlive`
     （每侧至多 1 张，异常多张取首张，与 `BoardState.FieldCardOf` 同口径）。
   - **类别过滤豁免（两处都要改）**：类别过滤的**启用条件**（`:607` 的 `Any(...)`）与**逐实体匹配循环**
     都要 `&& !IsFieldRegion(s.Region)`；场地候选单独收集、在类别过滤**之后**并入。
     否则「场地 + 另一条带类别 selector」的轴要么把场地剔掉、要么因 `Categories=None` 把整轴候选清空。
   - 可见性/帷幕/属性 `Filter` 仍走现有链路（`ExcludeUnselectable` 等对战场卡天然放行）。
   - 空场（该侧无场地）→ 该侧 0 候选；双人局 `双方场地` 上限 2。
2. **`AtomicEffectConfig.KindListOf`**（`:227`）：场地 selector 派生**区级 kinds** `3`（己方）/`4`（对方），
   Both 取 `3,4`。原因：`EffectExecutionEngine:237`、`SimpleAI:605`、`CostPayability`、`CostDerivation:1288`
   等 **17 个消费口**读的是 kinds 视图，派生为空会被判「无域 / 无目标」。
   > 注意：这只影响「区级侧别视图」，不影响候选（候选走 axis，且 P4 会从类别剔除场地）。
3. **数量档**：
   - `CardEffectConverter` 的 `singleOnly`（`:704`）：把「仅 Self/角色」扩成「仅 Self/角色/场地」→ count 2/3 收 1。
   - `CostDerivationService.SideLock` 自动可用（3→己方锁 / 4→对方锁），计价口径不变。

**验收**：夹具里给双方各放 1 张场地 → `对方场地` 恰 1 张（对方）、`双方场地` 恰 2 张、空场侧 0 张；
场地行 count=2/3 被收为 1；`CanPay`/计价链路不报「无域」。（`:结界` 不含场地属 P4 验收。）

### P3 文案与合成器（不改预制体）

1. **`UI/Data/AtomText.cs`**
   - `AxisPhraseOf`（`:184`）：`IsFieldRegion` → 直接输出区域词（如「对方场地」），不拼类别与量词。
   - `AreaAxisOf`（`:236`）：场地 selector 不进「全取面积轴」（与角色同口径）。
2. **`UI/Screens/EffectComposerScreen.AtomRows.cs`**
   - `DomainOptionsOf`（`:96`）：行域含场地 selector 时按极性产 `己方场地 / 对方场地 / 双方场地`
     （一段一项，复用现有收窄逻辑）。
   - **赋加行不给场地选项**：`MountKinds` 含「指示物」**或**「关键词」→ 场地选项不出现（P6 的静态拦口）。
   - `BindCountCore`（`:236`）的 `allowsMulti`（`:240`）：排除 `IsFieldRegion` → 数量档只剩 1（同角色）。

**验收**：建一条域写 `对方场地` 的原子行 → 合成器「作用范围」显示「对方场地」、数量档只有 1；
`己方场地:结界` 无法从下拉产生；指示物/关键词原子的下拉里不出现场地字样。

### P4 场地退出类别域（`TargetAxis.cs` · `EntityCategoryRules`）

1. `SupertypeCategoryOf`（`:224`）：`card.IsFieldCard()` → 返回 `TargetCategory.None`。
2. `Matches`（`:237`）：**在 `Card` 位短路之前**先判场地：
   ```csharp
   if (entity is Card f && f.IsFieldCard()) return false; // 场地只经场地域词元到达
   ```
   —— 这样 `:卡` 也不命中场地（用户拍板 ②）。
3. **不改** `IsNonLivingUnit`（场地受伤必须走耐久管线）、**不改** `TargetResolver.NonLivingOf`
   （它只服务 legacy 预检，见 §6 风险 R2）。
4. 全表回归：现有所有 `:结界` / `:卡` 行语义收紧为「不含场地」；
   `TargetAxisVerifier` 的「含场地子类」断言同步改写（P8）。

**验收**：夹具 `己方战场:结界` == 场上非场地结界数；`对方战场:卡` 不含场地；
`双方场地` 可单独取到场地；场地不再出现在任何类别候选里。

### P5 固定 1 耐久（两条伤害路径）

1. 新增 `Assets/Scripts/HotUpdate/CardCore/Cards/FieldRules.cs`（规则单源，禁止调用点各写一份）：
   ```csharp
   public static class FieldRules
   {
       public static bool IsField(Card card) => card != null && card.IsFieldCard();
       /// <summary>场地每次受伤固定 1 耐久；非场地原样返回。</summary>
       public static int DurabilityDamage(Card target, int incoming)
           => IsField(target) ? 1 : incoming;
       public static bool BlocksCounterGrant(Entity e) => ...;
       public static bool BlocksKeywordGrant(Entity e, KeywordLane lane) => ...;
   }
   ```
2. `KeywordRules.ApplyDamageLegacy`（`:495` 无生命单位分支）：
   `LoseDurability(..., FieldRules.DurabilityDamage(card, amount), ...)`。
   - 位置在防护层 / 易损 / 无实体之后（现有顺序不动），**只影响落耐久那一口**；`dealt` 仍按实际扣层。
3. `Damage/DamagePipeline.DefaultDamageApplier`（`:616`）：同口径改 `ctx.Amount`。
   （默认走 Legacy；Chain 仅在 `DamageResolverRegistry.ChainOptIn` 显式接线时启用——两路都改防漂移。）
4. **不改** `CounterRules.LoseDurability` 本身（触发次数成本 / 转移 / 验证器直调都是「明确指定扣 N」，
   放进去会误伤——例如 `CardPipelineVerifier.Atoms.cs:572` 的 P8 用例）。
5. 战斗路径口径：攻击场地=合法（P4 不动 `CanAttackTarget`），每次结算 −1；反击力 0（无生命既有口径）；
   碾压/溅射若波及场地按同一口 −1（不另设豁免）。

**验收**：`ApplyDamage(field, 5)` 两次 → 耐久逐次 −1；护甲 3 挡 5 伤 → 余 2 → 仍只扣 1；
耐久 1 再受伤 → 入墓（Smashed）；普通结界同场景仍按全伤扣；宣言攻击场地成功且只 −1。

### P6 赋加类效果对场地无效（指示物 + 关键词）

1. **指示物闸**：
   - `EntityEffectExtensions.CounterGrantKind`（`:775`）：追加 `Init`（引擎初始化，不属「赋予」）。
   - `AddCounters`（`:431`）**最前**（在禁疗令/破败/绝缘体/铭刻之前）加闸：
     `amount > 0 && kind == CounterGrantKind.Effect && FieldRules.BlocksCounterGrant(entity)` → `return 0`。
   - **初始化豁免**：`EquipRules.OnEnterBattlefield`（`:48`）、`MorphSystem`（`:143`）的耐久初始化改为 `kind: CounterGrantKind.Init`。
2. **关键词闸**：
   - `GrantKeywordHandler.Execute`（`GrantKeywordHandlers.cs:26`）：目标为场地 → `continue`（不写层、不发 `KeywordEvent`）。
   - `EntityEffectExtensions.AddKeyword(...)`（`:324`）：场地 + `lane != KeywordLane.Printed` → 直接 return（咽喉兜底）。
   - `LinkAuraSystem.HasAuraKeyword`（`:133`）：`entity` 为场地 → `false`（箭头光环投递的关键词不生效）。
   - 卡面印刷关键词（`CardData` ctor 直写 `_keywords` + `Printed` 轨）不拦——不是「效果」。
3. **装载告警**：`CardLoader`（`ValidateComboDomains` 内）——行 `MountKinds` 含「指示物」或「关键词」
   且 `Domain` 含场地词元 → `TideLog.Error`「指示物/关键词不可赋予场地（该行对场地空转）」（可见不炸）。
4. **合成器静态拦口**：P3 已把赋加行的场地域选项隐藏。

**验收**：`AddCounters(field, 护甲, 2)` 返回 0 且层数 0；`AddCounters(field, 圣盾, 1)` 同；
`AddKeyword(field, 先攻, Temp)` 后 `HasKeyword` false 且无 `KeywordEvent`；箭头光环指向场地格 → 关键词读取 false；
