# Tide - 规则引擎代码概览

双人卡牌对战游戏（TCG/CCG）的规则引擎框架，融合《游戏王》《万智牌》的核心机制。

> **规则与设计见 `README.md`（原 `设计文稿.md`，已改名）**（三条核心规则、基础数值、游戏规则、待办清单）。本文件只讲实现：架构、数据流、接线点。

## 回合控制系统解说
TurnEngine 只管"状态和流转"，业务动作全部事件化解耦到GameCore。TurnEngine 自己不发私有小道事件 ——
  PublishEvent 优先转发到 GameCore.PublishEvent（TurnEngine.PublishEvent）,保证回合/阶段事件能被 ReplacementEngine →
  EventManager →TriggerEngine →LayerEngine 全链路看到；未接线时退化为直接走事件总线，便于独立单测。

  阶段顺序硬编码在 TurnEngine._phaseOrder = [Standby, Main, End],循环取模流转。没有战斗阶段 ——战斗发生在 Main
  阶段内，由 CombatSystem 自己的状态机管理(CanCombatAction() 要求 Main+Active)。

  GameCore.InitGame（两路重载：卡牌对象 / CardData）          ←外部入口
    ├─ Reset + 重置疲劳计数 + 注入地牌曲线 [1..10]（曲线=ResourceCurve.StandardLandCurve，末端值取表 GameRules.LandCurveCap）
    ├─ 双方卡组入 Deck 区 →洗牌 →各抽满初始手牌（表 GameRules.OpeningHandSize=6）
    └─ GameCore.StartGame
         ├─ GameStateManager.StartGame() 守卫(防重复开始)
         ├─ 发布 GameStartEvent
         └─ TurnEngine.StartNewTurn(player1)   ←第一回合从这里开始

  TurnStartEvent 的消费者是 GameCore.OnTurnStarted ——这是回合开始真正干活的地方：
  - StackEngine.OnTurnStart 重置优先权持有者
  - EffectExecutor.OnNewTurn 清零"每回合一次"使用计数
  - DurationTracker / TextChangeLayer.OnTurnStart 推进全局回合计数（UntilNextTurn/ForTurns 到期戳基准）
  - 遍历回合玩家战场卡:Untap() + 发 UntapEvent(横置恢复)
  - ElementPool.OnTurnStart(个人曲线上限+1、地牌解除横置——2026-10-11 资源重做)
  - 抽 1 张牌（空库走疲劳 ApplyFatigue）

  StartPhase(phase)（TurnEngine.StartPhase）:创建 PhaseInfo{State=Active} →发 PhaseStartEvent →OnPhaseStarted
  按阶段分派。三个阶段的处理：

  - Standby（TurnEngine.StartNewTurn 末尾直调 AdvanceFromStandby；GameActions.SkipElementPool 走同一条入口，
    现为兼容保留）:纯自动阶段，无玩家操作。所有自动化已在 TurnStartEvent 里做完；
    AdvanceFromStandby（有"必须在Standby 阶段"的守卫）推进进入主阶段。
  - Main（TurnEngine.OnPhaseStarted 分派）:空操作，等玩家放元素池/出牌/攻击/发动效果。
  - End（TurnEngine.OnPhaseStarted 分派）:发 TurnEndEvent →CheckGameOver()(任一方 Life≤0发
    GameOverEvent)。注意注释里明确：不在这里切换玩家，轮换统一交给 End→Standby折返处理，否则 .Opponent
    会叠加导致回合不交替。

  TurnEndEvent 的消费者是 GameCore.OnTurnEnded:
  - ElementPool.OnTurnEnd:临时钱包清空（2026-10-11 现取现用：产色只在付费步，回合末未用元素即逝）
  - DurationTracker / TextChangeLayer:失效"直到回合结束"类持续效果 + 按到期全局回合戳失效 UntilNextTurn/ForTurns
  - DelayedEffectScheduler.OnTurnEnd:结算延迟效果(fire-and-forget,因含 await UI)
  - EnforceHandLimitAsync:手牌上限 7 张，超出由玩家选弃

  阶段推进 GoToNextPhase（TurnEngine.GoToNextPhase）:
  currentIndex →(currentIndex + 1) % 3
    ├─ 下一阶段是 Standby(即从 End 折返)→StartNewTurn(ResolveNextTurnPlayer())
    └─ 否则 →StartPhase(下一阶段)

  EndCurrentPhase（TurnEngine.EndCurrentPhase）:置 State=Ending →发 PhaseEndEvent →OnPhaseEnded(目前只有 Main
  结束时预留了战斗状态清理，是空的)。

  四、额外回合 / 跳过回合

  由原子效果 TakeExtraTurn / SkipTurn 驱动（TurnEngine.GrantExtraTurn / SkipNextTurnFor）。
  注意：**TakeExtraTurn 目前只有 handler、原子表无对应行**（不可配置）；2026-10-22 用户裁定「未来可能重启，先留着」——
  重启时补表行即可，handler 与 GrantExtraTurn 不动。SkipTurn 表行在用。

  - GrantExtraTurn(player):只支持给当前回合玩家叠额外回合计数
  - SkipNextTurnFor(player):把玩家加进跳过集合
  - ResolveNextTurnPlayer():先消耗额外回合 →否则给对手；再用 while 循环消化跳过标记(被跳过者的回合作废、顺延到其对手 ——
    双人局里如果双方都被标记，理论上会顺延回自己)

  五、守卫条件(防非法推进)

  - EndTurn()（TurnEngine.EndTurn）:必须 Main + Active + 栈为空才能结束回合
  - CheckPhaseTransition()（TurnEngine.CheckPhaseTransition）:必须 Active + 栈为空
  - AdvanceFromStandby():必须在 Standby 阶段
  - 栈空查询是通过 AttachRuntime(this, () => stackEngine.IsEmpty) 注入的委托（GameCore.Initialize 内），TurnEngine 不直接依赖
    StackEngine ——解耦，可独立测试

  六、主循环(GameLoopController.Update)

  由外部(GameCore.Update)按帧或按需泵动：

  0. StackEngine.IsResolving →直接返回(异步原子效果 await UI 中,防重入)
  1. DurationTracker 清理过期持续效果
  2. ControlChangeLayer 处理过期临时控制
  3. TextChangeLayer 检查文本修改
  4. 战斗阶段:自己的状态机,不管
  5. 栈空 && 可行动阶段:
      ├─ TriggerEngine.PutTriggersOnStack()   ←收集触发式入栈
      ├─ 栈上有东西 →ProcessPriority()(持有者无动作则自动 Pass)
      └─ 栈仍空 && 当前阶段=End && 无待答反问 →CheckPhaseTransition()（2026-09-24 收敛：只做 End→Standby 折返，
         准备→主由 StartNewTurn 自动推进、主→结束只由 IntentEndTurn 驱动，驱动器不得自由滑相位）

  栈结算（现行活路径）：`EffectExecutionEngine.FinishResolution`（自发连锁：结算完→收触发上栈→SBA→再收触发，
  循环到稳定）。`GameCore.ResolveStack`→`GameLoopController.ResolveStack` 整条链**零调用预留**（GameLoopController
  注释已声明语义过时——SBA 已是速度 1 栈对象，真路径在 StackEngine.ResolveStack 的 IsSBA 分支），不要按它理解现行结算顺序。

### 序列化架构
**双轨制**：Unity Inspector 用 `[Serializable]`/`[SerializeField]`，网络传输用 MemoryPack DTO。

| 层 | Unity 序列化 | MemoryPack 序列化 |
|---|---|---|
| 数据类 | `CardData`, `CardEffectData` | `SerializableCardData`, `SerializableCardEffectData` |
| 运行时状态 | `Card._power` 等 internal 字段 | `SerializableRuntimeCardState` |
| 效果定义 | `EffectDefinition`, `AtomicEffectInstance` | `SerializableEffectDefinition`, `SerializableAtomicEffectInstance` |
| 网络消息 | — | `NetworkMessage` 信封 + `MsgPlayCard` 等 |

`SerializableCardEffectData` 现已完整往返 `CardEffectData` 全字段（DisplayName / IsOptional / Duration / Tags / Costs / ActivationConditions / TriggerConditions / Steps），并配套嵌套 DTO `SerializableActivationConditionData` / `SerializableEffectCostEntry` / `SerializableEffectStepData`。
暂不进网络 DTO 的字段（接传输时需登记标签）：`AtomicEffectInstance.SubEffects`、`DurationValue`、`Player.FatigueCount`。

**MemoryPack 标签系统**：
- 属性标签：`TagTable.cs`（共 240 个 `const int`），由 `Tools/刷新属性排序（新增序列化字段时使用）` 编辑器工具（`Assets/Editor/配置/RefreshMemoryPackOrder.cs`）从 `"ClassName.PropertyName"` 经 MurmurHash32（seed `0x53796E67`）自动生成，含碰撞检测。
- 效果标签：64 位 MurmurHash3，从效果描述文本动态生成
- 新增属性需在 `GetTagDefinitions()` 加一行（唯一真相源），点菜单刷新生成 `TagTable.cs`

**关键转换路径**：
```
JSON → CardLoader → CardData → SerializableCardData → byte[] (网络传输)
byte[] → SerializableCardData → CardData → CardWrapper (运行时)
Card → SerializableRuntimeCardState → byte[] (状态同步)
```

### 卡牌数据模型
- `CardData`：纯数据容器（ID, Supertype, CardName, Life, Power, Cost, Effects, Tags, Keywords, ArrowDirections/LinkAuras, NoAttack/NoGuard, Durability, SpeedBonus）；`Keywords` 为 legacy 兼容列（关键词引用化后主路径走 `effectIds` 直引原子 refId）
- `Card`：partial class，继承 Entity，通过接口组合属性（IHasSupertype, IHasName, IHasLife 等）
- `CardWrapper`：连接 CardData 和 Card，实现所有接口
- Entity 效果扩展字段在 `EntityEffectExtensions.cs` 的 partial Card 中

### 属性计算与事件路由（唯一规范路径）
- **LayerEngine 为唯一属性计算路径**：`LayerEngine` 已重构为 MTG 标准 7 语义层（L1 Copy → L2 Control → L3 Text → L4 Type → L5 Color → L6 Ability 增删 → L7 Power/Toughness，L7 含 7a CDA→7b set→7c counters→7d ±增减→7e switch 子层）。属性查询统一走 `LayerEngine.CalculatePower/Toughness/Cost/Colors`。原 `ModifierSystem`/`AttributeCalculator`/`Unit`（旧 AttributeSystem.cs）已废弃，连续效果以 `TargetEntity` 为作用域，不再「对所有实体无差别生效」。
- **统一事件路由**：所有事件经 `GameCore.PublishEvent<T>` 单点分发——先过 `ReplacementEngine.CheckReplacements`（取 `GetFinalEvent()`），再依次 `EventManager.Publish` + `TriggerEngine.OnEvent` + `LayerEngine.OnEvent`。`TurnEngine` 不再持有私有 PublishEvent，回合/阶段事件可到达 Trigger/Layer。
- **连续效果失效为事件驱动**：UntilEndOfTurn / UntilLeaveBattlefield 由 `TurnEndEvent`/`PhaseEndEvent` 钩子驱动 `ContinuousEffectDurationTracker` 与 `TextChangeLayer` 失效；UntilNextTurn / ForTurns 由「到期全局回合戳」失效（GameCore 在 TurnStart 推送全局回合数、TurnEnd 携带 `e.TurnNumber` 检查戳）。
- **已知缺口**：`LayerEngine` 的 `LayerContinuousEffect`（AddPowerToughnessBuff 注册的 P/T 修改）尚无失效接线——`RemoveLayerContinuousEffect` 零调用、tracker 的 `AddEffect` 无生产者；`ContinuousEffectDurationTracker` 的 UntilEndOfTurn 失效路径就绪但未投用。接通会改变现行卡牌行为，列为待办。

### 持续时间计价与档位（实现细节）
- 唯一枚举 `DurationType`（Enums/Zones.cs）：Once / Permanent / UntilEndOfTurn / UntilLeaveBattlefield / WhileCondition / **UntilNextTurn** / **ForTurns**。ForTurns 的 N 存 `AtomicEffectInstance.DurationValue`（条目 `AtomicEffectEntry.DurationValue` 经 `CardEffectConverter` 映射）。
- 旧表侧枚举 `EffectDurationType` 已删除并入；xlsm 旧名经 `AtomicEffectTable.ParseDurationType` 别名归一（Instant→Once、UntilCondition→WhileCondition、UntilEndOfPhase→UntilEndOfTurn）。此修复消灭了 `CardEffectConverter` 曾按 int 跨枚举强转的错位映射（旧表 Permanent(4) 会被误转为运行时 WhileCondition(4)）——配置导出后表内 DurationType 列语义首次真正生效。
- 折扣表：`ValueSystemRuntimeConfig.AttributeValueConfig`（字段化，P3 可调）；费用接线：`CostDerivationService.ComputeAtomCost`（相对折扣 D(实际)/D(表默认)）；编辑器同步：`Assets/Scripts/HotUpdate/UI/Data/CardCostCalculator.cs`。

### 规则扩展点（OCP 定案）
规则修改类效果不修改引擎热点，按机制接入；热点（GameCore/GameActions/KeywordRules/Zones）只认扩展点、禁止点名具体系统（组合根 GameCore.Reset/InitGame 除外）：
- **ReplacementEngine（替代引擎）**：事件内容改写。伤害与疲劳已前置路由——`KeywordRules.ApplyDamage`/`ZoneManagerExtensions.ApplyFatigue` 结算前构造事件过替代取最终值，结算后发布最终 `DamageEvent`（调用方不再补发）。替代件状态无关（实时查询光环），随对局重挂（时序在 `ReplacementEngine.ClearAll` 之后）
- **RuleHooks（`Effects/RuleHooks.cs`）**：行为许可与数值查询注册表（仿 CostHandlerRegistry 惯例）——出牌限制 `IPlayRestriction`（PlayCard 遍历询问）、非手牌出牌来源 `IPlaySource`（如墓地视手牌）、回合开始自动化拦截 `ITurnStartInterceptor`（如跳过准备阶段）、手牌上限链 `IHandLimitModifier`（基值 7）
- 新规则 = 新类 + 登记 + 配置条目
- **DeathRules（`Attribute/DeathRules.cs`）**：死亡决策表——唯一的死亡决策点。`DeathCause` 枚举 6 位（DamageLethal/LifeLoss/LifePayment/ZeroToughness/DestroyEffect/Annihilate；2026-10-09 牺牲转直送、吞噬并入消灭，两死因位 2026-10-30 枚举收拢实删；Poison 已删 2026-10-08——剧毒转关键词 Venom，消灭走 DestroyEffect 口径）× 护盾矩阵（**2026-10-13 起仅剩不灭→拦消灭**；原神佑行已随神佑退役删除）。死亡判定点全部收敛到 `TryKill`（结算 handler / SBA / 剧毒 Venom 走全流程；ApplyDamage 内联只消费 `IsShielded` 决策，落墓交 SBA）。湮灭特判直送除外区且复生跳过。**世界观定案**：角色=普通生物单位（`_keywords` 上移 `Entity` 基类，Player/Card 同构）；**神佑（DivineProtection）已于 2026-10-13 整体退役**——原「Player 默认持有神佑」改为消灭行 `TargetFilter=NoRole` 在目标层滤角色，引擎层不再为角色保留免疫，`CardPipelineVerifier` 断言双方角色无该关键词。术语定案见 `README.md`（原 `设计文稿.md`）。

### 自发连锁与事件路由（触发时点全通）

- **自发连锁**（`EffectExecutionEngine.FinishResolution`，无头/AI 的 StackEngine 路径）：单次连锁结算完成 → ① 累积触发上栈开新连锁 → ② `SBAEngine.ExecuteAll()`（`ZeroToughnessChecker` 现也捕获战场尸体 `!IsAlive`——伤害致死只标死、送墓靠 SBA）→ ③ SBA 事件经路由喂触发引擎 → 循环到稳定（guard 16）。
- **事件路由**：handler 基类 `PublishEvent` 已改走 `GameCore.PublishEventRouted`（原直发总线使触发引擎收不到 handler 事件）；`PublishEventRouted` 增 `replacementsApplied` 参数——伤害管线在 `KeywordRules.ApplyDamage` 前已消费替代，结算后发 `DamageEvent` 时跳过二次替代。补全时点：回合抽牌发 `CardDrawEvent`（On_CardDraw）、`ZoneContainer.Move` 出战场发 `CardLeaveBattlefieldEvent`（On_LeaveBattlefield，原死类型）、攻击宣言经路由（On_AttackDeclare）。
- **KeywordAppliedEvent**（`GameEvents.cs`）：关键词生效统一观察点，战报〔关键词〕行；发布点覆盖 KeywordRules/CombatSystem/EffectExecutor/GameCore。

### 目标选择 spec 计划（2026-11-08 目标选择重构·选择从 handler 搬回数据）

参照族（活体炸弹/护甲等分段原子）的目标选择全部由**引擎 spec 计划**统一执行，`IAtomicEffectHandler.ExecuteAsync` 内禁止发起任何目标选择（守卫：`TargetSelectionService.Begin/EndHandlerScope` + `context.ApprovedSpecKeys`，越权请求 `TideLog.Error` 点名）。

- **表三列**（`原子表_一般效果.json`）：`RefDomain`（参照域，复用 Domain 选择器文法）/ `RefPick`（Cast=声明期选、Resolve=结算期问、Auto=不弹窗）/ `RefRequired`（v1 恒 true）。`Domain` 恒为**受体域**（被作用对象），与 RefDomain 各自独立产轴——converter 的「kinds 收窄空挂 null 回落」特例已删。
- **spec 计划**（`EffectHandlerRegistry.CollectSpecPlan`，声明期/结算期/LAE/SimpleAI 单源）：① Reference spec 前置（候选只做可见性过滤——无帷幕/守护/OnTargeted，参照不是被施加效果的对象）；② Target spec 按**同域分组共享**（沉默+消灭同域并列→单窗同目标；跨域并列卡各自 spec）；③ 分段受体 spec 尾置（`AiMode=Auto`——LAE 不展开，引擎/AiOrder 代选，不做 N×M 笛卡尔积）。`SpecKey`（`atom:{i}/spec:{j}/role:{r}`）为网络/重放/AI 代选的显式关联键。
- **Refs/Targets 分储**：`context.Refs["ref"]`（参照）与 `context.Targets`（受体）严格分离；网络 v10 分角色上送（`MsgIntentPlayCard.References`/`StackItemDTO.References`/`MsgSelectRequest.SpecKey`）。LAE 动作空间 v13：动作特征 12 维新增 `[11] referenceIndex`（参照选位镜像槽位）。
- **动态数值**（步6）：效果条目 `valueExpr`（白名单 `ref.power|ref.life|ref.cost`，结算期经 `EffectExecutionContext.ResolveValue` 读参照活值）+ `valueMax`（静态上界，只告警）；**定价恒按 `value` 名义锚**（不按上界/表达式定价）。教学炸弹 `ref.power`/`ref.life` 已落 `TutorialEffects.json`。
- 验证器：`Tools/验证/spec计划（目标选择重构）`（SpecPlanVerifier，15 断言）+ `Tools/验证/参照族双段目标三原子`（RefAtomSingleTargetVerifier 回归锚）。通用化债务（守卫已登记）：RedirectTarget/DiscardCard/Sacrifice/Discover/MoveUnit 五处 handler 内反问待后续迁入 spec 计划。
