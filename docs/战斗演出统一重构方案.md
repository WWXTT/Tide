# 战斗演出统一重构方案（演出 = 剧本回放）

> 2026-11-11 · 第三版（**对接 C 案「联机战报行流改造方案」**）
>
> 用户需求：
> ① 联机模块要有「日志回放」；把**实际战斗演出**和**回放**统一成一块，都是回放逻辑——
>    区别只在：实际战斗要等双方玩家输入，回放输入确定、跳过等待。
> ② 日志来源统一为**服务端跑同一份 `MatchLogRenderer`**：对战按座位遮蔽，回放无遮蔽。
> ③ 回放时日志变成**进度条**：可点击任意一段，从那里开始播放。
>
> **环境现状（2026-11-11 15:30）**：C 案 P1 已由 ZCode 落地中——
> `MatchLogLineStream`（新）、`MatchLogRenderer`（R1/R2 + `EffectShortName` 下沉）、
> `NetRoom`（三视角行流 + 行历史）、`BattleLogController`（本地委托行流）、
> `BattleViewData.EffectShortName`（转发）已在工作区；**协议 135 / 下发 / 客户端消费属 C 案 P2**，
> 尚未实现；`NetLogRenderer` 仍在（P3 删）。本方案**不重复实现日志**，只在 C 案之上加
> 「演出帧、回放录制、时间轴、演出事件子集、回放全量行通道」。
>
> 本版原则：**C 案是日志的唯一事实源**；本文只定义它没有的三件事（演出帧/回放/时间轴），
> 以及为支撑它们所需的**最小扩展**（§2.7.2 / §2.7.3 / §2.7.4）。

## 0. 结论摘要

三件事：

1. **演出 = 剧本回放**：所有战斗演出（本地/联机/回放）走同一个 `BattlePlayhead`，
   消费同一种 `BattleFrame`（局面快照 + 战报行 + 演出指令数据）；回放额外支持 `SeekTo`。
2. **日志 = C 案行流**：服务端 `MatchLogLineStream` 逐视角渲染、`NetLogBatch`(135) 下发；
   客户端只 `AppendServerLine`。本文不碰 C 案已定的行流/遮蔽/时序。
3. **回放 = 录制剧本 + 时间轴**：联机对局结束自动录一份（行流遮蔽版 + 终局全量行）；
   回放时战报面板=时间轴（全部行预铺、当前行高亮、点击跳转）。

为了支撑 1/3，需要对 C 案做 **三处最小扩展**（都在本文 §2.7 写死，避免与 C 案打架）：

| 扩展 | 内容 | 为什么必须 |
|---|---|---|
| **E1 演出事件子集** | C 案 P3「人类停发事件流」改为 `EventFeed` 三态：`None / FxOnly / Full`；人类收 `FxOnly`（约 14 类演出事件 + 三个结算边界），AI 保持 `Full` | 没有逐事件数据，联机就没有「攻击步/伤害/死亡/拼点」的演出，也无法录回放帧 |
| **E2 回放全量行通道** | 新增 `MatchLogFull=136`（复用 `MsgNetLogBatch` 载荷）：终局给每个座位发一份 `redactHidden=false, redactEffectSummary=false` 的全量行 | C 案的座位行流是**遮蔽版**；「回放无遮蔽」需要服务端另出一份全量版 |
| **E3 R1 遮蔽与观侧解耦** | `MatchLogRenderer`/`MatchLogLineStream` 增加 `redactHidden` 参数（本地 false、服务端座位 true、全量 false） | 现行 C 案 P1 把 R1 闸挂在 `isSelf != null` 上——**本地局也会遮 AI 的检索入手**，违反 C 案自己「本地逐字不变」的验收 |

**阶段协调**：C 案 P1–P3 由 ZCode 收口；本文的 **S1（播放器骨架）可并行**（只碰
`BattleScreen.cs`/`BattleProjector.cs`/新文件，不碰 C 案在改的日志文件）；**S2 起必须等 C 案 P3 落地**
（S2 的 `BattleLogController` 时间轴与 P3 同文件）。

### 1.3 分裂点（本重构要消灭的重复）

1. **两个导演**：本地 `BattleResolutionDirector`（步进/节拍/hold/看门狗） vs 联机「无导演，来什么放什么」。
2. **两套演出源**：本地 `DeferOrRun` 闭包（引擎实体）；联机零演出。
3. **两套战报时序**：C 案已收口到 `MatchLogLineStream`（本地 UI 已委托）——本方案沿用，不再另做。
4. **两套局面刷新**：本地 `BuildLocal`；联机 `BuildNet`（都产出 `BattleViewData`，这一层已统一）。

### 1.4 输入等待点（实际战斗中「等输入」的真实位置）

- 目标/选项反问：`TargetSelectionService` → `RegionTargetSelector`；
- 响应窗：`ResponseWindowService` → `BattleDecisionHub`；
- 玩家意图（出牌/放地/攻宣/技能/结束回合）：`GameActions.*`，由 `BattleScreen.Board.cs` 调用；
- AI 节奏：`SimpleAI.PacingWait` 等视觉门 + 导演空闲（`BattleScreen.Local.cs:449-461`）；
- 联机：`SelectRequest/TextRequest` 反问 + intent 上行（`BattleScreen.Net.cs:800-879`）。

> 这些等待**不搬进播放器**（属于对局驱动层）。播放器只认「帧还没来」——实际战斗时
> 队列空且回合未完 = `WaitingForInput`；回放时剧本完整 = 永不等待。

### 1.5 C 案 P1 的一处偏差（E3 的依据）

现行 `MatchLogRenderer` 的 R1 分支闸是 `isSelf != null && !isSelf(hand.Player)`——
`BattleLogController` 本地构造行流时传 `isSelf = p => p == P1`（非 null），**本地局对手（AI）
检索入手也会被遮成「未知卡」**。C 案自己的验收要求「本地局行为逐字不变」，因此必须把
「观侧」与「是否遮蔽」解耦：新增 `redactHidden`（本地 false、服务端座位 true、回放全量 false）。

## 2. 目标架构

```
             ┌─────────────── 生产者（三种，产同一种帧）───────────────┐
引擎事件 ──▶ │ LocalFilmSource（本地实时）                              │
服务器下行 ─▶ │ NetFilmSource（联机实时：行流 + 演出事件子集 + 快照）    │──▶ BattleFrame 队列
剧本文件 ──▶ │ ReplayFilmSource（回放，一次性）                          │
             └───────────────────────────────────────────────────────┘
                                   │
                         BattlePlayhead（唯一播放器）
             每帧：PreOps → ApplyView → Ops → 战报行 → 等视觉 → 节拍
                     回放另支持 SeekTo(帧)（时间轴点击跳转）
                                   │
                     IBattleStageSink（战斗屏实现 / 自检器桩实现）
```

### 2.1 帧模型（`BattleFilm.cs`）

```csharp
public enum BattleFrameKind { Step, View, Input, RoundEnd, End }

public sealed class BattleFrame {
    public BattleFrameKind Kind;
    public string Label;          // 步标签：卡名 / 攻击宣言 / 守卫宣言 / 状态动作 / 阶段窗口
    public uint   CardRid;        // 卡牌步的 RuntimeId（0=非卡步）
    public bool   IsAttack;       // 攻击步（战斗演出驱动位）
    public int    Remaining;      // 步后余栈
    public BattleViewData View;   // 本帧要应用的局面（可空：联机事件帧常常没有快照）
    public List<BattleLogLine> Lines = new();
    public List<BattleFxOp> PreOps = new();  // 应用 View 之前（死亡预持等）
    public List<BattleFxOp> Ops    = new();  // 应用 View 之后（伤害/回复/拼点/飞行/浮字…）
    public CombatShot Combat;     // 攻击步的战斗演出（可空）
    public BattleInputRecord Input; // Input 帧：录制的玩家决定（回放展示/未来输入闸）
    public int LogBoundary;       // 过渡字段（S1/S2 本地 Live 沿用日志 Hold 水位；S5 后删除）
}

public sealed class BattleLogLine {
    public uint   EventId;      // 与 MatchLogLine/NetLogLine 对齐（遮蔽版↔全量版合并、行↔帧映射）
    public int    FrameIndex;   // 归属帧（时间轴跳转目标；-1=帧前）
    public string Text;         // 当前视角文本（对战=遮蔽版；回放=无遮蔽版）
    public string FullText;     // 无遮蔽版（本地=同 Text；联机=终局 MatchLogFull 按 EventId 回填）
    public byte   Kind;         // MatchLogLineKind（C 案 1B 色编码）
    public byte   Flags;        // MatchLogLineFlags（ChainStart/ChainEnd/GameOver/TurnStart/FirstDraw）
    public string Class;        // log-line--*（UI 直用；由 Kind 反查）
}

public sealed class BattleFilmHeader {
    public int Version; public string MatchId; public int Mode; public int ViewerSeat;
    public string SelfName, OppName; public int Seed; public long CreatedAtUnix;
}

public sealed class BattleFilm { public BattleFilmHeader Header; public List<BattleFrame> Frames = new(); }
```

**帧 #0 恒为 `View`（开局局面）**；**行→帧映射**：每帧记 `LastEventId`（该帧最后一条事件的 EventId），
一行按 `FrameIndex = 第一个 LastEventId >= line.EventId 的帧`；对不上的行（帧前历史）记 -1。

序列化：`TideJson`（只序列化 public 字段）+ GZip。`BattleCardView.CoreCard` 加 `[NonSerialized]`。

### 2.2 演出指令（`BattleFxOp`，数据而非闭包）

现状演出是 `Action` 闭包（`BattleProjector.DeferOrRun`），不可录制、联机也用不了。
改成数据指令，由**唯一执行器**按帧解释：

```csharp
public enum BattleFxKind {
    Damage, Heal, Flight, Death, DeathHold, Arrival, Paid, Fatigue,
    CounterFloat, CounterBurst, KeywordBurst, DeckMark, Clash, LuckRoll,
    PhaseAnnounce, DrawFlyIn
}

public sealed class FxRef {               // 视图空间引用（不持有引擎对象）
    public uint Rid; public int Seat; public string CardId; public bool IsPlayer; public string Name;
}

public sealed class BattleFxOp {
    public BattleFxKind Kind;
    public FxRef Source, Target;
    public int Amount;
    public int Tint = -1;                 // ManaType，-1=无（捕获时已解析好颜色）
    public int CastX = -1, CastZ = -1;    // 法术位（-1=无）
    public int Reason;                    // DestroyReason / GameOverReason 等
    public bool Flag;                     // Success / IsAdd / blessing / debuff / FirstDraw
    public int D1, D2, Threshold;         // 运势
    public int Seat = -1;                 // 疲劳/抽牌归属
    public string Text;                   // counterType / 阶段名 / 备注
    public Dictionary<int, float> Paid;   // 入场粒子色（实付账单：色→量；可空）
}

public sealed class BattleInputRecord {   // Input 帧载荷（v1 只记录/展示）
    public int Kind; public int Seat; public string Text;
}
```

**执行器**（`BattleFxOpExecutor`）把 `FxRef` 解析成场上单位/角色立柱，调用 `BattleFieldView`
新增的 ref 版入口（`BattleFieldView.PlaybackFx.cs`，与 `Entity` 版共用私有实现）：

- 目标解析：`_units[Rid]` 或 `_heroes[Seat]`；
- 源锚点：单位 `Rid` → 单位胸口；否则 `Seat` → 角色立柱；法术位 `CastX/Z` 优先；
- 颜色：捕获时已写入 `Tint`，执行器不再查引擎；
- 死亡预持：`DeathHold(rid)` 在 `PreOps`，`Death(rid)` 在 `Ops`。

**战斗演出（CombatShot）**：

```csharp
public sealed class CombatShot {
    public FxRef Attacker, Target, Blocker;
    public int TargetX, TargetZ;
    public List<CombatHit> Hits = new();   // Target / Amount / Lethal / IsCounter
}
```

- 本地实时：编舞器捕获时写进攻击帧（编排能力不变）。
- 回放 v1：按 shot 跑「攻击者飞向目标 → 命中/受击 → 伤害浮字 → 死亡退场」；
  守卫闪现/反击/溅射的精细走位暂不还原（战报行照常），登记为已知差异。
- 联机实时：只有伤害/死亡事件（FxOnly 流），用事件流播打击感（S4）。

### 2.3 播放器（`BattlePlayhead`）

职责（取代 `BattleResolutionDirector`；接口兼容 `Busy`/`WaitIdleAsync`/`Tick`/`Shutdown`）：

```csharp
enum PlayMode { Live, Replay }
void Enqueue(BattleFrame f);      // 生产者投帧（Live）
void Load(BattleFilm film);       // 回放整包投帧（Replay）
bool Busy { get; }
bool WaitingForInput { get; }     // Live：队列放干且回合未完
int  CurrentFrame { get; }
UniTask WaitIdleAsync();
bool SeekTo(int frameIndex);      // 回放专用：跳到某帧段首并继续播
void Tick(); void Shutdown();
```

播放循环（每帧）：

1. `PreOps`（死亡预持）；
2. `View != null` → `stage.ApplyView(View)`；
3. `Ops` → `stage.ExecuteFx(op)`；
4. `Lines`：Live → `stage.AppendLog(line)`（按帧放行）；
   Replay → 不逐条追加（全量已预铺），只 `stage.SetTimelineCursor(帧号)`；
5. `Combat != null` → `stage.PlayCombat(shot)`；
6. `await stage.WaitVisualsIdleAsync()`；
7. 节拍：本地 Live 900ms/步；联机 Live 350ms/步；Replay 350ms/步；
   联机积压 >6 帧时压缩停顿（不跳演出）；
8. `RoundEnd` 帧：收尾（释放 hold、强对账、链消散延迟）。

Live/Replay 唯一分支：Live 队列空+未收尾=等输入；Replay 一次给全、末帧 `End` 收尾、不等待输入。

**SeekTo**：`epoch++` 作废在途 → 清队列 → 中止在途演出（`ReleaseAllHeldStats`/`CancelTargeting`/
`Dissolve`）→ 应用目标帧之前最近一个 View → 时间轴游标 → 从目标帧续播（跳过帧不播演出）。

### 2.4 生产者

**`LocalFilmSource`（本地实时）**
- 钩子：`StackResolutionStart/End`、`StackEmpty`（建 Step/RoundEnd 帧）；
- `View=CaptureSnapshot()`；`Lines` 由 `MatchLogLineStream`（本地 `redact=false`）产出，
  按「上一帧边界→本帧边界」归帧并写 `FrameIndex`/`LastEventId`；
- `PreOps/Ops`：投影器事件钩子捕获时构造 `BattleFxOp`（只录制，不执行）；
- `Combat`：编舞器攻击步捕获写入；
- 录制：帧内存攒到终局 → `BattleFilmStore.Save`（GZip）。

**`NetFilmSource`（联机实时）**
- 事件源 = **`EventFeed.FxOnly` 的 `NetEventBatch`**（E1；含 `StackResolutionStart/End/StackEmpty`
  与 §2.7.2 白名单事件）→ 按 `StackResolutionEnd` 切步、`StackEmpty` → RoundEnd；
- `Lines` = **`NetLogBatch`(135) 的 `NetLogLine`**（C 案；按 `EventId` 归帧），不再用客户端渲染；
- `Ops` = `NetFxMapper`（NetEvent → `BattleFxOp`，映射表同 §2.4 上一版）；
- `View` = `GameStateSyncV2` 到达时投 `View` 帧（决策点粒度，已知限制）；
- **交互数据与播放解耦**：`_netSnapshot`/回合计时/选目标候选在收到时立即更新，
  只有局面渲染+战报行+演出按帧节拍走；积压 >6 帧压缩停顿。
- 录制：帧 + 遮蔽行；终局 `MatchLogFull` 到达后按 `EventId` 回填 `FullText` 重写剧本。

**`ReplayFilmSource`（回放）**
- `BattleFilmStore.Load(id)` → 逐帧投给 `PlayMode.Replay`；无输入询问；`Input` 帧只展示。

### 2.5 录制与存储（`BattleFilmStore`）

- 目录：`persistentDataPath/Films/<matchId>.film.gz`（**不进云存档**）；
- 接口：`Save/Load/Has/Delete/Prune(keep=20)`；
- 联机：`OnGameOver` 先存遮蔽版；`MatchLogFull` 到达后按 `EventId` 回填 `FullText` 重写；
- 本地：S2 起默认录最近一局（调试用）；
- 上限：单局 2000 帧、单帧 JSON 上限、目录 20 局。

### 2.7 日志行流（C 案）与本文的三处扩展

#### 2.7.1 C 案要点（已定，本文不改）

- `MatchLogLineStream`（CardCore，`MatchLogLineStream.cs:50`）：时序整理单源（建局静默/自然抽挂起/
  阶段放行/旗标），本地 `BattleLogController.ProcessEntry` 已委托；
- `MatchLogLine { Text, Class, Kind, Flags, EventId }`；`Kind`=1B 色编码，`Flags`= ChainStart/ChainEnd/GameOver/FirstDraw/TurnStart；
- 服务端（`NetRoom`）三视角流：seat0/seat1（`isSelf=引擎座位`，`redactEffectSummary=true`）+ 观战 -1（`isSelf=null` 中立实名）；
- 协议：`NetLogBatch=135` + `MsgNetLogBatch{ NetLogLine[] Lines }` + `NetLogLine{ Kind, Flags, EventId, Text }`；`Version=15`；
- 下发：`FlushDownlink` 行流段按 `member.LogCursor` 切片、64 行/批；`LogCursor` 随 `EventCursor` 复位；
- 客户端：`NetGameClient.OnLogBatch` → `BattleLogController.AppendServerLine`；
- C 案 P3：删 `NetLogRenderer`、人类停发 `NetEventBatch`（**本文 E1 修订**）。

#### 2.7.2 E1：演出事件子集（`EventFeed` 三态）

C 案 P3 的「人类停发事件流」会让联机失去逐事件演出与回放帧。修订为：

```csharp
public enum EventFeed : byte { None = 0, FxOnly = 1, Full = 2 }   // INetChannel.EventFeed
```

- `IsAi`（`NetClientBrain`/验证器）= `Full`（不变）；
- 人类座位 / 观战 = `FxOnly`：`FlushDownlink` 只发**演出白名单**事件（+ 三个结算边界）：

| 用途 | 事件类型 |
|---|---|
| 帧切分 | `StackResolutionStartEvent`、`StackResolutionEndEvent`、`StackEmptyEvent` |
| 伤害/治疗 | `AtomicDamageEvent`（IsCombatDamage=false）、`CombatDamageEvent`、`HealEvent`、`LifeChangeEvent` |
| 死亡/入场 | `CardDestroyEvent`、`CardPutToBattlefieldEvent` |
| 状态/属性 | `CounterChangedEvent`、`StatModifyEvent`/`StatSetEvent`（浮字用）、`KeywordEvent`、`FreezeEvent` |
| 战斗/拼点/运势 | `AttackDeclarationEvent`、`AttackResolvedEvent`、`BlockDeclarationEvent`、`ClashResolvedEvent`、`LuckRolledEvent` |
| 效果视觉 | `EffectFlightEvent`、`FatigueEvent`、`ElementPoolPayEvent` |
| 骨架 | `TurnStartEvent`、`PhaseStartEvent`（阶段字/HUD） |

- 过滤在服务端出队处做（按 `EventType` 集合，零改投影）；
- 预算：白名单事件约占全量 1/3（实测待 V11.f 记录）；比全量省 ~60%，同时保住演出/回放；
- 若白名单漏了某类导致演出缺失：只加一行事件类型（不动协议/DTO）；
- 兜底：联机演出异常时把 `EventFeed` 切回 `Full`（一行配置回退）。

#### 2.7.3 E2：回放全量行通道（`MatchLogFull=136`）

C 案座位行流是**遮蔽版**；「回放无遮蔽」需要服务端另一份全量行：

- `MatchLogLineStream`/`MatchLogRenderer` 增加 `redactHidden`（见 E3）；
- `NetRoom` 额外为每个座位建一条**全量流**（`isSelf=该座位, redactEffectSummary=false, redactHidden=false`），
  行历史存 `_logFullHistory[seat]`（仅内存，不下发）；
- 终局 `OnGameOver` 置 pending，**下一次 `FlushDownlink` 末尾**（等本局事件/遮蔽行发完）发：
  `NetworkMessageType.MatchLogFull = 136`，载荷复用 `MsgNetLogBatch`（`NetLogLine[]`）；
- 客户端 `NetGameClient.OnLogFull` → 按 `EventId` 回填剧本 `BattleLogLine.FullText` 并重写 film；
- AI 填位局也发（用户仍要看自己的复盘）；观战同样发（全信息）；
- 断线/未到达：复盘退回遮蔽版（`Text`），登记为已知限制。

#### 2.7.4 E3：R1 遮蔽与观侧解耦（修正 C 案 P1 的本地偏差）

```csharp
public static Line Render(IGameEvent e, Func<Player, bool> isSelf,
                          bool redactEffectSummary = false, bool redactHidden = false)
public MatchLogLineStream(Func<Player, bool> isSelf, bool redactEffectSummary, bool redactHidden = false)
```

- R1 分支改为 `redactHidden && isSelf != null && 对手 && 隐藏区来源 && !Exposed`；

- 服务端座位流传 `redactHidden:true`；观战/导出/全量流传 `false`；
