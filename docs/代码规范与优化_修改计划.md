## 0. 总原则与禁止清单

### 0.1 总原则

1. **语义零变化**：S1–S3 的任何改动都不得改变运行时行为、日志文本、public 方法签名、预制体/场景绑定名。
2. **一次一阶段**：每阶段编译 + 自测 + 贴证据 + 停下，不自行进入下一阶段。
3. 范围硬边界：只改「§2 范围清单」内文件；发现范围外的问题只写进报告的「后续」栏，不动手。
4. 每阶段独立可回滚：阶段结束必须贴 `git status --short` + `git diff --stat`，按文件清单核对。
5. 遵守项目既有约定：UI 只绑定不生成（禁运行时拼 UI 节点）、临时文件只写 `.ztmp/`、不新建 runtime `.cs`（除非本计划点名）。

### 0.2 禁止

- 禁止批量格式化整个项目（会产生上万行巨型 diff，无法审阅）；只格式化「本阶段碰到的文件」。
- 禁止重命名 public 类型/方法/字段/序列化字段（Unity 序列化与场景引用会断）。
- 禁止改规则、数值、牌表、支付链、协议、预制体版式、`.meta` 的 GUID。
- 禁止动生成文件 `Assets/Scripts/HotUpdate/AOTGenericReferences.cs`、第三方目录 `Assets/Scripts/HotUpdate/Lib/**`、插件目录。
- 禁止启用 `TreatWarningsAsErrors`、禁止引入新 NuGet/分析与器包（本项目无 `Directory.Build.props`，不新增构建体系）。
- 禁止「顺手优化」范围外的逻辑；禁止把「行为可疑」当 bug 直接改（只记录）。
- 禁止在 S1–S3 期间开 Unity 的 Play 模式改场景（避免污染 `ProjectSettings`/场景文件）。

## 6. 阶段 S2：死代码与重复清理（同范围）

**目标**：本轮交付面里「写了但没用」「四份一样」「注释说 A 实现是 B」的清理，**不动行为**。

### 6.1 清理项

1. 未使用的私有字段/方法/常量（Unity 序列化字段除外，用 `[SerializeField]` 判断）。
2. 「按钮退役」后的空实现（`RefreshActionButtons`/`OnUseClicked`/`OnPlaceClicked`）——保留但必须写清「为何保留」+ 收敛为一个注释块，不重复空壳。
3. 重复 helper：同一语义的多份实现（如格坐标换算、色片索引、面片尺寸）合并到单源；被合并的调用点全改，不留双份。
4. 过期注释与死分支（`if (false)`、永假条件、已退役阶段的遗留 flag）。
5. 调试残留：`Console.WriteLine`、临时 `TIDE_DEBUG_*` 开关的**非必要**输出（保留计划明确要求的 `[dbg-ai]` 等，需在报告里说明保留理由）。

### 6.2 硬约束

- 删代码前必须 `grep` 全库确认无引用（含 `.prefab`/`.unity`/`Resources` 里的字符串反射绑定，如 `SendMessage`/`Invoke` 名字）。
- 不删 public 成员（即使无人调用，可能有外部/热更脚本引用）；public 的只标 `[Obsolete("…")]` 并在报告里列出。
- 不改泛型约束、不改方法签名。

## 7. 阶段 S3：热路径性能优化（同范围）

**目标**：把「每帧/每结算」路径的分配与查找消掉，收益可量化。

### 7.1 优先目标（按收益排序）

1. `UiKit.cs`（1377 行，含 `Update` + `GetComponent`）：缓存组件、去掉每帧 LINQ/闭包。
2. `Battle3D/**` 的每帧对账：面片/色片池化差量（若 A/C 阶段已做，则改为**核对**并补 `Profiler` 证据）、`Physics.Raycast` 复用 `RaycastHit[]` 非分配版、`List` 复用（`Clear()` 不 `new`）。
3. `CombatChoreographer.cs`：每段演出的闭包/`UniTask` 分配，能缓存的缓存。
4. 事件回调里的字符串拼接日志：高频路径改「开关 + 预格式化」或降级为 `TideLog.Debug`（默认关）。
5. `BattleHoverInfoProvider.cs`：悬停文本每帧重算 → 变更检测（上一次 key 与本次相同则跳过）。

### 7.2 度量要求

- 优化前后各给一组数字：用 `dotnet` 无头跑 `TideSim --games N` 的 GC 分配/耗时（`TIDE_PROFILE` 或现有统计口），或 Unity Profiler 截图（ZCode 自己跑一局木桩，抓 `GC Alloc` 列）。
- 若某项没有可测收益 → 不做，写进报告「评估后放弃及原因」。

### 7.3 硬约束

- 不改算法语义、不改结算顺序、不改随机种子路径（AI 决策必须逐字节可复现：`TideSim --games` 同种子结果一致）。
- 不引入对象池框架/第三方库；复用现有池化手法（`_units`/`_icons` 差量口径）。
- 每项优化单独可回退（一个文件一处改动，便于 cherry-pick 式回退）。

### 7.4 验收

- [ ] 构建全绿；TideSim 回归 + **同种子复现性**验证（优化前后 `--games 3` 结果一致）。
