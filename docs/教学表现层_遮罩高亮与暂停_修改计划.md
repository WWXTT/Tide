# 战场遮罩 / 高亮 / 暂停系统 · 修改计划（v0.4）

- 日期：2026-11-21（v0.4 按用户 2026-11-21 晚第三轮口径修订：**断线=结束**、联机只开房间对战、未来项登记到拓展方向；v0.3 曾定遮罩含 UI、单窗、通用暂停；v0.1 的「UI 压暗层 / 配音暂停」作废，
  v0.2 的「遮罩只做相机画面、UI 天然清晰」也作废——**遮罩是有 UI 遮罩的**）
- 状态：**计划（未实现）**。实际改动统一交 ZCode 实施，本文只定口径、schema、落点与验收。
- 依据（用户 2026-11-21 晚原话要点）：
  1. **遮罩是有 UI 遮罩的**：把**相机画面输入到一张遮罩图片**里，图片盖全屏、在关键位置挖窗——
     所以窗外连 UI 一起被盖掉。上一版"只糊相机、UI 不参与"的实现与预想不符。
  2. **高亮**对象 = **战场 3D**（模型 + 战场上用 **3D TMP 渲染的文字**），走**后处理选择描边**。
  3. **暂停 = 游戏逻辑 + 表现一起停**，这个功能本来就要做（**对手掉线时用**）；**代打先屏蔽**（后续按玩家需求再开）。
     教学只是调用方：解说摆出来 → 暂停 → 点【确定】或点窗内 → 恢复并下一步。
     **哪些教学步需要暂停，后续由用户指定**——先把功能做通，默认不挂。
  3b. **但"谁掉线"要按拓扑说清**（2026-11-21 用户指出）：房主就是服务器，**房主掉线=整房解散**，
     客人端没有可恢复的对局，也**判断不了是自己断还是房主没了** → 见 §5.4，本期只做中性提示+退出/结束。
  4. **每个步骤只开一个窗**（不做多窗）。
  5. 交互口径以**点击 + 按钮**为准（拖拽只作辅助，可忽略）。

## 1. 现役底座（v0.2 重新核对）

### 1.1 渲染

- Unity **6000.5.10f1**；URP **17.5 本地魔改分支 `DanbaidongRP-urp17`**（`Packages/manifest.json:30`）。
- [DbdURP.asset](../Assets/Settings/DbdURP.asset)：HDR 开（`:27`）、MSAA 1×（`:29`）、RenderScale 1（`:30`）、
  **深度图必开**（`:23`）、`m_RequireOpaqueTexture: 0`（`:24`）、SRP Batcher 开 / 动态合批关（`:81-82`）。
- [DbdURP_Renderer.asset](../Assets/Settings/DbdURP_Renderer.asset)：**Deferred**、`postProcessData` 已挂（`:48`）、
  feature 表只有一个 `ScreenSpaceShadows` 且**未启用**（`:43-46`）→ 加自定义 pass 的插槽是空的。
- Bloom 生效源 = Main 场景 Global Volume 的 [Low.asset](../Assets/Settings/Low.asset)：`mode=BloomDanbaidong`、
  **threshold 0.8**、scatter 0.4、HQ filtering 1、intensity 默认 0.75。
  （`DefaultVolumeProfile` 里的 Bloom `mode=None`，**不生效**，别照它调参。）
- 无 Camera Stacking；只有 Base 相机（Main / Launch）。

### 1.2 UI 与遮罩的关系（v0.3 关键修正）

- 全局单 Canvas，`ScreenSpaceOverlay`、排序 0（[UIBootstrap.cs:55-77](../Assets/Scripts/HotUpdate/UI/Framework/UIBootstrap.cs#L55)），
  Overlay **不参与后处理**：既不吃 bloom、也不会被相机类模糊"糊到"。
- 所以"窗外连 UI 一起盖掉"只能这样做：**把相机渲进 RT → 用一张全屏 UI 图显示它（模糊版）→ 图在窗口位置挖洞**。
  图在 UI 之上，所以**窗外的 UI 被图盖住**（看起来就是"全屏模糊"），窗内是洞 → 露出真实的 3D + UI。
- 3D 战场里的读数（攻/血/耐久、格面数字）是 **TextMeshPro 3D 物体**（[BattleFieldView.Units.cs:520-534](../Assets/Scripts/HotUpdate/UI/Framework/Battle3D/BattleFieldView.Units.cs#L520)），
  在相机画面里 → 会被模糊进那张图；高亮时也能被描边选中（见 §4）。

### 1.3 3D 高亮现状

- 单位 = wrapper + 模型 prefab（拼装刚体：一个模型十几到几十个 `MeshRenderer`，无蒙皮/无 instancing）。
- 现成件：`BattleTileFx` 的格环/扩散波（[BattleTileFx.cs:147-196](../Assets/Scripts/HotUpdate/UI/Framework/Battle3D/BattleTileFx.cs#L147)）、`BattleTargetReticle`、
  `BattleAttackArrow`、`BattleTileFresnel`（rim 数学）。
- **没有**任何针对模型的轮廓/描边实现 → 见 §4。

### 1.4 暂停现状

- **逻辑层已有半个暂停**：`GameStateManager.Pause()/Resume()`（[GameStateManager.cs:33-52](../Assets/Scripts/HotUpdate/CardCore/GameCore/GameStateManager.cs#L33)），
  且 `GameCore.Update()` 被 `CanPerformGameActions`（=Running 才跑）拦着（[GameCore.cs:784](../Assets/Scripts/HotUpdate/CardCore/GameCore/GameCore.cs#L784)）
  → **暂停能停住主循环**（回合推进/栈/结算）。缺的是：谁调、表现层跟不跟、恢复条件、断线场景。
- **表现层没有任何统一暂停**：只有零散开关——`MonsterRigAnimator._paused`（单模型）、`BattlePlayhead.SetPaused`（回放）、
  各 `UniTask` 演出/相机 tween 各跑各的。
- **断线**：联机有超时代打（[NetBattleChannel.cs:730-763](../Assets/Scripts/HotUpdate/CardCore/NetSession/NetBattleChannel.cs#L730)），
  但没有"本地冻结 + 等重连"的暂停态。→ 本轮：**断线改暂停等重连，代打开关先关**（§5.2）。
- **教学**：现役"暂停"= 引擎侧 8 组闸 + UI 门，不是真暂停；解说卡出现时玩家仍能操作（被闸拒）。

## 2. 配置 schema（每步三块；旧档缺字段=不启用）

```jsonc
{
  "type": "attack", "audio": "basics_16", "hint": "…",
  "mask": {
    "target": "unit:C_DA499FAE",   // 每步**只一个**窗（3D 目标，见 §2.1）
    "pad": 16,          // px（1920×1080 参考；运行时按屏幕比例换算）
    "radius": 12,       // 圆角（0=直角矩形）
    "feather": 24,      // 羽化 px
    "strength": 1.0     // 模糊强度 0..1
  },
  "highlight": [
    { "target": "unit:C_DA499FAE", "style": "outline", "color": "#FFD75A", "width": 4, "hdr": 2.5, "pulse": "slow" },
    { "target": "tmp:unit:C_DA499FAE", "style": "outline", "color": "#FFD75A", "width": 2, "hdr": 2.0 }
  ],
  "pause": { "on": false, "resumeBy": "windowOrConfirm", "showHint": true }
}
```

### 2.1 目标词表（**只收 3D**）

| token | 解析目标 |
|---|---|
| `hero` / `oppHero` | 角色（模型） |
| `unit:<卡 id 或实例 id>` | 场上生物（wrapper 下全部 renderer 包围盒） |
| `tmp:<token>` | 该目标身上的 **3D TMP 文字**（攻/血/耐久/卡面读数），如 `tmp:unit:C_DA499FAE` |
| `cell:x:z` | 棋盘格（格环/波） |
| `zone:role` `zone:activation` `zone:p1-land` `zone:mid` `board` `units` | 区域（3D 格群），沿用 `reveal` 词表 |
| ~~`ui:*` / `card:*` / `hand`~~ | **不支持**（UI 不参与；手牌引导靠现成按钮/箭头） |

解析规则：未知 token 记警告跳过；`tmp:` 前缀找不到 TMP 时退回宿主包围盒。

### 2.2 暂停

| 字段 | 值 | 说明 |
|---|---|---|
| `on` | bool | 本步是否暂停 |
| `resumeBy` | `confirm` / `window` / `windowOrConfirm` | 只认【确定】/ 只认点窗内 / 两者皆可（推荐） |
| `showHint` | bool | 暂停期间把 `hint` 常驻横幅（否则玩家看不到解说） |

- **不设** `voice` 模式：配音播完不是暂停条件。
- 自由步（`fieldclear/luckuse/deathtoll`）与 `aiTurnOnConfirm` 交回合动作：`pause` 强制无效（防死锁，见 §2-3）。

## 3. 遮罩怎么落（相机画面 → 遮罩图片 → 单窗挖洞）

因为要连 UI 一起遮，v0.2 的"Renderer Feature 糊相机、UI 不动"作废；改为 **相机 RT + 全屏遮罩图**：

1. **相机渲进 RT**（只在遮罩启用期间）：`MainCamera.targetTexture = crispRT`（HDR、屏幕同尺寸或 0.75×、
   MSAA 1 与管线一致）。**全工程零 RT 先例**，格式/竖切 resize/释放要一起做（见 §8 风险）。
2. **模糊链**：`crispRT` → 1/4 分辨率 `halfRT` → 分离高斯（H/V 各 2 pass，`strength` 控半径）→ `blurRT`。
3. **UI 三层（烘焙在 `BattleUI.prefab`，不代码拼）**：
   - 底层 `mask-bg`：全屏 `RawImage` 采样 `crispRT`（因为相机不再直接画到屏幕，没有它屏幕是空的）；
   - 中间：**现有游戏 UI 原样**（手牌/弹窗/HUD 2D），位置不动；
   - 顶层 `mask-img`：全屏 `RawImage` 采样 `blurRT` + `SynergyUI/TutorialMask` shader（**单矩形**圆角/羽化挖洞，
     `raycastTarget=false`）。
   → 视觉结果：窗外=模糊（UI 被顶层图盖住），窗内=洞（露出 3D + 手牌/按钮，可点）。
4. **窗口来源** = §2.1 解析器：目标的 `Renderer.bounds`（TMP 取 TMP bounds）八点投影 → 屏幕 AABB + pad；
   每帧跟新（镜头/演出位移）。
5. 关闭遮罩：`targetTexture = null`、隐藏两层图、`Release` 三张 RT——**平时零开销**。
6. Shader 规矩：单 Pass、混合写死、**零 `shader_feature`**（照 [TideIconAlpha.shader:2-5](../Assets/Art/Shaders/TideIconAlpha.shader#L2) 的教训）。
7. 与后处理的先后：相机 RT 里已含 bloom（后处理照常写进 RT，`UniversalRenderPipeline.cs` 只看
   `renderPostProcessing`）→ **模糊是在成片之后做的**，窗外光晕会被一起糊开（v0.1 讨论过的"先糊再 bloom"在 RT 方案里不成立，
   这是本方案的固定代价，验收按观感判）。

## 4. 高亮怎么落（后处理选择描边）

- 目标集合 = `highlight` 解析出的 renderer（模型部件 + TMP 文字 + 格面 mesh）；
- `TutorialOutlineFeature`：渲染目标层到 mask RT → 膨胀 2~3px → 取边缘 → 以 HDR 色（`hdr` > bloom 阈值 0.8）
  合成 → **注入点早于后处理**，让 bloom 把边缘晕开成"边缘光"；
- 多目标一次覆盖；模型是拼装刚体也不怕（不需要逐部件套壳、不新建预制体）；
- 格级想更简单：`BattleTileFx.SetCellRing`（现成）作为 `cell:x:z` 的实现，与描边可叠加；
- 脉动：shader 内 `_Time` 驱动（照 `GuideFrame` 的做法），不做 C# 逐帧。

## 5. 暂停系统怎么落（通用，不是教学专用）

### 5.1 分层

| 层 | 内容 | 做法 |
|---|---|---|
| 逻辑 | 回合推进、栈结算、AI 驱动、计时器 | `GameStateManager.Pause()`（已能停 `GameCore.Update`）+ AI/计时器补 Running 校验；**不改规则语义** |
| 表现 | 模型程序动画、战斗演出、相机 tween、粒子/VFX、音频、UI 动效 | 新增 `BattlePauseBus`：`Paused` 事件 + 各表现系统订阅；无订阅者也不报错（渐进接入） |
| 输入 | 拖拽/点格/按钮/结束回合 | 暂停态统一短路（复用 `FanGateQuiet`/`GateMyMain` 前置判断），**不用全屏 Graphic 拦** |
| UI | 暂停提示层（"连接已断开" / 教学【继续】） | 复用现成 Modal/Toast 宿主，不新建 UI 结构（守"UI 只绑定不生成"） |

### 5.2 两个调用方

- **联机断线（口径已修正，见 §5.4）**：当前拓扑是**房主即服务器**——房主掉线=整房解散，
  所以"暂停等重连"只在**客人掉线、房主还在**时成立；客人侧看到房主消失时**没有可恢复的对局**（客人端无本地引擎）。
  本期只做：**暂停 + 中性提示 + 退出/结束**（不承诺重连），**代打先屏蔽**（`NetBattleChannel` 30s 到点代打挂开关，默认关）。
- **教学（按需挂）**：`Apply(mask/highlight)` → 若该步 `pause.on` → `Pause(reason: Tutorial, resumeBy)` →
  玩家点【确定】或点窗内 → `Resume()` + 推进下一步。**默认不挂；哪些步要挂，用户后续点名。**

### 5.3 必须守的约束

1. **自由步不暂停**（`fieldclear/luckuse/deathtoll`）：它们靠玩家操作推进，锁住=死锁。
2. `aiTurnOnConfirm` 交回合动作不能停 AI 推进；只锁 UI。
3. 暂停期间**不允许**任何 `GameActions` 进（逻辑层 Running 校验兜底；表现层 input 短路）。
4. 所有暂停入口都要能被"强制恢复"（切屏/终局/异常）——`OnExit`/`Shutdown` 里 `ForceResume`。
5. **回放/观战**（`BattlePlayhead`）用自己的暂停，不混进 `BattlePauseBus`。
6. **暂停默认关**：不配 `pause.on` 的步骤行为与今天一致（先合功能，不改变现有教学节奏）。

### 5.4 联机断线的现实约束（2026-11-21 用户指出，必须先认这个）

**拓扑事实**

| 事实 | 证据 |
|---|---|
| **房主 = 本进程宿主**（P2P，不可转移）：房主退出 = **解散整房**，断开全部成员 | [NetRoom.cs:14-18](../Assets/Scripts/HotUpdate/CardCore/NetSession/NetRoom.cs#L14) |
| **客人端没有本地引擎**：战报/结算都由房主引擎渲染，随摘要携带 | [NetBattleChannel.cs:498](../Assets/Scripts/HotUpdate/CardCore/NetSession/NetBattleChannel.cs#L498) |
| **重连属 M4，未实现**：作废对局是最小策略 | [NetRoom.cs:460](../Assets/Scripts/HotUpdate/CardCore/NetSession/NetRoom.cs#L460)、[项目概览.md:286](项目概览.md) |
| 有一个独立权威服务器方案（gateway + 每局 match 子进程），但目前不是联机主路径 | `TideServer/Program.cs`（gateway/match/selftest） |

**推论（决定我们能承诺什么）**

1. **房主掉线 ⇒ 对局在客人侧已经不存在**：没有服主、没有本地状态，**"暂停等重连"对这个场景不成立**。
   唯一出路是把对局交给独立服务器（TideServer 托管）或实现**房主迁移**（需要全量状态迁移，成本极高）。
2. **客人掉线 ⇒ 房主还活着**：但"回得来"要等 M4 重连，本期没有 → 只能结束。
3. **"谁掉了"判定不了**：客人失去的是"到房主"的同一条连接，无法区分"自己断网"还是"房主进程没了"。
   要区分，必须有第三方通道（平台 presence / relay 心跳），当前没有。
   → 提示文案必须**中性**（"连接已断开"），不能写"房主已离开"或"你已掉线"。

**本期口径（2026-11-21 用户定案）：断开就结束，不做等待/重连**

| 角色 | 现象 | 处理 |
|---|---|---|
| 房主 | 客人连接断开 | **立即结束本局**（断开方判负）＋中性提示＋回大厅；不暂停、不等待、**不代打** |
| 客人 | 与房主断开 | **立即结束本局**（视为自己断开）＋中性提示"连接已断开"＋回大厅；**不显示"重连中"** |
| 观战 | 断开 | 直接退回大厅（不影响对局方） |
| 房主 | 自己崩溃/杀进程 | 房间解散（现有行为），客人侧落到"客人与房主断开"那一行 |

- **不做"继续等 X 秒"按钮**，也不做超时判定——断开即结算，链路最短。
- 判负口径：客人断=客人负；房主断=整房解散、**不记胜负**（服务端都没有，记不了）。
- **联机界面只开放房间对战**：排位/匹配入口关闭（`LobbyScreen` 的 `panel-ranked`、页签、排位开局钮），
  只留建/进房间。**当前联机主路径 = TapTap 房间**（登录后走 TapTap 房间列表/建房，`TapBattleTransportHost` 做中转；
  未登录才回落局域网）。注意：TapTap 只是**中转/信令**，对局引擎仍在房主进程 → 「房主掉线=整房解散」的口径不变。
  局域网（`LanRoomBeacon`/`Scanner`）保留但本轮不投入、不做手输 IP 兜底。这条属联机 UI 收敛，和暂停系统分开派活。

**后续（等部署权威服务器再说，已登记到 [拓展方向](拓展方向.md) §10）**

- M4 重连（快照+事件重放）、取消"房主即服务器"、判定增强（presence/心跳）、
  断线判负与代打策略、排位/匹配入口重开、房主迁移。

## 7. 验收

**静态**：四档装载 + `--tutorial-guide-audit`（未知 token / 非法字段 / 空 target / 多目标写法报错）；
新 shader 零 `shader_feature` 且在 `Assets/Art/Shaders/`（ArtRuntime 自动收）。

**动态**
1. 25 步：窗对准目标（±8px @1920×1080）、窗外模糊且盖住 UI、窗内清晰可点；暂停步按 §5.2 验证恢复链路；
2. 暂停期间：AI 不动、演出冻住、音频停、结束回合/出牌全被拒且提示可读；
3. 恢复后：无残留遮罩/描边、回合/栈状态与暂停前一致；
4. `midTransition` 换场后遮罩重挂；`End()`/退出教学彻底清；
5. 教学二/三/四（无字段）零变化；
6. 分辨率：1920×1080 / 2560×1080 / 1080×2400；安卓真机遮罩前后帧率差 ≤5%，离开教学 RT 已释放。

## 8. 风险与对策

| 风险 | 对策 |
|---|---|
| 暂停只停 `GameCore.Update`，AI/计时器/演出照跑 | 阶段 1 逐个子系统补 Running 校验 + `BattlePauseBus`，验收里逐项列 |
| 自由步被暂停锁死 | `fieldclear/luckuse/deathtoll` 强制 `pause` 无效；`ForceResume` 兜底 |
| 断线后玩家等到天荒地老 | 已定"断开就结束"：不做等待按钮、不做超时，直接结算回大厅（§5.4） |
| 房主掉线被误当"可恢复" | §5.4 已明确：房主掉线=房间解散，客人侧中性提示 + 退回大厅 |
| 联机入口一多，"断开就结束"更劝退 | 联机界面只开房间对战（排位/匹配入口关闭），排期见 [拓展方向](拓展方向.md) §10 |
