## 0. 通用规则

### 0.1 回合定义（2026-11-16 用户定案）

T1/T3/T5/T7 **就是全局回合号**（`TurnEngine.TurnNumber`，先手首回合=1，双方轮替各 +1）。脚本里的 T1/T3/T5/T7 是**先手开局**在各全局回合要做的事——**只有一套 T3，没有「先手T3」「后手T3」的说法**。

绿在后手时：放地和出牌的操作与先手**完全一致，不做改变**——固定序随绿方自己的回合序照常推进（绿的第 1/2/3/4 个回合分别执行 T1/T3/T5/T7 的操作；绿先手时恰好落在全局 1/3/5/7，这正是 T 编号的来源）。

实现：固定序按绿方回合序推进（代码现状 `scriptTurn = 绿先手 ? TurnNumber : TurnNumber - 1` 即此意），不为后手另设锚点。

### 0.2 统计口径

- **上手率**：对应脚本回合开始时，该回合需要的 key 是否在**手牌**中。
- **达成率**：key 上手后，该回合固定操作是否全部完成。
- 分母使用“实际到达该脚本回合的局数”，同时标注占全部局数的比例。
- 统计口径一旦确定，跨阶段不换分母、不换定义。

### 0.3 新卡费用

- 新卡/新效果费用必须由 `CardCostService` / `CostDerivationService` 推导。
- 禁止手填 `costList` 当权威价，禁止按卡 ID 硬编码费用。
- 推导结果不符合设计时，改卡内容/原子/关键词/组合，或补正式计费规则。

### 0.4 排查纪律

- 每个固定回合必须输出：手牌、场上、墓地、元素池、横置/未横置、可用费、固定标记。
- 一次只改一个变量；调试期不改卡、不改费用、不改牌库。
- 回归顺序：固定排序先手 → 固定排序后手 → 随机 100 局；前一步不过，不进入下一步。
- 单局成功不能当结论；结论必须对应状态日志或固定 seed 复现。

    牺牲 → 归根 ×1 → 阿格洛斯

（2026-11-16 补：T5 前置小精灵首卡=用户拍板——T5 手牌余册只够铺到 7 地时，第 8 块地不存在，靠小精灵把沃土压到 @4 补上 1 费缺口；7 地费线 7−1−4=2 恰付牺牲。）

绑定规则：

- 牺牲与归根绑定（**绿预组全局硬规则**，固定序和普通评分都必须遵守）：**没有归根，不使用牺牲**；
- 该限制在英雄技能最终发动入口执行，不能只在 Want/Allow/目标选择里检查；
- 牺牲后固定使用 **1 张归根**；
- 归根每回合最多 1 张，且固定在牺牲之后；
- T1/T3 不牺牲；
- T7/T8 只有手牌存在归根才进循环；没有归根时不牺牲、按普通评分，**不补地**；
- T5 结束后只需要保证手里留下 **1 张归根**；T5 保留的阿格洛斯当回合使用，不作为长期 key。
- T7/T8 刷新旧阿格洛斯时，只牺牲场上**攻击+生命总和最低**的 1 只；有第三张可下时先下第三张。

## 4. 上手率与达成率不一致：修复计划

### 4.1 已确认的断点类型

1. **T1 没有先建立绿地**
   - 固定序依赖 T1 有一张可铺的未知地；
   - 随机起手没有时，小精灵 1 费付不出，T1 空过；
   - T3 key 虽在手，但没有绿地启动固定序。

2. **T3 的 key 被铺地消耗**
   - `PlayLands` 先于固定出牌执行；
   - 沃土/小精灵被当土地铺掉；
   - 固定标记 `t3S/t3B` 仍为 false，但统计上 key 上手为 true。

3. **T5 的可执行判定口径错误**
   - 只看“三张都在手”会把场上/池中的阿格洛斯排除；
   - 需要区分手牌、场上、元素池三个位置。

### 4.2 阶段 A：只诊断，不改行为（2026-11-16 已完成）

固定 seed 复现（seed 20261301 对红 / 20261302 对蓝，各 100 局，`--detail` + `[green-state]` 状态行 + `TIDE_DEBUG_PLAY` 单局取证）。

**统计口径修正**：达成必须按 `[play]` 实证（当回合真的打出），不能用 `[green-key]` 的 t3S/t3B 标记——那是 `ForcePlayCard` 返回卡时置位的乐观标记，后续 `PlayCard` 失败被静默跳过时标记仍为 true。

**结果（当前代码）**：

| 指标 | 对红 | 对蓝 |
|---|---:|---:|
| T1 小精灵上手 / 当回合打出 | 99/100 → 99 | 97/100 → 97 |
| T3 双 key 上手 / 当回合完成 | 88 → 53 | 97 → 44 |
| 到达 T5 / 可执行形态(手有沃土+归根) / 阿格洛斯落地 | 62 / 51 / **2** | 78 / 72 / 25 |

**归因（逐类，证据=dbg-land/dbg-play 行）**：

1. **T1 无绿地：不成立**。起手总有可铺地牌（沃土/归根余册、阿格洛斯），T1 小精灵 99%/97% 打出。
2. **T3 被铺地（主因，红蓝同型）**：`LandsAsFodder` 的循环卡组保留数分支**提前 return，绕过「带费用降低（绿）指示物永不当土地」保护**——T1 小精灵的 −2 折扣落在沃土 A 上，T3 开局铺地把 A 铺进元素池 → 手里沃土全价 6，mana=3~4 付不起 → 沃土没出，剩余费被第二只小精灵烧掉。对照组（折扣幸存的局）沃土 6−4=2 顺利打出（game 实证 `real=4.0→2.0, canPlay=True`）。
3. **T5 无费（对红主因）**：T3 折扣丢失的延续。T5 整条链以「沃土打出」为闸（牺牲等 `_loopT5Bloom`、归根被 hold 到牺牲后、阿格洛斯 14 费）——沃土 6 费在 mana=5 打不出时 T5 出牌为空。对蓝 25/72 落地证明链路本身（沃土→牺牲全池→归根→阿格洛斯）是通的。
4. 另：T1 铺地选择与 §4.3 不符——现状按 `LandPriority` 把**沃土**当地（2200 分最高），不是「非 key 未知地（阿格洛斯）」；T1 专属分支（只铺阿格洛斯）被循环卡组分支短路成死码。

验收达成：失败局均可归因到上述 2/3/4 之一，无未解释样本。

### 4.3 阶段 B：修 T1 起手（2026-11-16 已执行）

- 优先铺 1 张非 key 的未知地（阿格洛斯）；
- 随机起手没有阿格洛斯时，不允许直接空过：按普通评分找一张可铺地牌，建立第一块绿地；
- 不把 T3 需要的小精灵/沃土当土地；
- 验收：T1 小精灵上手后打出率 100%，T3 开始至少 1 块绿地。

**执行**：`LandsAsFodder` 在保留数分支之前新增 T1 首块地规则——阿格洛斯单张也铺（池中位置仍算可用，牺牲/归根回收；占手牌位反而在 T5 少一块可铺余册）；无阿格洛斯才走余册兜底。**结果**：T1 小精灵打出 99/99（红）、97/97（蓝）；T5 池 7 地局 35→30、8 地局 21→27（阶段B顺带缓解费线，见 §4.5）。

### 4.4 阶段 C：修 T3 固定顺序（2026-11-16 已执行）
