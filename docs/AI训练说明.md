### 0.1 两阶段课程（2026-11-17 拍板；**一期=三套都会打，二期=拿到什么都会玩**）

> 分工：**一期**证明「同一套卡表下，AI 对三套预组的操控都超过脚本」；**二期**再把卡组换成
> 「整组减 1 + 训练池随机补」，练「拿到什么都会玩」。两期都有明确的强度标尺，只是卡组分布不同。

**阶段一：三套预组（红/绿/蓝）**

- 训练：模型侧卡组 = 三预组随机（`--model-theme all`，每次 reset 抽一套并显式下发
  `modelTheme=red|green|blue`）；对手 = SimpleAI 脚本三预组随机（`red/green/blue`），座次随机。
- 目的：AI 要能**执三套都比脚本强**——红吃快攻节奏、绿吃成长、蓝吃减费，各自套路都要学会。
- 评估：模型分别执三套 × 先/后手 = **6 格**（对脚本三主题随机，换边轮替）；
  每格判据 = Δ 口径（2026-11-22 定案）：模型胜率 − 同格脚本基线 ≥ +15pp，不封顶（见 §0.2）。
- 出口：6 格逐格达标（`cells_pass=True`）；早停/best 选择口径 = **18 格矩阵最小 margin**
  （B4，2026-11-22 起；矩阵无数据回落 6 格最小 margin，见 §3.4）。

**阶段二：掺卡自对弈（扩广度）**

- 卡组构造（仅模型侧，`红·快攻`）：按卡名去重，每种减 1 张（5 种 → 25 张），
  空出 5 张从训练池（85 张）随机补齐回 30 张。
- 对手侧：沿用旧自对弈口径（主题整组 / 随机 30 两种卡组形态，双方模型驱动、座次随机）。
- 目的：保留套路骨架，用随机卡制造牌面差异，练「拿到什么都会玩」。
- 验收：阶段二后复验 6 格，仍 Δ≥+15pp（不封顶），且不低于阶段一末的水平。

## 2. 奖励

```
reward = 终局 ±1（actor-centric：归属「刚行动的一方」）
       + λ · (Φ(s') − Φ(s))        λ = 0.005（势能塑形）
```

- 势能 Φ = `FieldValueReward.ComputePotential(includeHand:true)`：**战场 + 资源价值，含手牌**
  （2026-11-23 起与定价体系对齐；旧「剔除手牌」2026-09-22 口径已废弃，回滚点 =
  `TideHeadlessDriver` 两处 `includeHand`）。**A4（2026-11-24 回到一期训练目标）单价**：
  手牌 **3/张固定**（不乘卡面费）、地 **2/块**、横置净 **+1**、生命/护甲/元素 1.0、
  战斗伤害 0.5——详见[计价与塑形_统一口径](计价与塑形_统一口径.md) §1/§2/§3。
- **历史坑（必须记住）**：旧口径 λ=0.05 且势能含手牌（每张 0.6）→ 双方整局塑形累计 ≈ +3.1，
  **淹没终局 ±1** → 自对弈收敛到拖局（局长 90→267、对脚本胜率 0.35→0.10）。现在 λ 小 10 倍，
  且囤牌收益被手牌 7 上限封顶（第 8 张回合末先 +3 后 −3，不赚不亏）。
- λ=0 是基线开关（`--shaping-lambda 0`）：非终局奖励恒 0，纯终局 ±1。
- 势能塑形理论上不改变最优策略，**前提是塑形累计量 ≪ 1**。这条是设计红线。

### 3.2 对手池（`--opponent-pool`，2026-11-02 C 期，默认 `current` = 旧行为不变）

每次 `reset()` 采一个对手来源，`info.opponentSource` 与日志/stats 标注；评估等显式
options 的 reset 不受池影响（直通）。

| 取值 | 含义 | info.opponentSource |
|---|---|---|
| `current`（默认） | 旧行为：同策略自对弈（等价旧 selfplay） | `current` |
| `themes` | 三预组整组轮换：红·快攻（30）/ 蓝·控制（30，2026-11-18 重做=潮汐12/深潭碑8/乱锋6/寒冬4）/ 绿·慢速（60，含 14 费 系命者·阿格洛斯），各配对应 skill 卡（红·激励 / 蓝·蛰伏〔2026-11-18 替换隐匿〕 / 绿·牺牲）与策略脚本（SimpleAI+AutoMatch，协议层 `opponent=simpleai`+`theme`，Unity 侧零改） | `theme:red` / `theme:green` / `theme:blue` |
| `checkpoints` | 历史 checkpoint 池：每个评估点把当前策略参数快照入池（环形保留最近 `checkpoint_pool_size=8` 份，含初始随机策略 `init`），按局采一份当对手；对手座次的决策由**旧参数**驱动（独立对手 RNN 链），对手步经 learner 掩码剔除出 PPO 批次（其 logprob 相对当前策略无意义） | `ckpt:init` / `ckpt:step50000` … |

  保持 50% 同策略自对弈是主学习信号不被稀释；主题/快照各 25% 引入分布多样性。可按
  「想专攻哪类对手」调，但建议 current ≥ 0.4，否则主信号塌掉。
- 快照采样权重 `checkpoint_weighting`：`uniform`（默认，等权）/ `recency`（越新越易
  抽中，权重 ∝ 序号——防过旧弱策略占比过大）。
- 日志证据：控制台每 log_interval 打一行 `[对手池] opponentSource 累计: …`；
  `stats.jsonl` 每行带 `oppPool`（累计来源分布）与 `fsp` 字段。
- **绿专项统计点（v19 2026-11-20 绿套补盲 §3 起加；A6 2026-11-24 口径更新）**：`stats.jsonl` 每行带 `green` 块——

  拾取步行 `[10]=-1`、提交行 `[10]=0`——旧 `[10]nTargets>0` 口径随组合行退役废弃））、`any_gain`（牺牲目标数合计
  ——SacrificeHandler 逐目标 +1 Any 的代理量，蛰伏层兑现不走动作行故为下界）、`big_plays/big_play_frac`

#### 3.4.1 判定口径：池化三态（2026-11-20 定案，取代「单次评估 pass/fail」）

> 起因：三预组是**验收用的绝对标尺**，但现行每格样本量撑不起「达标 / 未达标」这个二值结论。
> 本节只改**怎么读评估结果**，不改训练分布、不动观测/动作/奖励/卡表。

**现状数据**（只读历史 `eval.jsonl`；主 run `...1795004994`，13 次评估）

- 每次评估 144 局（`evaluate_greedy_multi`：3 模型卡组 × 3 对手主题 × `50//3=16`），6 格平分后
  **每格 17~31 局、均值 24**。
  - 2026-11-21 起该口径对**所有** run 成立（含绿 bootcamp 这类单主题训练，此前只评 48 局/2 格）；
    单主题 run 的红/蓝格是未训练 floor，池化时不要与「该模型真训过的格」混谈。
- 24 局下，真值**恰在门槛**时判「达标」的概率 = **50%**；真值高 5pp 也只有 72%，高 10pp 才 89%
  （门槛取 72.5% 档；数值单源 = `eval_stats.single_pass_prob`）—— 单次 `pass` 字段约等于翻硬币。
  实证：`blue/P2` 13 次评估里 6 次达标 / 7 次未达标，而池化真值 56.6%、门槛 57.2%（骑线）。
- 分辨率：24 局只能可靠认出 **+7.2pp**（相对门槛，单侧 α=5%、功放 80%）；48 局 +4.4pp、
  96 局 +3.5pp、200 局 +2.3pp。
- 「看胜率是否在上升」更贵：两个评估点比较，分辨 10pp 需每格 358 局、**5pp 需 1429 局**
  （现口径的 60 倍）——2M 步预算内做不到，所以**不追斜率，只判是否越过门槛**。

**口径**

1. **池化**：同一 run、**同一门槛代**的全部 `vs_script_cell` 行累计 k/n。跨代相加是错账
   （基线重测已改过 3 次门槛，见 §0.2 / §9）；同格门槛变过时只取最新代。
2. **三态**：95% **Wilson** 区间整体在门槛之上 = `pass`（确认达标）；整体之下 = `fail`
   （确认不达标）；门槛落在区间内 = `undecided`（**骑线，判不了，不算失败**）。
3. **判定只认池化三态**：单次评估的 `pass` 字段降级为观测点与早停信号，不再作为
   「这一轮没达标」的依据。

**用途分工（谁用哪把尺）**

| 场景 | 用哪个 | 理由 |
|---|---|---|
| 训练中早停 / best 选点 | 逐点 **18 格矩阵最小 margin**（B4，2026-11-22 起；旧=6 格 margin） | 只需防跑飞、要即时反应；噪声大但不致命 |
| **验收 / 汇报 / 决定是否重训** | **池化三态** | 单次标签 50% 翻硬币（真值骑门槛时），不能当结论 |
| 末态定档（「到底多强」） | 训练后单独认证评估（600 局/格 ≈ 1.5h） | 池化跨多个策略版本，不是末态估计 |

## 7. 训练中怎么判断「有没有在学」

只看三条曲线（`monitor_training.py`）：

| 指标 | 健康 | 异常含义 |
|---|---|---|
| `approx_kl` | 0.005 ~ 0.03 | 爆掉 → 学习率过大 |
| `pg_loss` | 非零（量级 1e-4 ~ 1e-2），随 update 波动 | 恒 ≈1e-8 且 `approx_kl`≈1e-10、`clipfrac`=0 → 参数没在动（lr 归零 / 优势全零），训练循环照跑但策略冻结 |
| `clipfrac` | 0.05 ~ 0.3 | 接近 0 → 没在更新；接近 1 → 步子太大 |
| `entropy` | 缓慢下降，不塌零 | 快速塌零 → 探索死（熵系数太低） |
| 对脚本胜率 | 打不过预组 = 没学会 | 长期打不过「预组 + 对应策略脚本」→ 奖励/观测有问题，不是超参问题 |

**判据**：曲线健康 ≠ 学得好；曲线不健康则一定学不好。所以先看曲线，再谈强度。
