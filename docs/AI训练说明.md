# AI 训练说明（tide_rl）

> 目的：把「为什么这么设、改什么要重训、怎么判断改得好不好」写死，避免下次再问「当初为什么这样」。
> 最后更新：2026-11-02

## 1. 算法与网络

| 项 | 值 | 出处 |
|---|---|---|
| 算法 | PPO + GAE（+ UPGO 优势项 + JueWu dual-clip） | `train_tide_complete.py` |

| GAE λ | 0.95 | L135 |

| rollout | num_envs=1，num_steps=256，update_epochs=4 | L126-130 |
| 总步数 | 2,000,000 | L144 |
| 网络 | CNN 128 通道 + GRU 512 | L164-166 |
| 单局步数上限 | 2000（超时判负） | L148 |

## 2. 奖励

```
reward = 终局 ±1（actor-centric：归属「刚行动的一方」）
       + λ · (Φ(s') − Φ(s))        λ = 0.005（势能塑形）
```

- 势能 Φ = `FieldValueReward.ComputePotential(includeHand:false)`：**战场 + 资源价值，剔除手牌**。
- **历史坑（必须记住）**：旧口径 λ=0.05 且势能含手牌 → 双方整局塑形累计 ≈ +3.1，**淹没终局 ±1** → 自对弈收敛到拖局（局长 90→267、对脚本胜率 0.35→0.10）。现在降 10 倍且剔手牌。
- λ=0 是基线开关（`--shaping-lambda 0`）：非终局奖励恒 0，纯终局 ±1。
- 势能塑形理论上不改变最优策略，**前提是塑形累计量 ≪ 1**。这条是设计红线。

## 3. 对手与评估

| 口径 | 含义 |
|---|---|
| `opponent="selfplay"`（默认） | 主题整组 vs `Cards.json` 随机 30，双方同一策略；座次随机 |
| `opponent="simpleai"` | 模型 vs 脚本主题卡组（SimpleAI + AutoMatch），座次随机（先后手各半） |

- 评估：每 5 万步一次、**每次 50 局**（20 局时二项噪声 σ≈0.11，best 选点靠运气）。
- **评估基准主题当前 = red**：绿/蓝脚本尚未重设计（随机基线绿 100% / 蓝 55% 白送分，污染总胜率），重设计完成后改回三主题随机。
- 早停：目标胜率 0.75、连续 5 次达标。

## 4. 版本与冻结面

| 冻结项 | 说明 |
|---|---|
| **卡表 + 原子表**（含所有 ID） | 观测编码的是卡 ID；重推工具会改 ID（例：火炬 `C_93E8DDD1`）→ 训练数据作废 |
| **布局版本** | `TideObservation.LayoutVersion`（C#）与 `tide_features.LAYOUT_VERSION`（Python）必须一致，当前 **v8 / 动作 11 维** |
| **AI 决策代码** | `AiStrategy` / `SimpleAI` / `LegalActionEnumerator` |
| **规则与费用推导** | 影响回报分布 = 换环境 |

**并行开发时**：表现层（UI/动画/音效）随便改；上面四项任何一项变动 → 必须重训。

## 5. 哪些改动必须重训

| 改动 | 要重训？ | 能否预先判断 |
|---|---|---|
| 卡表 / 原子表 / 费用公式 | ✅ 必须 | ✅ 用 `Tools/规范总校验` 对账 |
| 观测特征 / 布局版本 | ✅ 必须 | ✅ 编码器自检 |
| 动作空间（LAE 枚举） | ✅ 必须 | ✅ `audit_action_space.py` |
| 奖励函数 / λ | ✅ 必须 | ✅ 跑 100 局看 reward 分布 |
| 网络结构 | ✅ 必须 | ⚠️ 半预判 |
| 超参（lr/熵/clip） | ❌ 不用重训，重跑即可 | ❌ 只能看曲线 |
| 表现层 | ❌ | — |

## 6. 训练前自检清单（分钟级，先跑这个再开训）

1. **契约对账**：`Tools/规范总校验（2026-11-02 定案）` → 卡表 hash / 布局版本 / ONNX stamp 三项
2. **动作空间审计**：`python tide_rl/audit_action_space.py --episodes 100` → 死动作比例
3. **脚本基线（强度标尺）**：红/绿/蓝三套互打各 100 局，记录胜率与平均回合。
   **判强弱的唯一标准 = 能不能打赢「预组 + 对应策略脚本」**（不需要额外的随机策略基线）。
   旧基线（卡表改色前，仅参考）：红 59-41 绿；蓝 39-1 红；绿 19-1 蓝，平均 22 回合。
   改色后（10 局采样）：红 4-6 绿、平均 31.5 回合——**回合数变长是费用抬高的直接后果，基线需按 100 局重测。**

## 7. 训练中怎么判断「有没有在学」

只看三条曲线（`monitor_training.py`）：

| 指标 | 健康 | 异常含义 |
|---|---|---|
| `approx_kl` | 0.005 ~ 0.03 | 爆掉 → 学习率过大 |
| `clipfrac` | 0.05 ~ 0.3 | 接近 0 → 没在更新；接近 1 → 步子太大 |
| `entropy` | 缓慢下降，不塌零 | 快速塌零 → 探索死（熵系数太低） |
| 对脚本胜率 | 打不过预组 = 没学会 | 长期打不过「预组 + 对应策略脚本」→ 奖励/观测有问题，不是超参问题 |

**判据**：曲线健康 ≠ 学得好；曲线不健康则一定学不好。所以先看曲线，再谈强度。

## 9. 历史沿革（为什么变了）

| 时间 | 变动 | 原因 |
|---|---|---|
| 2026-09-22 | 评估 20→50 局、λ 0.05→0.005、势能剔手牌 | 20 局噪声大；λ 过大导致拖局 |
| 2026-09-29 | PPO 4 epoch、γ 0.99→1.0 | 1 epoch 时 clip 永不触发，退化成单步策略梯度 |
| 2026-09-30 | v2c 动作空间（时机+目标+响应窗口进动作） | 旧空间表达不了响应与目标选择 |
| 2026-11-02 | 布局升 v8（动作 11 维，多目标） | 多目标组合行需要目标2/目标3/目标数三个特征位 |
